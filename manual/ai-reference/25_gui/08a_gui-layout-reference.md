# GUI Design Reference — レイアウト

バトル画面の GUI 設計ガイド。
主な参考: バトルスピリッツ コネクテッドバトラーズ (FuRyu, 2022, Switch/PS4)。
参照スクリーンショット: `images/reference/cb-pv2-004.jpg`, `cb-pv2-007.jpg`。

---

## 1. フィールドレイアウト

### 1.1 全体構成

画面は**上下対称の 2 プレイヤー分割**。
上半分が相手フィールド、下半分が自分フィールド。
中央にバトル演出エリアを兼ねた空間を置く。

公式プレイシート準拠（参照: `images/reference/playsheet_w_countarea.pdf`）。
デジタル版では上下対称に 2 プレイヤー分を配置する。

```
公式プレイシート (1 プレイヤー分):
┌────────┬──────────────────────────────┬─────────┐
│ Burst  │                              │ Count   │
│(左上)  │     ターンシークエンス        │(右上)   │
│        │    (ステップ進行表示)         ├─────────┤
├────────┤                              │  Deck   │
│  Life  │        Field                 │(右中)   │
│(左中)  │   スピリット/ネクサス配置     │         │
│        │      (中央大エリア)           ├─────────┤
├────────┤                              │  Trash  │
│Reserve │                              │(右下)   │
│(左下)  │                              │  Core   │
└────────┴──────────────────────────────┴─────────┘
            [手札 (手元)]
```

デジタル版レイアウト（上下 2 プレイヤー分割）:

コネクテッドバトラーズのデジタル版も、公式プレイシートの配置を**そのまま上下反転**
して 2 面分を画面に収めている。各ゾーンの相対位置は公式と一致する。

```
┌──────────────────────────────────────────────┐
│ [HUD: ステップ / 各者のボイド残数]                │
├──────────────┬──────────────────────┬────────┤
│  相手手札（裏面横並び）                        │
├──────────────┬──────────────────────┬────────┤
│ o Deck       │   相手 Field         │oBurst  │
│ o Trash/Core │  [ネクサス]           │oLife   │
│              │  [スピリット]         │oReserve│
├──────────────┼──────────────────────┼────────┤
│ Burst        │   自分 Field         │  Deck  │
│ Life         │  [スピリット]         │ Trash  │
│ Reserve      │  [ネクサス]           │  Core  │
├──────────────┴──────────────────────┴────────┤
│              [手札 (横並び)]                   │
├───────────────────────────────────────────────┤
│           [下部パスバー / 操作ボタン]          │
└───────────────────────────────────────────────┘
```

ポイント:
- 相手側は `direction: rtl` + `flex-direction: column-reverse` で**左右・上下反転**（Burst が右側、Deck が左側）
- 自分側は公式プレイシートそのまま（Burst 左上、Life 左中、Reserve 左下、Deck 右上、Trash 右下）
- ネクサスはスピリットの外側（相手: 上、自分: 下）に配置
- HUD は画面最上部に固定（ターン/ステップ + 両者のライフ・リザーブ・トラッシュ数値）
- 下部 ActionBar は pass 系と、EffectQueue 前面項目の「発揮する/発揮しない」（誘発/即時効果/バースト発動可否）を半透明ボタンで表示する。ブロック辞退は専用ボタン、召喚/アタック/ブロック等はカードタップ、効果内チョイスやその他 pending は専用 overlay/HUD で操作。

### 1.2 ゾーン配置の詳細（公式プレイシート準拠）

| ゾーン | 公式位置 | デジタル版位置 | 表示形式 |
|--------|---------|---------------|----------|
| バースト | 左上 | 自分: 左下、相手: 左上 | 同一エリアで斜め重ね（自分:B左下/M右上、相手:B右上/M左下）。領域は常時予約 |
| ライフ | 左中 | 左端 | コアアイコン (4〜5個) |
| リザーブ | 左下 | 左端、ライフの下 | コア数の数値表示 |
| フィールド | 中央大エリア | 中央 | スピリット横並び + ネクサス |
| カウント | 右上 | 右端 | 数値表示 |
| デッキ | 右中 | 右端 | 裏向きカード山 + 残数 |
| トラッシュ / コア | 右下 | 右端 | 枚数 + コア数 |
| 手札 | 手元 | 画面最下部 | ファン状に横並び |

### 1.3 フィールド枚数制限

エターナル版ルール上は枚数制限なし。本プロジェクトでは独自カード拡張を想定するため可変長レイアウトで実装する。

参考: コネクテッドバトラーズ (バンダイ公式デジタル版) の制限はスピリット/アルティメット 5 体・ネクサス 3 枚・ブレイヴ合体 1 体につき 1 つ・デッキ 40 枚だが、本プロジェクトでは採用しない (記録としてのみ言及)。

#### P3-56 可変長レイアウト実装概要

- **scroll 容器**: `.field-center-scroll` がプレイヤーごとに 1 容器 (= spirit 行 + nexus 行を一体スクロール)。 自分↔相手は独立スクロール。 サイドカラム (burst/life/reserve/deck/trash/count) は容器外で常時不動。
- **合体スピリットの端固定**: spirits を combined-first sort して scroll 起点 (自分=左 / 相手=右、 opp 側は `direction: rtl`) に合体スピリットを優先配置。 viewport 収容数を超える合体は scroll で順次表示。
- **手元連動**: 手元 (set_aside) 有時は scroll 容器内 grid 末尾に invisible phantom (`grid-column: span 2`) を挿入し、 ネクサス行のみ早期 scroll 起動 (spirit 行は影響なし)。
- **フィールドのカード状態**: 魂状態以外のカード状態カード（マジック等）は、手元と同じ列のスピリット行に手元と同じサイズ・重ね方で固定表示する（自分は手元の上、相手は反転）。領域の背景・枠は透明でフィールドの背景を見せる。存在中は scroll 容器の両行を固定列の手前で切り、横スクロールしてもカード状態・手元の両方は動かない。手元が0枚でも表示する。クリックで全枚数を一覧でき、対象選択・使用可能な効果を実行できる。表示区分は `fieldCardDisplayKind` を盤面・一覧で共有し、合体/下のカードは重複表示しない。分身・魂状態の配置は従来どおり。
- **自動 scroll**: 新規召喚時 / アタック・ブロック宣言時に該当カードへ横方向だけ smooth scroll。両行の縦位置は維持する。
- **分身のコア配置待ち**: コア配分直後に分身として扱う裏向きカードは、配置待ちの間からスピリット行へ個別表示する。元カードの印刷カテゴリには依存せず、コアHUDから各カードを直接タップできる。分身として成立するまでBP・Lvは表示しない。

## 2. カード表示

### 2.1 フィールド上のカード

- **縦向き**で表示。疲労状態は **横向き（90° 回転）**。
- カードイラスト全体を表示（`images/` から取得）。画像がないカードはテキストフォールバック。
- カード右下に **BP 値** をオーバーレイ表示（例: `0`, `6000`, `13000`）。**フィールド上のみ表示**。BP0でもバッジを維持する。通常ネクサスなどBPを持たないカードには表示しない。魂状態ではBP・Lvバッジを両方隠す（共有配置を含む）。
- カード左上に **Lv 表示** をオーバーレイ。コア数から自動判定。**フィールド上のみ表示**。
- カード右上に **コアアイコン** を重ねて表示（`images/ForGUI/core.png`, `soul-core.png`）。
- カードの色に応じた **枠色** を表示（赤/青/白/緑/黄/紫/黒）。
- 合体ブレイヴは本体の右上へ斜めに重ねる（相手側は反転）。合体ネクサスも2行を占有し、自分はネクサス行の下端、相手は上端に本体を揃える。転神やスピリット/アルティメット状態の間は中央線側へ切り替える。
- 合体/アンダーカードの wrapper は member 数と配置offsetから占有幅を動的に確保する。
  grid 上は2行を占有するが、回転対象boxは空白行を含めず host+brave+under-card の
  視覚 envelope に縮め、常に wrapper 全体の中心を回転軸にする。
  複数合体ブレイヴは先頭の既存位置を維持し、2枚目以降を右上へ各10pxずらす。
  回復/疲労のどちらでも回転後のmember外接領域をtrackへ含め、隣接カードと接触させない。
- 2体が1枚を共有する関係は左右どちらかのwrapperへ複製せず、2 anchor列を束ねる共有memberを
  盤面に1枚だけ描画する。異魔神ブレイヴは左右スピリットの中央線側に△、真・バディの
  共有煌臨元は外側に▽として置き、左右anchorの疲労状態に追従せず常に回復角度で表示する。
  追加の煌臨で各枝のカードが煌臨元になった場合、そのカードは左右それぞれのローカルstackへ置く。
- 共有カードのゾーンブラウズはanchorごとに分ける。同一共有instanceを複製せず、左右それぞれの
  browse listから同じinstanceIdを参照する（本体1枚+共有カード1枚）。
- **魂状態カードは印刷カテゴリ由来の行を維持し、その行のライフ側の端に固定する**。盤面反転後も同じ意味になるよう物理的な左右ではなくライフ側を基準とし、自分側は左端、相手側は右端（各 `field-center-scroll` の scroll 起点）に置く。魂状態カードをネクサス行へ一律移動しない。魂状態/クォーツの占有幅は両行の先頭列に予約し、通常の合体カードの回転後外接範囲と重ならないようにする。

クォーツ配置はカード寸法を維持し、3段の縦間隔だけを2行分の高さへ制限する。最下段を収め、非表示の縦スクロールで通常スピリット行が見切れる状態を防ぐ。

### 2.2 手札のカード

- 横並び表示。
- 使用可能なカードは **緑枠 + パルスアニメーション** でハイライト。クリックで直接実行。
- Lv / BP は表示しない（フィールド上のみ）。

### 2.3 相手の手札

- 画面上部にカード裏面（`images/ForGUI/card-back.jpg`）を横並び表示。枚数が分かる。

### 2.3 カード詳細ポップアップ

- カードをクリック/長押しで全文テキスト + ステータスを表示。
- 効果テキスト、系統、コスト、軽減、レベル情報を含む。

## 3. UI 要素

### 3.1 ステップ表示

画面左上に常時表示:

```
PLAYER Turn  [ターン数]  [ステップ名]
```

- ステップ名: `スタートステップ`, `コアステップ`, `ドローステップ`, `リフレッシュステップ`, `メインステップ`, `アタックステップ`, `エンドステップ`
- 現在のステップをハイライト。
- 自分のターンか相手のターンかを色で区別。

### 3.2 ライフ・コア表示

- **ライフ**: 公式プレイシート準拠で **横 3 列 grid** に `core.png` アイコンを配置。
  - 自分側: 上段から 3 個ずつ埋まる（5個 → 上3下2、端数は左寄せ）。
  - 相手側: 下段が 3 個、上段に端数（右寄せ）。反転レイアウトに対応。
  - 6 個以下はそのまま表示、7 個以上はアイコンを自動縮小。
- **リザーブコア**: `core.png` + 数値表示。ソウルコアがリザーブにある場合は `soul-core.png` も表示。
- **トラッシュコア**: トラッシュエリア近くに `core.png` + 数値表示。

### 3.3 下部操作エリア

画面最下部に固定配置:

| ボタン | 用途 |
|--------|------|
| 決定 / OK | 選択したアクションの実行 |
| キャンセル | アクション選択の取り消し |
| カード詳細 | 選択中のカードの詳細表示 |
| シンボル表示 | トグル: 自/相手両方のフィールドカード (spirit + nexus) をグレーアウト + 操作不可化し、効果適用後シンボルラベル (`紫2 赤1` 形式) を各カード上にテキストオーバーレイ表示。合体スピリットは host にブレイヴ込みの合算ラベル、brave 子はラベル無しグレーのみ。再押下で OFF。|
| バトルメニュー | ゲーム設定、降参、ログ表示等 |
| パス | フラッシュ窓やスタック窓でのパス（ActionBar の通常表示対象） |

盤面・カード詳細のシンボルと軽減は `symbol-format.ts` の共通表記を使う。
1個（軽減1枠）の全通常6色は「六」、黒を含む7色は「七」へ省略し、神・導・極は残す。
別々の単色シンボル・軽減枠は結合せず、個数を維持する。

棋譜読み込みでは上部の観戦バーと独立した下部ツールバーを置かず、既存HUDを常時見せる。
手札左側の進行操作を「◀前 / 再生（停止） / 次▶ / 視: プレイヤー名」に置き換える。
シンボル表示は維持し、狭い横画面でも横幅を圧縮して1行に収め、高さは既存ボタンに揃える。
再生右クリック（Alt+↓も可）で
速度メニューを展開する。「・・・」には棋譜名・再生位置・タイトルへを置き、観戦時の
リセットとスナップショット保存は表示しない。「・・・」を開くと再生を停止する。

### 3.4 アクション選択 UI（実装済み）

- カードタップ操作で完結するアクション（召喚/アタック/ブロック/マジック使用/効果使用/バーストセット/配置等）は、カードタップから直接実行または候補モーダルへ進む。
- 下部 ActionBar は **pass 系 + EffectQueue 前面項目の「発揮する/発揮しない」**を扱う。EffectQueue は前面カードの選択を担い、ActionBar はその前面カードに対応する action だけを半透明ボタンで表示する。バースト発動可否も `pendingBurstChecks` から EffectQueue に載せ、効果内チョイスやその他 pending 操作は専用 overlay、HUD、または対象選択 UI で処理する。
- `pendingStepOptionalChoice` / `pendingStepChoice` overlay は `PendingStepPrompt` を主表示に使う。カード `textLines` 全体は最後の fallback であり、複数の任意文・choice がある効果では step/choice 単位の `sourceText` を DSL に持たせる。
- 手札の使用可能カードは緑枠ハイライト。タップで直接召喚（コスト自動計算・リザーブ自動支払い・Lv1 コア自動配置）。
- フィールドのスピリットをタップ → アタック宣言（アタックステップ中）/ ブロック宣言（相手アタック中）。
- 「ブロックしない」ボタンでブロック辞退。
- パス系と誘発/即時効果/バースト発動可否の決定は下部 ActionBar、EffectQueue は解決待ちカードの表示と前面選択、選択 pending は専用 overlay で扱う。他に意味のある選択肢がなければ自動進行する。
- 相手の行動は `PlayerController` コールバックに委譲（デフォルト: 全自動実行）。こちらに意味のある選択肢がある間は相手の自動実行を止める。
- アクション実行結果を **トーストメッセージ** で画面中央に 2 秒間表示。

### 3.5 ログ表示

- `LogPanel`（`apps/playground-web/src/components/LogPanel.tsx`）は `BattleScreen` から常時マウントされるが、`battle.css` で `.log-panel { display: none; }` 指定のため**GUI 上は非表示**（P3-08 Task 1-3 でユーザー判断によりスコープ外、表示復帰は未定）。
- コンポーネント内部では `formatLogEntry` で主要イベント（`deck_reveal:*` / `summon:declare:*`）を絵文字付き日本語に整形し、`trigger:resolve-main:*` / `summon:` の非-declare / `burst:queued:*` / `trigger:queued:*` は表示抑制するロジックが残存。
- maxEntries のデフォルトは 20。
