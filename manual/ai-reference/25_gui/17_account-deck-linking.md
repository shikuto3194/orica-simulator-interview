# 管理者のメイン・サブアカウントとデッキ連携

管理画面の構成は acg-react の「運営メニュー → 機能別ページ」に合わせる。
シミュレーターはマイページ → 運営メニュー → アカウント・デッキ連携。
orika-react は `/admin` を入口に、既存イベント管理を `/admin/events`、連携設定を
`/admin/accounts` に配置する。ACG のカード管理機能は BS 側へ移植しない。

## ユーザー仕様（2026-09-17 確定）

- メインとサブは登録済みメールアドレスで指定。ログイン中の管理者をどちらかに含める。
- サブアカウント連携とデッキ連携（BS）が両方オンのとき、メインの BS デッキを共用する。
- オンへの切り替えでサブの従来の BS デッキを削除する。退避・復元機能は設けない。
- オフへの切り替えでは、その時点の共有デッキをサブへ複製し、それ以降は独立する。
  オン以前のデッキは復元しない。複製には新しい ID を採番し、公開状態は引き継がない。
- 共有中の同じ2人のメイン／サブ交換は、共有デッキの所有者を新メインへ変更する。
  デッキ ID・カード・トークン・サムネイルは保持する。
- 相手の変更は、旧ペアを分離してから新ペアを連携する。独立状態でのメイン変更は
  デッキを移動せず、次にオンにした時点のメインを正源にする。
- ログイン ID、プロフィール、対戦参加者は統合しない。ACG デッキは変更しない。
- アカウント切り替え時は編集画面を再作成する。ログイン中はグローバルな端末保存を
  自動アップロードしない。手動の JSON 読み込み・保存は可能。

## DB と API

正源は `supabase/migrations/20260917073409_bs_account_linking.sql`。
`private.bs_account_links` がペアとスイッチ、`private.bs_deck_epochs` が保存の世代を保持する。
設定の更新は管理者ロールを検証し、双方の ID の重複使用と古い設定の上書きを拒否する。
`profiles.role` は本人のプロフィール更新では変更できない。

- `bs_admin_account_link(p_settings?)`: 引数なしで設定取得、引数ありで変更。
  `revision`・メイン／サブのメール・2つのスイッチを渡す。
- `bs_deck_library(p_action, p_scope?, p_deck?)`: `list` は解決済み所有者・世代・一覧を返す。
  `save` / `delete` は読み込み時の世代を必須とし、古い画面の書き込みを拒否する。
- 公開 RPC は SECURITY INVOKER、内部関数は private スキーマに配置して認証と対象を検証する。
  連携切り替えとデッキ操作は同じ transaction advisory lock で直列化する。
- 既存公開デッキの SELECT ポリシーは維持。追加の restrictive ポリシーで、旧クライアントが
  共有中のサブの保存先へ直接書き込んで旧デッキを再作成することを防ぐ。

`useDeckLibrary` が読み込み・フォーカス復帰・設定変更時の再取得とエラー処理を共通化する。
`AccountLinkSettings` とこのフックは orika-react にも同じ処理を配置する。
同期は `node scripts/sync-orika-account-link.mjs <orika-react-root>` で行い、生成先を直接編集しない。
設定で権限を変更してもルーム内の進行中デッキを変更する機能ではない。

## 検証と適用

- `apps/playground-web/test/account-link-postgres.test.ts`: PGlite で実 SQL の遷移、権限、
  古い世代の拒否、ACG 分離を確認。
- `e2e/account-link.spec.ts`: GUI の設定とテスト DB に接続した REST API を往復する。
  orika-react も検証する場合は `ORIKA_TEST_URL` にローカル URL を指定する。
- 新 RPC を先に DB へ適用し、両アプリを更新してから管理画面で連携をオンにする。
  初期登録はメイン・サブを指定して両スイッチをオフにする。デッキ削除は管理画面の保存時に行う。
