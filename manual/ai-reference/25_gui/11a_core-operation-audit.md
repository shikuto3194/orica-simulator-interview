# コア操作 GUI 再監査（2026-09-08）

コア選択の正源は [11_core-selection-hud.md](11_core-selection-hud.md)。
対象は手動操作、LegalAction のコスト入力、GameState のコア選択 pending、効果解決中の自動移動。
状態変更・移動制限の正源は rules-core のまま、GUI は正源の候補と上限を使う。

| 経路 | ユーザーが決めるもの | GUI / 判定 |
| --- | --- | --- |
| 通常召喚・ネクサス配置・マジック・アクセル・チェンジ・ミラージュ・クォーツ | コスト内訳 | 既存 card_cost HUD。入力不要ならエンジンの確定処理 |
| 効果起動 pay_cost・効果内召喚・逆転醒 | コスト内訳 | 既存 card_cost HUD。窓後 pending のタイミングを保持 |

## 選択だけで終わる場面のソウル確認

通常召喚・効果コスト配分・ライフの種類選択・コアシュートの確認表示は `SoulCoreConfirmation`。種類切替ボタンを使わず、移動元タップで「含みますか？」を表示する。候補上限と通常/ソウルの選択権は各エンジン契約に従う。数選択だけのpendingには種類確認を追加しない。

## 配置元の正源

通常召喚・効果召喚の維持コア配置は `buildPlacementFieldSources()` →
`canProvideEnterFieldCorePlacementSource()` を使う。複数体配置も候補ハイライトと
grab処理で同じ一覧を参照し、配置対象自身を除外する。創界神・導界者・創界石、
通常コア移動禁止、強制ボイド転送の制限をGUIで再実装しない。
通常コアとソウルコアの可否は別々に正源の結果を使う。

## 2026-09-18: 通常コアとソウルコアの混在選択

「通常1個＋ソウル1個」を基準に上表の入力経路を再監査した。
通常数の上限と、通常＋ソウルの合計上限を区別する。

| 経路 | 監査結果・回帰 |
| --- | --- |
| 通常召喚・場入り・逆転醒の単体配置 | リザーブの取得数にソウルを足して通常枠を消費していた。通常数だけに修正。カード元は通常/ソウル可否と合計供給上限を保持 |
| 効果召喚・バーストの単体/複数体配置 | トラッシュの取得済みソウルを認識せず再確認する問題を修正。通常0の「いいえ」で架空の通常コアを取得しない |
| 分離・場に残す | ソウルだけのフィールド元も選択可能に修正。GUIとサーバー再生は共通処理でソウルを維持判定前に配置し、不要な通常コア自動補填を防止 |
| 通常コスト支払い（召喚/配置/マジック等） | フィールド元の上限はソウル込みで正常。全体コスト到達後の追加取得と、通常残0の取得を防止 |
| 手動コア移動 | 混在取得は正常。ソウルだけの元で通常を選んでも通常コアを生成しない |
| コアシュート | 通常→ソウルで取得可能。ソウル辞退後の再タップで通常コアを過剰取得しないよう修正 |
| pay_cost配分・持ち主のライフ内訳・代替召喚コスト | 共通pendingは種類別残数と合計上限を別管理。ライフ・効果支払いの既存GUI/REST回帰を維持。代替コストのnormal-first契約は維持 |
| any_movable配分・単一元配分 | 種類別のdraft/held数を管理。任意配分の同一元通常＋ソウル取得と配置を追加回帰。単一元の種類切替も通常上限と独立 |
| splitDestinations・リンクエイド・発揮前提・固定/均等移動 | 通常のみ・固定1個・エンジン自動処理、または後段で種類を選ぶ経路。今回の混在選択の上限比較なし |

再現入口: `?scenario=core-hud-audit&kind=mixed-placement&source=reserve`。
`kind=mixed-multi/mixed-free/mixed-separate/mixed-shoot/mixed-cost/mixed-distribute`、
`source=field`、`owner=bob&viewer=bob` で各経路を確認する。
回帰は `e2e/scenario-mixed-core-selection.spec.ts` と
`test/brave-separation-core-selection.test.ts`。取得内訳だけでなく確定後の盤面も検証する。
「いいえ」でソウルを辞退する経路では、混在に選び直す際にリセットを使う既存仕様を維持。

## 2026-09-26: ソウル確認と選択者の再監査

9月18日時点の「代替コストnormal-first」「発揮前提は通常のみ」「コアシュートは効果側が種類を指定」という扱いを訂正する。裁定は [公式エターナルQ31528・信頼度A](../10_rules/06b_core-removal-choice.md)。

| 経路 | 今回の確認・修正 |
| --- | --- |
| 通常支払い全入口（召喚・配置・マジック・ミラージュ・アクセル・チェンジ・効果起動） | 辞退状態を支払い単位で初期化。前のマジックで辞退しても次の初回リザーブタップで混在確認 |
| 対象選択後のpay_cost | フィールド候補の有無で省略せず共通自動支払い判定。リザーブ混在でもHUDへ |
| 効果内コスト・ライフ内訳 | 共通HUDの通常/ソウル候補とリセットを維持 |
| 代替召喚コア移動（ベル） | 種類確認を有効化。配置先1か所でも明示配分で選択したソウルを保持 |
| 発揮前提コア除去 | 候補列挙・GUI・REST・AI入力にソウルを接続。共通移動プリミティブで確定 |
| コアシュート | 対象と個数の確定後に持ち主へ内訳選択。一意な内訳は即時。元の効果原因・配分・継続を保持 |
| 自由移動・単体/複数配置・分離・any_movable配分 | 通常残0・通常コア移動禁止なら確認を省略してソウル取得。通常が合法に残るときだけ確認 |
| 単一元の配分 | 明示のソウル配置先選択が存在。配分を種類確認で置き換えない |
| リンクエイド・ボイド移動・core_split・カウント減少・固定移動 | 通常限定・個数だけ・種類指定済みの契約を維持。ソウルを選べない場面へ確認を追加しない |

回帰入口は core-hud-audit&kind=repeat-payment、kind=gate&normal=0/5、kind=mixed-shoot&choice=1&owner=bob。既存のmixed各種・ベル・効果コストのGUIとRESTも確認する。

追加生成された複数ソウルの個数API・primary以外の候補列挙は既存の [P3-101](../../../issues/P3-101_soul-core-multiple.md) に残る。今回の確認漏れ修正で、この複数個操作まで対応済みとはしない。

## 2026-09-27: エンジン内部の暗黙選択を廃止

- 自己・他カード・魂状態・トークン・分割召喚は共通の支払い判定へ集約。支払元が複数、またはソウルが候補なら共通HUDを待つ。
- すべての効果召喚・配置・デッキ公開後の場入りで個数と種類を選ぶ。複数所有者の召喚、合体用トークンの支払い前配置も同じ経路へ接続。
- 対象開示・step参照・回数制限・後続効果・神託・合体の継続を保持。ライフ増加置換とダメージ対処後の内訳も持ち主が選ぶ。
- 回帰入口: 「core-hud-audit&kind=pre-cost-token」、「kind=deck-placement&owner=bob&viewer=bob」。新規GUI/RESTテストは 「scenario-core-hud-choice-routing.spec.ts」、盤面回帰は 「core-hud-choice-routing.test.ts」。
- デッキ公開の有料分岐は、外部の手札増加対価だけでなく本文の追加コストも同じ金額計算へ含める。手札／手元の両行き先でGUI・AIが明示した支払い内訳を使う。
- 「effect-core-choice-must-use-hud」 が効果解決での汎用自動コア選択を禁止する。候補の実行可否シミュレーションは状態を確定しないため例外。

強制合体用トークンをコスト支払い前に出す場合は、トークン配置HUD→盤面再計算→召喚コストHUD→召喚応答窓の順に進む。対象開示・回数制限・合体先を再宣言せず引き継ぐ。複数の持ち主へ同時に戻るカードは持ち主ごとに配置を選び、全配置対象を相互の供給元から除外する。

配置確定後に元効果の後続ステップ・誘発収集へ戻り、未確定の場入りで後続効果を先行させない。ライフ増加置換やダメージ対処の選択後にも、通常/ソウルの内訳が複数あれば所有者の共通HUDへ戻る。手札追加対価も支払元省略で任意のコアを選ばない。

## 機械検知

- `multi-placement-field-source-ssot` は複数配置分岐での生の `cardInstances` 参照をASTで検知し、配置元の独自判定を防ぐ。
- scripts/check-ssot.mjs の core-operation-dedicated-selector は apps 配下も走査する。
- scripts/core-hud-ssot.mjs で旧専用モーダル、画面内のリンクエイド支払いボタン、発揮前提コア候補ボタン、固定された placement_multi HUD を検知する。
- 画面コンポーネント内のコスト源配分payload生成・専用recompose呼び出しもASTで検知する。
- 同ファイル内に共通HUDが存在しても専用分岐を免除しない。検知の正例/負例は core-hud-ssot.test.ts。
- コアの移動元/移動先の共通変換は core-hud-pending.ts。表示キーは coreDisplayOverrides.ts。相手ゾーンも所有プレイヤーごとに同じ表示関数で計算する。
