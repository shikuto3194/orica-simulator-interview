# 効果キューの本文識別

## 表示契約

同じカードに同じタイミングの効果が複数あっても、宣言待ち・発揮宣言後・入れ子の
スタックで、解決対象の原文を保持する。タイミング語や現在のキュー順は効果の識別子ではない。

- 効果出典のカード定義は `effect-source-display.ts` で確定する。ホスト・付与元・宣言時の面を混同しない。
- 前面キューと同じ出典の個体IDを盤面表示へ渡し、金色の輪郭と強い発光で強調する。文字ラベルは付けない。同名カードでも1個体だけに追随し、盤面確認でキューを隠しても発光を残す。前面切替で発光先を更新し、キュー消滅で解除する。合体ブレイヴも出典個体だけを発光させ、回転・相手側反転は維持する。
- 状態ラベルは全キューで効果出典に揃える。場以外はゾーン名、場では煌臨元・魂状態を優先し、それ以外は `getEffectiveCategory()` と `cardCategoryLabel()` による全カード種別を表示する。宣言後のスタックでも同じ判定を使う。
- DSL の effect index がある場合は対応する `effects[].textRef` を使う。
- 他カードから取得した効果の本文は `resolveGrantedEffectSourceDefinition()` で取得元を解決する。発揮元の本文へ取得元の `textRef` を当てない。動的取得は取得元名・Lv無視・展開済みのアタック/ブロック変更を表示し、取得条件ヘッダーを反復しない。
- registration index しかない場合は engine の `generate*Registrations()` / 登録 lookup から effect index を得る。GUI に登録条件やイベント列挙を再実装しない。
- 神技は指定された `grandwalkerData.divineSkills[index].effects`、アクセル・チェンジは各機構の `effects` の本文参照を使う。
- 召喚・配置宣言は本文を空欄にする。召喚時・配置時の効果は別キューで表示する。
- 本文参照を持たない旧状態・機構由来誘発は既存の印字ブロック抽出を使う。現行の DSL 登録と機構内効果には本文参照を必須とする。
- バースト全11種の確認に「バースト発動：相手の手札＋1枚（彗星「ブレイジングスター」）」のように条件事象・当事者・数量・原因カードを添える。発動宣言／効果発揮宣言のスタックも同じ原因を保持する。構造化イベントを優先し、旧状態は engine の変換関数を使う。自己回収の原因は公開時の定義を保持し、非公開カード名は推測しない。
- どちらかの原因で発動したら、そのカードだけが候補の他確認はキューから消える。選んだ原因・枚数を保持し、別カードのバースト候補は残す。辞退単位の残課題は [Q484と実装差分](../10_rules/04b4_simultaneous-hand-increase.md) を参照。

## バースト効果抑止中の発動確認（2026-09-21）

- 「バースト発動」を選んだ時点で、相手の無効化／発揮抑止が現在有効なら、StepChoiceと同じ本文カード・選択ボタンで最終確認を表示する。原因カード名と該当効果の `textRef` を示し、「発動する」「戻る」を選ぶ。盤面確認も可能。
- 発動中耐性や当該効果の「発揮できない」を無視する能力で抑止を回避できる場合は確認しない。発動自体が禁止され、合法な発動候補がないチェックは表示せず既存の辞退操作で整理する。
- 確認はクライアントの表示状態だけ。バーストの公開、対価支払い、発動宣言、`PendingStepChoice` の生成は行わない。確認時の判定をゲーム状態へ保存しない。発動宣言後に常時抑止元が離れる等で状況が変われば、既存の解決時判定で効果を発揮できる。
- 判定正源: `previewBurstEffectSuppression()` は既存の発動中耐性登録を一時状態へ適用し、解決時と共通の `getBurstEffectSuppressors()` で原因を得る。裁定・解決順は変更しない（[04b3: 無効と発揮できない](../10_rules/04b3_burst-suppression-and-paid-gates.md)）。
- 回帰: `burst-activation-confirmation.test.ts` と `e2e/scenario-burst-confirmation.spec.ts`。`?scenario=burst-confirmation`、`mode=normal/immune/bypass/nullify-bypass/cannot/forbidden/continuous`、`owner=bob&viewer=bob`。Alice GUI・Bob REST、確認の取消・盤面確認・横画面、抑止元離脱後の発揮を検証する。
