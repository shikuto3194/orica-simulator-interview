# ルームのデッキ選択

保存デッキ・ルーム・一人バトルは `SavedDeckBrowser` を共有する。検索、ヒット度・収録・名前・作成・更新順の並べ替え、
サムネイル、メイン／トークン枚数を揃え、内容は共通の `DeckViewModal` で確認する。
保存デッキ側には編集・削除・読込・デッキ情報を残し、ルーム側は選択用の操作だけを表示する。

## フィルターとヒット度

- 色・系統・収録パック・契約カードの候補を、現在の保存デッキ全体から生成する。候補の件数はデッキ数。メインデッキの正の採用枚数だけを集計し、トークンは含めない。
- 系統は区切り文字で分け、ダブルフェイスは両面を参照する。同じカードが複数面・複数系統で一致しても、その採用枚数は一度だけ数える。系統・契約カードは入力による部分一致も可能。
- 項目間はデッキ単位のAND。同じ1枚で全条件を満たす必要はない。候補は検索・絞り込みで消さず、保存デッキの追加・更新・削除で再生成する。選択中の候補が消えた場合は0件として残し、条件リセットで解除する。
- ヒット度は条件ごとの「一致する採用枚数 / メイン枚数」の平均。「契約なし」は該当時100%。不明カードも分母に含める。デッキ名検索はスコア対象外。スコアと計算説明は画面に表示しない。条件なしと同点は保存順を維持する。
- 初期値は「ヒット度・降順」。条件を選ぶとヒット度の高い順に並ぶ。「ヒット度」を選び直したときも降順から開始し、昇順も選択可能。ルームの選択中表示や使用可否には影響しない。
- 「フィルター・並び替え」ボタンで共通パネルを開閉する。色・系統・収録パック・契約カードと、並び替え項目・順序を同じ入力欄の配置にまとめる。閉じても条件と並び順は維持する。
- 統合ボタンとデッキ読込は共通の高さ・書体・装飾。ルームは既存の暗色と金色、明朝見出しに合わせ、縦画面は2列、横画面は操作欄と一覧を別スクロールにする。

収録データの照合・訂正根拠: [カードの収録情報 A/C](../00_meta/source-findings-card-metadata.md)。

## 操作

1. ルームの「デッキを選ぶ」または選択済みデッキから、大きな選択モーダルを開く。
2. 一覧から詳細を確認し、「このデッキを使う」で確定する。別途「準備完了」でサーバーへ登録する。
3. 一覧には確定済みのデッキを「選択中」と表示する。閉じる・キャンセルは選択と準備状態を変えない。
4. 別デッキへの変更確定で準備を解除する。同じデッキの再確認では解除しない。

文言は選択・準備状態と必要なエラーだけに絞る。使用可否は `validateMainDeckDefinitions` と
`MIN_DECK_SIZE` を参照し、枚数不足などの理由を一覧・詳細に短く表示して確定を無効にする。
通信中は重複送信を防ぎ、失敗時は元の選択・準備状態と開いている詳細を保持する。

## 一人バトル

一人バトルの準備画面は「あなた」「相手」の選択済みデッキだけを表示する。両者で別々の一覧を展開せず、
ルームと共通の `RoomDeckPicker` を1つだけ使う。モーダル内の選択先切替でも検索・フィルター・並び順を保持し、
詳細の「あなた／相手のデッキにする」で対象だけを確定する。取消では両者の選択を変更しない。
ランダムデッキへも同じ画面から戻せる。保存デッキ名 `random` とランダム選択は区別する。
ローカル優先の同名統合を維持し、クラウド・ローカルの作成日／更新日・代表画像・トークンも引き継ぐ。
使用可否はルームと同じ `deckSelectionIssue` で判定する。初期値は自分が最初の使用可能な保存デッキ、相手がランダム。
保存デッキがなければ両者ランダム。準備画面の暗色・金色と明朝見出し、モーダルの配色・寸法・操作部品を共有する。

## 状態と非公開情報

- `DELETE /api/room/:id/deck` は認証済み本人の `set_room_deck` RPC を `p_deck: null` で呼ぶ。
  RPCの行ロック・参加者検証・開始済み拒否を登録処理と共有し、DB migrationは追加しない。
- 対戦開始は未開始かつ読み取り時と同じ `players` の場合だけ書き込む。変更が先に確定したら409。
- `GET /api/room/:id` の `ownDeckCardNos` は本人の登録済みカードだけ。相手・観戦者には漏らさない。
  再参加時は保存デッキに照合し、削除済みなら「登録済みデッキ」として内容を確認できる。
- 変更・登録前に始まったポーリング結果は準備表示へ反映しない。相手の表示は準備状態だけ。
