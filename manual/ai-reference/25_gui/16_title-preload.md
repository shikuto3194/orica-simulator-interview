# タイトルのログインと素材保存

## 表示と遷移

- 初回起動のログイン後に、画像・音源・BGM一覧を一式保存する。未ログインでは一括取得せず、既存のタイトル内ログインを維持する。
- ログイン後の素材確認中は、タイトルを残したまま淡い金色のリングを回転表示する。横画面はタイトルを左・リングを右、縦画面はタイトルの下に配置。「読み込み中」の文字は表示せず、開始可能になれば「タップでスタート」へ切り替える。動きを減らす設定ではリングを静止させる。
- 不足分がある間だけ、初期取得は「ダウンロード中 N%」、保存済み素材の更新は「アップデート中 N%」と細い金色のメーター・直近3件の取得ログを表示する。横画面はタイトルを左・メーターを右、縦画面はタイトルの下に配置する。進捗は今回取得するバイト数を基準にする。
- 保存先は **アプリ専用ファイル領域（OPFS）→事前キャッシュ（Cache Storage）→逐次読み込み** の順。API不在、保存拒否、容量不足では自動で次の方式へ進む。両方保存できない場合も通常の「タップでスタート」に戻り、保存できたような100%表示はしない。
- 通信・整合性検証が失敗した場合も逐次読み込みで開始可能にする。既に検証・保存できたファイルは残し、次回起動に不足分だけ再取得する。
- ルーム・観戦の直リンクは、ログイン後、保存完了または逐次読み込みへ切り替わった時点で自動遷移する。開発用の `?scenario=` は直接開始を維持する。
- 保存済み一覧と実ファイルが揃っていれば、更新通信を待たず開始できる。約80バイトの `/asset-version.json` を確認し、版が違う場合だけ一覧・変更素材を取得する。取得は認証中のアプリが管理し、タイトルを離れても継続する。ログアウト時は中断する。
- PWAの復帰・オンライン復帰・表示中の60秒間隔で素材更新を確認する。タイトルで追加取得が始まったら初期取得と同じ表示にし、取得完了後に「タップでスタート」へ切り替える。取得中はタップ・キー操作で開始せず、BGMコントロールには素材更新を表示しない。既にタイトルを離れている場合はそのまま取得を継続し、完了後にBGM一覧も再読み込みする。

## 保存契約

- アプリ本体・ルール・カードデータ・画面コードはService WorkerのWorkbox precacheに保存する。画像・音源は認証後の共通ダウンローダーで保存し、同じファイルを二重に一括取得しない。
- `server/image-assets.ts` が画像・音源のURL・SHA-256・サイズとBGM一覧を `/asset-manifest.json` にまとめる。`/image-manifest.json` と `/api/bgm-manifest` は既存consumer向けに維持する。
- dev・本番で同じ一覧生成を使う。本番は画像・音源・静的 `/bgm-manifest.json` もdistへ出力し、BGM一覧のためだけのAPI通信を不要にする。取得済み一覧の版は収録素材の内容から生成する。
- 公開ビルドは登録作品の背景・音源欠落を拒否する。背景WebP・音源M4AのGit管理と変換手順は [公開用dist](../00_meta/public-build.md#タイトル背景bgm-の配備前提) を参照。
- 旧公開版の空のBGM一覧が保存済みの場合は、曲選択時に保存領域を迂回して最新版を取得する。全素材の保存完了を待たず逐次再生でき、有効な保存済み一覧のオフライン起動は維持する。
- `src/assets/local-asset-store.ts` のOPFS保存先は `orica-assets-v1`。応答ヘッダーと本文を1ファイルへ原子的に保存し、途中書き込みで旧ファイルを壊さない。初回は実際に書き込み可否を確認する。
- OPFSへ書けない場合は既存 `orica-images-v1` キャッシュへ切り替える。切り替え時は検証済み応答をそのまま再利用し、同じ素材を再ダウンロードしない。旧キャッシュの画像も再利用する。
- 両保存先に同一URLがある場合は保存世代の新しい応答を使う。書き込み拒否された古いOPFSファイルが更新済みキャッシュを隠さない。
- 最大2件を並行取得し、長さ・SHA-256・Content-Typeを検証した完全なファイルだけ保存する。破損・欠落分は再取得する。Web Locksが利用できるブラウザではタブ間の一括取得も直列化する。
- 音源などの大きなファイルは、受信が続く限り60秒を超えても取得を継続する。受信が60秒停止した場合だけ中断し、最大3回の試行後に逐次読み込みへ切り替える。
- 通常の画像・音源・BGM一覧URLはService Workerがローカルの検証済み応答から返す。revisionクエリは保存領域を迂回する。音源のRange要求にも対応する。保存応答がなければ通常の通信へ戻る。
- 不要素材の削除は新しい一式が揃った後だけ。他用途の保存領域は削除しない。アプリ本体の更新は[ブラウザの更新](../00_meta/local-pc-deployment.md#ブラウザの更新)に従い、安全な画面で自動反映する。

## 保存できる条件と範囲

localhostまたはHTTPSで、Service Workerがページを制御してから保存を開始する。3秒以内に制御できない場合は逐次読み込みで開始する。LANのHTTPなど必要なAPIを使えない環境も同じフォールバックを使う。

OPFSもブラウザが管理する端末内領域で、ユーザーのダウンロードフォルダーではない。保存の永続化を要求するが、拒否されても動作を続ける。OPFSとCache Storageは容量制限を共有するため、容量不足では両方失敗することがある。ブラウザの保存データ削除後は再取得が必要。一次資料: [MDN OPFS](https://developer.mozilla.org/en-US/docs/Web/API/File_System_API/Origin_private_file_system)。

素材を保存しても、ログイン・対戦同期など必要なオンライン通信は残る。ゲーム全体の完全オフライン動作を保証する機能ではない。

## 検証

- 単体: `apps/playground-web/test/image-{download,manifest}.test.ts` / `asset-store.test.ts`。検証済みファイル再利用、保存途中のフォールバック、破損拒否、容量不足、URL検証。
- GUI: `e2e/title-asset-storage.spec.ts` / `title-image-download.spec.ts` / `title-direct-link.spec.ts`。3段階の保存経路、更新待ちなし起動、通信なし音源Range取得、破損したOPFSファイルの再取得、ログイン境界と直リンク。
- 本番: `pnpm build` 後、`PW_TITLE_PRODUCTION=1` で `e2e/title-image-production.spec.ts`。本番PWAと実画像・実音源の代表サンプルを保存し、通信を切ってページを再起動する。`PW_TITLE_FULL_ASSETS=1` を併用すると実素材全件を対象にする（数GB）。
- GUI/REST双方向: `e2e/scenario-four-of-a-kind.spec.ts` などの既存シナリオ。
