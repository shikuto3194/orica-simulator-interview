# 誘発タイミングと原因チェーン

親: [ターンとタイミング](02_turn-flow-and-timing.md)、[派生効果の順序](02b_declaration-timing-window-principle.md#派生した効果ツリーの解決順2026-09-15-確認)。2026-09-25、原因ID必須化の実装前に裁定を再確認。

## タイミングの再確認

下表の公式根拠はエターナル版のみ、信頼度 **A / 実装採用**。語尾だけで一律に「直前」「直後」へ分類せず、何を条件とする本文かで境界を決める。

| 本文               | 発生・解決の境界                                                                                                                                                                                                                                                 | 根拠                                                                                                                                              |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 「～るとき」       | 「ライフが減るとき」など明示された直前の効果は原因処理へ割り込む。ただし、その割込みからの召喚時等は元の原因効果を解決した後に他の派生と同時発揮する。「煌臨するとき」も煌臨完了前で、煌臨時は完了後。すべての「とき」を直前割込みにしない。                     | Q11463、Q14247、Q28711、公式マニュアルpage12「煌臨の手順」                                                                                        |
| 「～したとき」     | 成立した事象から誘発し、原則として解決中の効果本文へ割り込まない。同一本文の「そうしたとき」「この効果で破壊したとき」は結果を受けた後段であり、別の誘発とは区別する。ライフ減少を防いで実際には減らなければ「減ったとき」は発生しない。                         | Q25971、Q282、page14「効果全般」Q6・Q7。[同一効果の成立結果](04e_leave-outcomes-and-trigger-eligibility.md)は独自qa-016～018・ユーザー確認Cも適用 |
| 「～離れるとき」   | 待機入りを参照する。原因の破壊・バウンス等を含む効果を解決してから、破壊時・消滅時と同時発揮する。離脱関連効果と派生を解決した後、魂状態・ブレイヴ残留等を選び、実移動する。                                                                                     | Q1346、Q1348、Q1349、Q1350、Q1501、Q1511                                                                                                          |
| 「～離れたとき」   | 待機入りではなく実移動後に誘発する。魂状態でフィールドに留まれば発生しない。通常バーストより先に解決する。                                                                                                                                                       | Q1360、Q1512。[離脱順序](04d_leave-choice-timing.md)の2026-09-22ユーザー確認C                                                                     |
| 「この効果発揮後」 | 前段→前段からの派生→前段で待機したカードの実移動→後段。「その後」は派生を挟まない。外側のカード使用コストで消滅したカードは、その使用効果全体と派生を終えるまで移動しない。                                                                                      | Q156、Q197、Q281、Q282、page14「効果全般」Q7                                                                                                      |
| 「バースト：～後」 | 条件成立時の手札誘発提示と同時に発動宣言する。破壊後・離れた後のバーストも待機入りで宣言し、実移動まで宣言を遅らせない。通常バーストの効果解決は、残る非バースト効果・派生の後。召喚時の「この効果発揮後」より前に宣言できても、その後段より先に効果解決しない。 | Q411（2026-09-18）、Q420、Q427、Q436、Q440、Q478、Q480、Q7734                                                                                     |

「ただちに発動」は該当する同時発揮群で優先する。ライフ減少直前のような割込み指定がなければ、解決中の本文へ割り込まない（Q11148、Q16207、Q28711）。独自スタックの発動宣言窓・効果発揮宣言窓は[02b](02b_declaration-timing-window-principle.md)の既定裁定を維持する。

「ドローしたとき」は同時に引いた枚数だけ誘発しない。公式Q22566の逐語は「1度に2枚以上ドローしても「ドローしたとき」は1回と数えます。」。取得済みエターナルFAQ `C:\dev\orica-simulator\external-qa-official\BS24.md:997-1000`、信頼度 **A / 実装採用**。
効果の系統・発揮者・「このカード以外」を条件とする本文では、ドローしたプレイヤーと原因カードを区別する。BSTH07-転醒R01(A)の配置時2ドローでは、同じインスタンス自身を除外し、別インスタンスは条件を満たし得る。実装・再現は[聖蓮船の回帰記録](../30_plan/03_completed-milestones-phase-6-seirensen-draw-trigger.md)を参照。

同時発揮群ではターンプレイヤーが順序を選び、一つを解決して新しい派生が生じたら内側を先に処理する。公式page13は「新しく発揮した効果を先に解決します」（ルビ省略）とする。Q6645・Q6163でも確認。外側の順序待ちは発揮不能と区別して保持する。

## 待機解除・分離・魂状態の再確認

2026-09-25追補。以下の公式根拠はA、独自裁定は各リンク先の信頼度で適用する。

| 処理                         | 時点と区別                                                                                                                                                                                                        | 根拠                                                                                           |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 離脱待機の終了               | 待機入りだけで実移動やコア返却をしない。原因効果の区間・派生・中断中の選択を終えて実移動するか、合法な「残る」で待機を解除する。内側の待機を先に閉じ、外側の待機を同時に消さない。                                | Q1346、Q156、Q197、[04 原因チェーンの閉鎖](04_state-based-rules.md#フラッシュのタイミング原則) |
| 「残る」による解除           | 先に残った対象の元の待機を参照する別誘発は資格を失う。同一本文で既に成立した破壊等の結果とは別。消滅時にコアを補充する効果がなければ自由に補充して残すことはできない。                                            | Q513、Q1355、[04e](04e_leave-outcomes-and-trigger-eligibility.md)、qa-016～018                 |
| 魂状態への置換               | 相手による離脱について、離脱関連効果と派生をすべて解決し、実離脱が確定した時点で選ぶ。先に魂状態にして離脱時効果を使うことはできない。魂状態で残ったカードは「離れたとき」を満たさない。                          | Q1501、Q1533、Q1511、Q1512。煌臨元の複数契約はQ1505・Q1506、[08a2](08a2_contract.md)           |
| 離脱するホストのブレイヴ残留 | 魂状態の選択と同じ節目。派生前に合体を解除しない。残さない場合はホストと同時に同じ移動先へ移る。残す処理はルール上の「分離」ではない。                                                                            | Q1501、Q27659、Q3216、公式page09                                                               |
| ブレイヴ残留時のコア         | 実離脱に伴うコア返却後、フィールド/リザーブから残すブレイヴへ配置する。ホストのコアがトラッシュへ移る置換があれば、そのコアは配置元に使えない。待機中の一般的な支払元可否と、この離脱確定時の処理順を混同しない。 | Q353、Q390、[03f 待機コア](03f_stack-failure-and-waiting-cores.md)                             |
| 通常の分離・効果による分離   | 通常はメインの基本行動。効果で行う分離はその本文の処理位置で行い、離脱時残留と混同しない。合体条件を失えばその時点で自動分離。必要Lvを保てないブレイヴのトラッシュ移動に破壊・消滅時を発生させない。              | 公式page09、Q1034・Q1291、[05](05_brave-and-attack-special-cases.md)                           |
| 交換・共有された下カード     | 交換の途中でブレイヴをスピリット状態にしない。異魔神が別ホストにも合体中なら、一方の離脱だけで残留選択や同行を発生させない。共有煌臨元の魂状態選択は[08a2](08a2_contract.md)の独自裁定に従う。                    | 公式page09、Q582、Q1061                                                                        |

待機中のコア除去による離脱理由の上書き可否は[03f](03f_stack-failure-and-waiting-cores.md)のユーザー明示裁定を優先する。本調査だけで既定裁定を変更しない。

## 原因IDの必須性

**2026-09-25 ユーザー指示（C / 実装要件）: 誘発の `chainId` が空であること自体を違法とする。** `null`・未指定・空文字・空白のみを正常な待機状態として扱わない。解封・神託・転醒・付与効果、公開・非公開・宣言待ち・バーストを含む。

- 効果由来の誘発は、原因効果とその解決区間のIDを保持する。解決時にも祖先関係を切らず、内側の子・孫を閉じてから外側へ戻る。
- ステップ開始/終了、アタック/ブロック、通常行動、効果によらないコア移動等にも、その発生を表す明示の根IDを生成する。親効果がないことと、原因IDがないことを同一視しない。
- 「次のステップ」の要求時は、現在のステップの終了時誘発とその派生をすべて処理するまで移動しない。終了時の原因IDと、実際に移動した後の開始時の原因IDは別に発行する。開始時処理の先取りにIDを使わない（[02 ステップ終了時](02_turn-flow-and-timing.md)）。
- 同時発揮群と原因効果は別情報。別効果による同時の手札増加等を一つの原因へ合算しない（Q484・Q7927）。直前割込みの派生が元効果の派生と合流する規則も保持する。
- 対象のいない空撃ち・不発・未宣言の資格喪失は[03b](03b_resolution-and-interrupts.md)に従う。原因ID欠落はこれらの合法なゲーム状態ではなく、生成・読込・検証で検出すべき実装不整合。
- 原因が欠落した旧保存状態の親子関係を、カード種別・配列順・名前から推測して補わない。
