# 誘発と中断再開の組合せ監査（2026-09-26）

親文書: [誘発タイミングと原因ID](02d_trigger-timing-and-causality.md)。

## 裁定と監査範囲

- 親文書の「効果由来の誘発は、原因効果とその解決区間のIDを保持する」を、中断・保存復元・反復にも適用する。外側の同時誘発群を選べるのは内側の子・孫を解決／辞退した後。
- [03c](03c_effect-text-interpretation.md)の「その後」と「この効果発揮後」を区別する。本文を中断する入力待ち自体を、効果完了と扱わない。「することで」のコスト辞退は効果不発であり、発揮後の観測を起こさない。
- [04b5](04b5_after-effects-and-burst.md)の通常バーストは非バーストの全派生後。発動宣言と効果発揮宣言を同じタイミングへ移さない。
- [04d](04d_leave-choice-timing.md)の魂状態・ブレイヴ残留選択は、関連派生後・実移動直前。離脱処理が作る選択を本文中断と同じゲートへ入れると循環待ちになるため、処理段階を区別する。
- 「次のステップ」は終了時誘発を閉じてから実移動し、新ステップの根IDを発行する。ステップID生成・移動の先行を許可する変更はない。
- 入替時のコアは[公式エターナルBS35 Q5847](https://www.battlespirits.com/faq/list.php?format=eternal&prodname=BS35)の「入れ替えたスピリットに置かれていたコアをそのままこのスピリットに置きます」（A、`external-qa-official/BS35.md:413`）。Q5846の「はい、疲労状態でフィールドに出ます」（同408行）に従い、回復指定がなければ場の状態を引き継ぐ。Q5848・Q5849のバトル継続と合体維持も共通入替処理を利用する。分離時は[05](05_brave-and-attack-special-cases.md)の疲労状態決定に接続する。入替を召喚や配置の神託として数えない。

## 発見と共通修正

| 発見 | 修正の正源 |
| --- | --- |
| 本文中断・効果完了・神託／発揮後の4つの待機一覧が不一致。入替選択中に後段が実行される | `effect/pending-resolution-policy.ts`。GameStateの全77個のpendingフィールドを型で分類必須にする |
| 入替選択に再開文脈がなく、本文・反復・発揮後処理を失う | 本文継続の共通builder/resumer。受諾／辞退とも同じ保存・再開経路を通す |
| 「することで」の支払い失敗による接続部のrollbackに発揮失敗の記録がない | インタプリタの共通rollback境界で記録し、既存の発揮後観測判定に渡す |
| バトル終了待機がpending種別ごとの手書き走査で、新しい保存先を見落とす | `chain-id.ts`の生きた原因文脈の走査を、ID検査とバトル寿命判定で共用する |
| 最後の選択・離脱を閉じた後の再判定が個別action種別に依存する | `applyLegalAction`の共通安定点で終了予約を再判定する |
| 保存された追加イベントがchainId検査を通らない | `supplementalTriggerEvents`も原因文脈として走査する。空IDの推測補完はしない |
| フィールドと手札の入替が独自の物理移動でコアをリザーブへ戻す | 既存チェンジの物理入替処理を共用し、入替イベントは召喚と区別する |

待機分類は次の4段階。異なる意味の待機を一律に止めない。

| 分類 | 本文のループ | 効果発揮後 | 離脱の完了判定 |
| --- | --- | --- | --- |
| input: 選択入力 | 停止 | 待機 | 待機 |
| context: 外側の本文／発揮後の再開文脈 | 内側を実行できる | 待機 | 原因区間に応じて待機 |
| cascade: 後続スタックの退避 | 内側を実行できる | 個々の効果は完了できる | 既存のバースト例外を保って待機 |
| outside: 誘発・離脱選択・宣言・ステップ等 | 各段階の規則で処理 | 各段階の規則で処理 | 自分自身を待たせない |

バトル寿命では、実行中の窓とflush用のスタック保存情報は「解決済みスタックを削除する前に寿命を確定する」呼出順を持つため、保存されていることだけで延命しない。未解決の本文はpending継続側で捕捉する。

離脱待機そのものとアタックステップ終了予約も、バトル終了判定の後で消化するため自身をブロッカーにしない。全件回帰で、離脱flushの直前に自分自身を待つ循環と、バトル終了後のステップ退出予約がバトル終了を止める循環を検出・修正した。離脱が新たに作る反応・入力待ちは共通走査で待つ。

「全組合せ」は上表の有限な軸の直積と、モデルに現れる保存先の全件を指す。任意のカード本文・任意深さの反復・あらゆる盤面を数学的に証明したという意味ではない。入力待ちの到達条件を満たさない組合せを、ダミー状態で合法とみなさない。保存経路テストの最小fixtureは保存不変条件専用であり、合法な対戦の実行テストとは別。

原因IDを持たない旧入替待機スナップショットも読込時に拒否する互換性変更を含む。

提供された `orica-snapshot-2026-09-25T12-31-52-843Z.json` は、`pendingTriggeredEffects[0]` と `[1]` のchainIdがnull。現行の共通検査は先頭で拒否する。原因関係を推測して読込を通す補完は行わない。
