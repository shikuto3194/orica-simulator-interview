## 常時/継続 vs 誘発/即時 の判定根拠(発揮開始タイミング語彙の有無)

(独自カードサイトQ&A qa-016、信頼度B、2026-07-18 ユーザー確認・BSLH01-T07..T17 由来)

効果が**常時/継続効果**か**誘発/即時(宣言可能)効果**かは、「する」/「できる」の**強制/任意の軸とは無関係の別軸**である。原文全体の発揮開始タイミングと、状態を維持する条件を区別する。特に『アタック時』見出しだけで本文すべてを誘発と判定しない（qa-009）。

- **発揮開始タイミング語彙が無い**(「〜の間」のような継続条件の記述のみ) → 常時/継続効果。誘発でも宣言可能効果でもなく、スタックタイミング元にもならない。
- **発揮開始タイミング語彙がある**(『召喚時』『破壊時』等の見出し、または「〜になったとき」) → 原則として誘発効果(強制/任意は別途「する」/「できる」で判定)。アタック/ブロック中の性質付与に期間指定がない場合は、[qa-009と混在本文](03e_attack-duration-precedents.md#bslh01-x03-常時部分と即時部分の混在)を優先する。

qa-016 逐語(`external-qa/qaData.js:172-179`、BSTH01-R04 紅 美鈴 の「離れない」効果に関する回答):

> 「類似効果として一番近いのは、『このスピリットが相手の効果でフィールドを離れるとき、同じ状態でフィールドに残る。』です。ただし、この効果は『離れるとき』などの**発揮タイミングの指定が無い常時効果**であるため、**スタックタイミング元になりません**。」

**アンチパターン(2026-07-18 実例)**: 「Xを満たしている間、フィールドに置き」(BSLH01-T07..T17【アーツ】)を、「置き」が動詞の終止形/連用形(可能形「置ける」ではない)=強制だから常時効果、と誤って判断した事例。強制/任意の軸(03c「する」vs「できる」)を継続性判定の根拠に使ったのは**カテゴリ錯誤**。正しくは、当該イディオムに『〜時』見出しも「〜になったとき」も無く、「間」による継続条件の記述のみであることが根拠。同一カード内の対比: 同じ文中の「フィールドにある間、…アタックステップに使用できる」は「アタックステップに」という named step 指定を持つため誘発/宣言可能効果(通常のマジック使用宣言)。

実装状況: `timing.kind:"continuous"` 相当の常時効果として表現する。機械監査: `scripts/cards-fidelity-audit.mjs` の `continuityWording` warn(2026-07-18 追加、`scripts/continuity-wording-detector.mjs`)が「満たしている間、フィールドに置き」型イディオムを検出したカードを一律フラグする(正誤は判定せず、本節の再確認を促す注意喚起のみ)。

### 「〜したとき」の結論部が状態記述の場合の条件付け解釈（qa-007 拡張、2026-07-28 ユーザー確認）

qa-007 逐語(`external-qa/qaData.js:84-89`、信頼度B):

> Q:『このスピリットのアタック時』などのタイミングが書かれていなくて「～したとき、」などと書かれている効果の発揮宣言にはスタックタイミングは発生するの？
> A:「はい、発生します。Lvの行などに明確にタイミングが書かれていなくても、「～したとき、」などと効果文内に発揮タイミングが書かれている効果は常時効果ではありません。ただし、「自分のスピリットがいるとき、」などの条件付けは含みません。」

qa-007 原文が明示する例外は、「とき」節**自体**が状態存在チェック(「いる」等)である場合のみ。ユーザー確認により以下へ適用範囲を拡張する(qa-007原文は結論部の性質まで言及していないため、ここは原文からの推論):

- 「とき」節に続く**結論部**が一回実行可能なアクション(破壊する/コアを置く 等)でなく、実行不能な**状態記述**(受けない/として扱う 等、`03b:20`「常在系」相当)であり、かつ
- 結論部に「このターンの間」等の**明示的な期間指定が無い**

場合、「とき」は"いつ発火するか"でなく"いつその状態がON/OFFになるか"の条件(スコープ)を指すと解釈し、常時効果として扱う(誘発でもスタックタイミング元でもない)。

対照: 「〜したとき、**このターンの間**、Xは〜」のように結論部に明示的な期間指定が付く場合は、「とき」は一回発火する誘発で、そこから独立した期間指定効果(即時型持続効果、`03b:47-53`)を生成する一回限りのアクションとなり、誘発効果として扱う。

precedent: BSTH07-転醒X02(A)「毘沙門天の宝塔」【神秘】Lv1「自分が系統：「星蓮」/「闘神」を持つ効果で手札を増やしたとき、自分の手札は、相手のスピリット/ネクサスの効果を受けない。」— 期間指定なし・結論部「受けない」は状態記述 → 常時効果。条件＝「対象効果(星蓮/闘神)による手札増加を原因として誘発した、相手側の誘発効果が未解決の間」を動的評価。詳細 `needs-ruling.jsonl` BSTH07-転醒X02(A)-神秘。実装未着手。

## 〔ターンに1回〕vs〔ターンに1回:同名〕

[対象別制限](03e_domain-repeat-scope.md)。

- **〔ターンに1回〕**: 同じカード名のスピリットが複数いたら、そのスピリットごとにターンに1回ずつ使える。
- **〔ターンに1回:同名〕**: 同じカード名のスピリットが複数いても、どれか1体が使ったら他は使えない。カード名が違えば別々に1回ずつ発揮できる。
- 「ターン」の部分は「ゲーム」「ステップ」に変わりうる (例: 〔ゲームに1回〕、〔ステップに1回〕)。

## ゲーム回数制限と複数の制限の併用

### キーワード名を指定した共有制限

2026-09-13 ユーザー裁定（信頼度C）: BSSL01-X01の「〔ターンに1回：【影の軍団】〕」は、自分の【影の軍団】全体で共有する。X02が取得した効果も同じ使用枠を消費する。個体やカード名ごとの枠には分けない。実装は `per_group` と `limitGroupId:"影の軍団"` を用い、使用プレイヤー・グループ・ターンで照合する。

| 原文                                                     | DSL                                 | 共有範囲                                          |
| -------------------------------------------------------- | ----------------------------------- | ------------------------------------------------- |
| 「ゲーム中に1回」                                        | `per_instance`, `duration: "game"`  | その個体でゲーム中1回。同名の別個体とは共有しない |
| 「〔ゲームに1回:同名〕」                                 | `per_card_name`, `duration: "game"` | 同じプレイヤーの同名カードで共有                  |
| 「ゲームに1回しか使えない」「ゲーム中に1回しか使えない」 | `per_card_name`, `duration: "game"` | 同じプレイヤーの同名カードで共有                  |

回数が2回・3回の場合も同じ区別で `maxCount` を設定する。「ゲーム中に」という語だけで
判定せず、「同名」「しか使えない」まで読む。期間と共有範囲は独立した軸である。

BSSA01-X02 の「〔ターンに1回：同名〕ゲーム中に1回」は、
`[{ kind: "per_card_name", duration: "turn" }, { kind: "per_instance", duration: "game" }]`
を AND で適用する。同一ターンの別個体は使用不可、後のターンの未使用個体は使用可。
使用済み個体は後のターンも使用不可。併記された一方の制限を落としたり、共有範囲を揃えたりしない。

根拠: 2026-09-10 ユーザー確認（信頼度 C）。原文抜粋:
「『ゲーム中に1回』はper instanceである」「『〔ゲームに1回:同名〕』/『ゲームに1回しか使えない』がper card nameである」。
既存実装・既存テストの異なる解釈は、この確認に従って修正する。
回帰検証: `packages/rules-core/test/game-usage-scope-audit.test.ts` で全カードの本文と制限定義、
同名別個体・相手側の使用可否を照合する。

BSTS01-C01「［受け継いだ想い］リムル=テンペスト」の OC 中メイン効果も、保存原文の
「〔ターンに1回:同名〕ゲート中に1回」に対し、2026-09-13 ユーザーが
「per card name per turnかつper instance per gameである」と確認した（信頼度 C）。
同名ターン1回と個体ゲーム1回を AND で適用し、保存原文の誤記を別の使用制限として解釈しない。

### フィールド離脱による個体制限の終了（2026-09-12、信頼度 C / ユーザー確認）

- BSGE01-CX01【バレットエディット】の「ゲーム中に1回」は、トラッシュなどへ実際にフィールドを離れ、再登場して別個体になった場合には再使用できる。
- 同効果は【魂状態】を含むため、魂状態になるだけでは消費をリセットしない。魂状態からスピリット状態へ戻っても消費を維持する。
- 実装では物理カードの `instanceId` を維持し、実離脱ごとに `fieldInstanceGeneration` を進める。使用記録には発揮時の世代を保存し、個体単位の集計だけで照合する。同名共有制限の履歴は残す。
- **per_instance の区別（同日ユーザー追加確認、信頼度 C）**: 【魂状態】を含まない効果の個体制限は、魂状態への移行でリセットする。【魂状態】を含む効果は魂状態経由でも維持する。期間軸（ゲーム/ターン/ステップ/バトル）とは独立で、`per_card_name` など同名共有制限はこのリセットの対象外。
- フィールド実離脱と魂状態化の世代を分離して記録する。魂状態を含むかはカード全体ではなく、発揮する効果の DSL 適用範囲と本文参照で判定する。同じ本文をスピリット用・魂状態用の DSL に分けた星霊衣も消費を引き継ぐ。
- 回帰: `packages/rules-core/test/bsge01-bullet-edit-reentry.test.ts`。

## 〔重複不可〕(『この効果は重複しない』) vs 〔ターンに1回:同名〕(『この効果はターンに一回しか使えない』)

両者は **別 keyword かつ別 scope**。混同しないこと。

| keyword                                                    | DSL kind        | scope                       | 例                                                                                                             |
| ---------------------------------------------------------- | --------------- | --------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 〔重複不可〕『この効果は重複しない』                       | `no_duplicate`  | **per-event (per-trigger)** | 同一 battle_end 発火で同名複数 source は 1 体に畳むだけ。同ターン別 trigger 発火では同名 source が再発火できる |
| 〔ターンに1回:同名〕『この効果はターンに一回しか使えない』 | `per_card_name` | **per-turn**                | 同名カード全体で 1 ターン 1 回。同ターン内の別 trigger 発火でも再発火不可                                      |
| 〔ターンに1回〕                                            | `per_instance`  | per-turn, per instance      | 各インスタンスごとに 1 ターン 1 回                                                                             |

`no_duplicate` の scope は per-event (裁定 2026-06-24, 信頼度 C / ユーザー確認)。`model.ts:895` の doc コメント「no_duplicate では duration 無視」はこの趣旨を表す。

### 〔重複不可〕の詳細

- 同じカード名のスピリットが複数いるとき、条件を満たしてもどちらか1体しか効果を発揮できない。
- 別のカード名のスピリットが同じ効果を持っていた場合は、カード名ごとに1体ずつ発揮できる。

2026-09-17 ユーザー確認（信頼度 C）: 同名の別個体が2件誘発すること自体は許容する。どちらかを発揮したなら、もう一方は発揮できず、解決キューからも消える。BSTS01-CX01は後続に「この『リムル』の効果で」とあるため、発揮元を勝手に1体へ固定しない。魂状態・スピリット状態を区別して選択できるようにする。

2026-09-18 ユーザー確認（信頼度 C）: 〔重複不可〕／「この効果は重複しない・できない」の必須誘発も、所有者が片方を「スキップ」できる。相手による順序選択後も別個体を発揮できるよう、任意効果の「発揮しない」と区別する。実装では別個体の発揮候補が残る場合に提示し、使用回数を消費しない。

実装は `triggerEventScopeKey` でイベント単位の使用記録を照合する。画像・順序選択・再キューは `isTriggeredSourceUsageAvailable` から `canUseEffectByUsageLimit` を用い、使用済みの候補を除く。本文・DSLの全件監査は `no-duplicate-audit.test.ts`、個体選択と後続ドローは `apps/playground-web/test/no-duplicate-queue.test.ts`。

## 「このカード」のアタック時とアタックステップ（2026-09-11）

信頼度 C（本文・ユーザー照合）。『このスピリット/アルティメットのアタック時』は本人の攻撃中に限定する。合体中ブレイヴの「このスピリット/アルティメット」は合体先を指す。別個体の攻撃中は条件を満たさない。

- フラッシュ見出しは `activated/flash` と本人の参加条件を併用する。`timingScope(self/attack)` はアタックステップの限定なので、本人の条件の代用にならない。裏返し等、本文に本人限定見出しのない別効果には条件を広げない。
- 継続効果も同じ本人条件を持ち、アタック参加・終了時に再評価する。既存 `self_state` の `reference:"self"` / `battleState:"attacking"` と共通条件評価を使用する。
