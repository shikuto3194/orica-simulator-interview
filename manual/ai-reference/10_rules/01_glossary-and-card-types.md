# Glossary And Card Types

## 使用 / 発動 / 発揮 の区別

この 3 語はルール上明確に異なる概念である。

### 使用（しよう）

- カードを手札などから出して効果を得る行為。召喚 / 配置 / マジック使用が該当する。
- 使用するカードは一度 `in_use` ゾーンを経由する（手札 → in_use → 解決後に field / trash）。
- 使用した結果として、実際の **効果を発揮する**。

### 発動（はつどう）

- **バースト限定**のアクション。バーストエリアにセットされたカードの発動宣言を指す。
- 発動した結果として、実際の **効果を発揮する**。
- 「マジックの使用」とは別の行為であり、「マジックの使用を制限する」効果はバースト発動を妨げない。

### 発揮（はっき）

- 効果自体を実行する行為。使用・発動のいずれを経由しても、最終的に効果が実行される段階が「発揮」。
- 効果が無効化された場合、「使用した / 発動した」事実は残るが「発揮」はされない。
- フィールド上のカードが持つ効果を直接実行する場合も「発揮」と呼ぶ（使用や発動を伴わない）。

### まとめ

| 語 | 対象 | in_use 経由 | 関係 |
|----|------|------------|------|
| 使用 | カード全般（召喚/配置/マジック使用） | する | 使用 → 発揮 |
| 発動 | バースト限定 | しない（バーストエリアで処理） | 発動 → 発揮 |
| 発揮 | 効果自体 | — | 使用/発動の結果、または直接 |

## カード名参照（「X」= 部分一致 / カード名：「X」= 完全一致）

効果がカード名を参照するときの一致条件は **記法で決まる**（裁定 2026-06-05）。
合体条件・対象指定・サーチ・「〜という名前の」参照など、名前を参照する**全効果に共通**。

| カードテキスト記法 | 一致条件 | 例 |
|--------------------|----------|----|
| `「X」`（カード名：なし） | カード名に `X` を**部分文字列として含めば成立**（変種カードも対象） | 「フランドール・スカーレット」は「[覚醒]フランドール・スカーレット」にも一致 |
| `カード名：「X」`（カード名：あり） | カード名が `X` と**全文完全一致**のみ成立 | カード名：「フランドール・スカーレット」は完全一致のみ |

実装メモ:

- DSL: `CardFilter.cardName: CardNameMatch`（`{ contains }`=部分一致 / `{ exact }`=完全一致 / `"self"`=発動元と同名）。判定は `card-filter.ts` の `matchesCardName()`。
- ブレイヴ合体条件は別型 `BraveCondition.cardNameContains`（部分一致）/ `cardNames`（完全一致）。判定は `legal-actions-availability.ts` の `matchesBraveCondition()`。

## 勝利条件

- 相手のライフが 0 になったら勝利。
- ライフが 0 になった瞬間に敗北する。ライフ減少後の誘発・バースト・フラッシュや同じ効果の後続処理を待たず、後から回復して敗北を取り消すことはできない。
- 「ライフが0になっても敗北しない」などの敗北防止効果が有効な場合だけ例外とし、その効果が失効した時点でライフ0なら敗北する。
- 上記の即時性と例外: 2026-09-11 ユーザー明示裁定（信頼度 C、実装採用）。
- 相手のスタートステップ時点で相手のデッキが 0 枚なら勝利。

実装メモ:

- 勝敗判定は「ライフ減少直後」と「スタートステップ開始直後」の 2 系統に分ける。
- デッキ切れはドロー失敗時ではなく、自分の次のスタートステップ到達時に敗北判定する。

## カードカテゴリ

### スピリット

- 攻撃と防御の基本ユニット。
- Lv と BP を持つ。
- 最低 Lv コスト未満になると消滅判定の対象になる。

### アルティメット

- スピリットの強化版カテゴリ。
- 高い BP を持つが、召喚条件を持つ。
- MVP ではスピリット類似の戦闘ユニットとして扱い、召喚条件だけ別レイヤに分離するとよい。

### ブレイヴ

- 単体ではスピリット状態にもなれる。
- 条件を満たすスピリットに重ねて合体できる。
- 合体/交換/分離という固有の標準アクションを持つ。

### ネクサス

- フィールドに「配置」するカード。
- 効果で盤面へ寄与するが、通常の攻撃/防御には参加しない。
- **フラッグネクサス** (Ver.17.0 追加): 系統「フラッグ」を持つネクサス。通常ネクサスと同様に扱う。創界神ネクサスとは異なる。契約ネクサスの場合は契約カードとしての特徴を持つ。詳細は `08a2_contract.md` を参照。

### マジック

- 基本的には使い捨て。
- `メイン` と `フラッシュ` の 2 モードを持つ場合がある。
- 使用後は、効果と派生効果の解決がすべて終わってからトラッシュへ置かれる。

## 重要な場所とリソース

ゾーンごとの公開/非公開（誰がどの情報を見られるか）は [01b_information-visibility.md](01b_information-visibility.md) を参照。

### ボイド

- コアを置いておく場所。
- コアステップや一部効果で参照する。

### リザーブ

- コスト支払いやコア移動の基本置き場。
- トラッシュのコアはリフレッシュステップでここへ戻る。

### フィールド

- スピリット、アルティメット、ブレイヴ、ネクサスが存在する主戦場。
- 同じ印刷カードでも、フィールド上かどうかでルール上の呼称が変わることがある。

### トラッシュ

- 破壊されたカード、使用済みマジック、破棄カード、支払いに使ったコアなどの置き場。
- ただしカード本体とコアは別物として管理する。

## 後年ルールで重要な状態

### 魂状態

- `魂状態` は、`魂状態` にできるルールや効果でフィールドに置かれた契約カードの状態。
- この状態のカードは、通常のスピリットやネクサスなどとしては扱わない。
- 少なくとも次はできない。
  - 上にコアを置く
  - アタックする
  - ブロックする
  - そのシンボルで軽減する
- Lv のある効果は発揮できない。
- ただし `〖魂状態〗` と書かれた効果は、Lv に関係なく発揮する。

実装メモ:

- `zone` 追加ではなく、`state / mode` として扱う方が自然。
- custom 側で似た mechanic を足すときも、まずこの official precedent に寄せる。

## キーワード効果 (Ver.17.0 用語改定)

Ver.17.0 で「属性専用効果」から「キーワード効果」に改名。

- 【粉砕】【強襲】【突進】等の【】で囲まれた効果の総称。
- **1体のスピリット/アルティメットがキーワード効果を複数個所持可能**（Ver.17.0 改定）。
  - 例: 【粉砕:2】と【粉砕:3】を同時に持つ場合、それぞれ独立して発揮する。
- キーワード効果は発揮時に個別に処理される。

実装メモ:

- キーワード効果の複数インスタンス: `keywordEffects` を配列で管理し、同名キーワードの重複を許容する。
- 該当カード実装時にインタプリタ側の重複処理を追加。

## AI/実装向けの重要な分離

- `CardDefinition.printedCategory`
  - 印刷上のカード種類（実装済み）。
- `CardInstance.zoneRoleName`
  - 今いる場所に応じた呼称（実装済み）。
  - 例: スピリットカードはフィールド上でスピリットとして扱う。
- 盤面上の戦闘単位は `GameState.battleEntities: BattleEntity[]` で独立管理（実装済み）。
  - `CardInstance.attachedToInstanceId` / `attachedChildrenIds` で合体関係を表現。
  - 合体スピリットは1つの `BattleEntity.memberInstanceIds` に複数 instanceId を並べて表現する（単一の `entityKind` フィールドは設けない）。
