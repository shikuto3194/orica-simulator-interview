## 1. 煌臨（Advent）

手札からソウルコアを消費し、条件を満たす自分のスピリット/アルティメットの上にカードを重ねる。**召喚ではない**。

### 煌臨条件

| 要素 | 例 |
|------|-----|
| 色・コスト・系統（**合体ブレイヴ含む**） | 「紫＆コスト3以上」 |
| タイミング | 「お互いのアタックステップ」フラッシュ |
| 対象種別 | スピリット / アルティメット |

### 処理手順

1. 手札から公開 → 条件確認
2. 「煌臨するとき」効果解決
3. ソウルコア消費（スピリット→トラッシュ、アルティメット→除外）。ソウルコアはフィールド/リザーブ/ライフから使用可能。除外時はトラッシュのコアも可
4. 煌臨元の上に重ねる
5. 『煌臨時』効果

### 状態引き継ぎ

コア・疲労/回復/重疲労・アタック/ブロック中・合体ブレイヴ・**期間指定ある効果**を引き継ぐ。期間指定なしの効果は消失。既存の煌臨元カードも積める（多重煌臨）。合体条件を満たさなくなったブレイヴは即分離・破棄。

### 煌臨元カード

- 下に**表向き**で重なる。表向き煌臨元≧1枚 → 【煌臨中】
- 煌臨元カード対象の効果のみ受ける。場所指定なき「このカード」効果は発揮可能
- **フィールド離脱時、煌臨元も全て同じ場所に移動**

### 主要裁定

- ソウルコアだけの対象は実支払いで消滅する場合のみ煌臨不可。「置いたものとして」なら可能。根拠・実装は [ソウルコア支払いと対象の存続](08a4_advent-core-payment.md)。
- スピリット扱いブレイヴ/ネクサス/分身スピリットには不可
- 煌臨中に再煌臨可能
- ライフのソウルコアで煌臨 → 「ライフ減少後」バースト発動可
- 派生形（神煌臨/超煌臨/契約煌臨/超契約煌臨/裏契約煌臨）は全て煌臨として扱う

#### 多重煌臨（1宣言で複数 host に同時に重ねる）— 裁定確定（2026-08-01、ユーザー確認）

BSSG01-X03「暁 切歌＆月読 調『アマルガム』」は、ソウルコアをトラッシュに置き、「暁 切歌」1体と「月読 調」1体へ同時に煌臨する。

**裁定**: 対象2体を1つの煌臨元スタックへ統合し、X03がその頂上に乗る。

- プレイヤーは対象2体のうち **どちらを「上」（＝直接の煌臨先、状態引き継ぎ側）にするか選択する**。選ばれた側は通常の煌臨と同じ「状態引き継ぎ」（本章 §状態引き継ぎ）を適用され、選ばれなかった側はその下に単純に畳まれる（状態は引き継がれない）。
- 継続効果・アタック/ブロック中かどうかは「上」側から引き継がれる。「上」に選ばれなかった側がこれらを持っていても消える。
- **維持コアは統合される**（両方のコアを合算してX03へ引き継ぐ）。「上」側のコアだけを引き継ぎ「下」側のコアを単純に失わせる実装は誤り。
- 実装方針: 「上」側へ通常の `executeAdvent`（1対1）を実行後、「下」側は `attachAsAdventSource`（`advent-system.ts:1246`、フィールドカードを別カードの煌臨元として直接配置する既存 SSOT）でX03の煌臨元へ追加する。ただし `attachAsAdventSource` は呼び出し側が事前にコアをリザーブ等へ退避済みという前提で `normalCoreCount: 0` にリセットする設計のため、**そのまま流用すると「下」側のコアが消失し裁定（維持コアは統合される）に反する**。実装時は「下」側のコアをリザーブ経由ではなく直接「上」側（＝統合後のX03インスタンス）へ合算する処理を追加する必要がある。
- 実装完了 (2026-08-01、P3-133): `DualHostAdventData`(model.ts) + `declare_dual_host_advent`
  (LegalActionKind) + `mechanics/multi-host-advent.ts` (executeDualHostAdvent) で表現。
  詳細は `issues/archive/P3-133/index.md`。`needs-ruling.jsonl`（cardNo: `BSSG01-X03`）resolved。

## 2. 転醒（Rebirth）

フィールド上のダブルフェイスカードを条件達成時に裏返す。**召喚ではない**。

### ダブルフェイスカード

- **A面**: コスト左上。デッキに入れる面
- **B面**: コスト右上。転醒後の面
- A/B は独立したカード情報。カード種類が変わることもある（ネクサス→スピリット等）
- 見えている面のカード種類として扱う

### 処理手順

1. A面の《転醒時》効果を解決（コア移動等）
2. 裏返す
3. B面「この面に裏返ったとき、フィールドに残り、カウント+1する」（**効果ではない**ため効果無効の影響外）
4. B面の《転醒時》効果

### 状態引き継ぎ

コア・疲労/回復・期間指定効果（BP減少も含む、公式Q1289）を引き継ぐ。コスト支払い不要。転醒後のLv最低コア未満なら「自分の効果で消滅」扱い（カウント増えず転醒中断）。ただし、公式 FAQ Q1282/Q1296 型の「このカードに自分の《ソウルコア》を置いて裏返せる」は、06_core-system の個別扱いに従い、置けない/最低Lv不足でも一度裏返してから転醒後カードを消滅させる。

### 主要裁定

- 「召喚時」「配置時」効果は不発
- **同じ原因の同じ発生からの転醒は1つのみ。異なる原因・後続召喚は別扱い。** [同時転醒の裁定と具体例](08a3_rebirth-trigger-causes.md)（2026-09-04）。
- フィールド離脱時、**自動的にA面に戻る**
- 煌臨元になるときもA面に戻る
- **転醒後ブレイヴの「このとき」合体/コア配置選択（裁定 2026-08-14、ユーザー確認）**:
  A面【転醒】本文に「このとき、この転醒後ブレイヴは、自分のスピリットに合体するか、
  自分のフィールド/リザーブのコア1個を置いてスピリット状態にする。」と続く型
  （BSSA01-転醒X01(A)/X04(A)）は、B面「この面に裏返ったとき」やB面『転醒時』として
  裏返った後に誘発する効果ではない。合体対象/コア配置は【転醒】解決中の内包選択であり、
  召喚時の維持コア配置と同様、選択が確定するまでルール上の状態は「転醒確定前」と扱う。
  UI 表示上は転醒後ブレイヴ面で候補提示してよいが、実状態の face swap、B面定型 count 処理、
  B面『転醒時』誘発収集は、合体またはコア配置が確定して転醒処理が成立した後に行う。
  実装SSOTは A面 `RebirthAction.postRebirthChoice`。`brave_combine`（例:
  BSTH09-TR01(A)）、`brave_combine_or_core`（例: BSSA01-転醒X01(A)/X04(A)）、
  `core_distribute`（例: BSFT01 TR系、BSTH02.7-TR01(A)）で表す。pending は
  `pendingStoneFlipCombine` / `pendingCoreDistribution` を使い、候補表示の definitionId は
  B面を示してよいが、`rebirthCompletion` が確定するまで instance の実 `definitionId` はA面のまま。
  B面 `card_event:"rebirth"` は、B面に実際に「このスピリット/ブレイヴ/ネクサスの転醒時」
  等の誘発効果が印字されている場合に限る。
- 「裏返す」効果 ≠ 転醒（カウント+1は発生するがLv効果不発）。**射程確定（2026-07-30、ユーザー確認）**: 自動+1の発揮源はB面に印字された定型テキスト「この面に裏返ったとき…カウント+1する」（batspi.com「転醒」参照）**のみ**。この定型テキストが無いダブルフェイスカード（転醒キーワード不使用、本文が独自に「裏返せる」＋付随効果とだけ明記、例 BSDB01-TX01(A)）には自動+1を適用しない（`AttackAlternativeFlipData`/`flipCardFaceWithoutRebirthCountBonus` 経由で本文明記分のみ加算）。既存 `{kind:"rebirth"}` 実装のうちB面に定型文が無いのに自動+1が適用されているカードは誤実装（判明例: BSGE01-TR01(A)）。
  - **注**: 転醒キーワード表記の有無とB面のカウント増減記述は独立した2軸であり、「転醒キーワードがあれば必ず+1する」と決め打ちしない。B面 textLines そのものがそのカードのルールテキストであり、定型文がなければ増減0、独自の増減文言（-2/+2 等）があればその原文どおりに実装する。横断監査は [P3-132](../../../issues/archive/P3-132/index.md)(完了・archive化) 参照。
  - **実装注意**: `executeRebirth` の `countBonusMode`（increment_1/reset_to_zero/none）はB面本文に合わせる。
- アタック中に転醒した場合、転醒後スピリットでバトル継続
- **前方転醒トリガー（A面【転醒】発火条件）の実装写像（2026-06-15）**: 専用機構を作らず既存誘発へ写像。疲労／アタック=`game_event`(`exhaust`/`attack`)、相手による離脱=`card_event`(`leave_field`, ネクサス`cause:"opponent_effect"`・スピリット`cause:["opponent_effect","battle"]`)。転醒条件は `condition:count_value(max:N)`・`steps:[rebirth]`・`executionMode:"optional"`。離脱トリガーでの転醒は**離脱の置換**＝`executeRebirth` が flip 時に `pendingLeave*` 解除＋`pendingLeaveEntities` 除去でフィールドに残す（`executeStayOnField` 同型）。正源例 BSTH03/06/09.2-転醒R01(A)。
- **分離を伴う転醒のコア配置（裁定d、2026-09-08ユーザー再確認、信頼度B）**: 「分離し裏返せる」型は通常の分離と同様、フィールド（待機元を含む）/リザーブからLv1以上になる任意数のコアをHUDで選ぶ。`separatesFromHost:true` は `pendingCoreDistribution` を使い、配置確定まで面・カウント・転醒時誘発を保留する。正源 X02(A)[10,11]/X03(B)[8,9]。
- **煌臨元の転醒を「合体していたものとして発揮」**: 発揮源自身の煌臨元だけを選び（`sourceUnderCardRole`）、分離コア配置確定時に元のホストを転醒後カードの下へ追加する。実際の合体イベントは発生させない。実装詳細は [P3-159](../../../issues/archive/P3-159/index.md)。
- **「アタックするかわりに裏返せる」型（裁定 2026-08-01、ユーザー確認）**: アタック宣言の代替行動として裏返す型（`CardDefinition.attackAlternativeFlip`、正源 BSDB01-TX01(A)）は、疲労しない・バトルも発生しない（アタック宣言そのものではなく単なる「裏返せる」任意効果）。ただし通常のアタック宣言と同じ legality（`getAttackDeclarationBlockReason`）を満たさない（既に疲労している等）場合は発揮できない。実装 `resolveDeferredFlipInsteadOfAttackStack`（`effect/structured-card-replacement.ts`）は疲労付与を行わない。
- **BSGE01 神機ブレイヴB面先頭ヘッダー（裁定 2026-08-15、ユーザー確認）**: 「スピリット状態のこのブレイヴは、疲労せず、アタック/ブロックできず、ただちに裏返す」は通常効果ではなくB面先頭のルールテキスト。`effect_resistance(exhaust)` と `prevent_battle(attack/block)` は他のスピリット状態ブレイヴ制限と同じく `ruleStrength:true`、`ただちに裏返す` は B面ブレイヴが合体していないスピリット状態単独になった瞬間の mandatory SBA（`revertToFrontOnSeparation`）として扱う。アタック中 host 離脱後、このB面だけで「アタック継続」は提示/成立させない。

付与された転醒も受け手の面で可否を判定する。B面ディオスクリアはヘラスの転醒を発揮しない（2026-09-26ユーザー確認、信頼度C）。記録: `needs-ruling.jsonl` の `bsaz02-dioscuria-granted-rebirth-back-face`。

### 逆転醒（B面→A面）— テキスト記法による2分類（裁定 2026-06-12）

逆転醒テキストは語尾で挙動が大きく分岐する。実装時にここを取り違えると、コスト未支払い／維持コア未配置の盤面破綻、または不要なコスト要求が出る。

**パターン1: 単純に表に返す（「表にする / 裏返す / 表返す」）**

- 単に面を反転するだけ。コスト支払い・維持コア配置・instance 変更は**発生しない**。
- 状態（コア・疲労/回復・期間指定効果）は完全に引き継ぐ。

**逆転醒でカウントは変動しない（裁定 2026-06-14）**: 前方転醒の「カウント+1」（line 78）は逆転醒では発生しない（パターン1/2 共通）。逆転醒は count 不変。実装では `executeReverseRebirth` で countValue を増減させない。

**パターン2: 裏返して「配置」/「召喚」する**

- 「コストを支払わず」の明示がない限り、通常召喚/配置と同じ処理:
  - 軽減あり（ただし**自身のシンボルでは軽減不可**、自身のコアは支払いに使用可）
  - **維持コア配置が発生**（コスト変更系効果が適用されても維持コア配置は省略されない）
  - **instance が変わる**（新規エンティティ扱い、継続効果の付与・カウンター・召喚酔い等の状態は引き継がず、新規召喚として再評価）
- 「コストを支払わず」が併記されている場合のみコスト支払いを skip する。**instance 変更と維持コア配置は skip しない**（明示テキストが無ければ常に発生）。

**実装含意**:

- 逆転醒カードを実装する際、テキスト末尾が「表にする/裏返す」だけか「配置する/召喚する」かを必ず確認する。
- パターン2 は通常 summon パイプライン（軽減・支払い・維持コア配置・instance 発番）を経由させ、`act_as_spirit` 系のショートカットや単純フラグ反転で済ませない。

### カウントエリア

フィールドに含まれない独立ゾーン。公式プレイシートでは**右上**（デッキの上）に配置。物理TCGではプレイ前にあらかじめ位置を決める。

- 「カウント+X」効果で**ボイドから**コアを置く
- カウント = カウントエリアに置かれたコアの数
- カウントに関する効果以外でコアを移動・使用・参照できない
- 転醒条件・OC条件・その他カード効果の条件で参照される

#### カウント＋ メタ修飾（「カウント＋効果で増やすカウントを＋N する」）（裁定 2026-06-14）

例: BSTS01-C03 ［行政担当］リグルド〔ターンに1回:同名〕「自分の『カウント＋』効果で増やすカウントを＋1する」。

- **適用先**: そのターンに**最初に解決する 1 件のカウント＋効果のみ**へ自動適用する（プレイヤーは乗せる先を選べない）。終止形＝**強制**、〔ターンに1回〕は **first-opportunity で消費**（最初の機会で必ず使い切る）。
- **「カウント＋効果」の範囲**: 自分の `count_increase`（カウント＋）action **全般**。バースト由来・他カード由来も含む（メタ修飾元カードの自己効果に限定しない）。
- 同型: BSSA01-転醒X02 記憶開放術 のコスト閾値書換メタ修飾も「自分の◯◯効果を一律修飾」系として本裁定の first-opportunity / 全般スコープに準ずる。
