### 6. 星霊衣 / アルドノアドライブ / タイプ：作戦（独自・確定 / 信頼度 B = カード本文 + ユーザー裁定 2026-06-09）

公式 FAQ 0件（作戦のヒットはカード名部分一致のみ）＝独自。Q&A も無く、ソースはカード本文＋ユーザー裁定。

**星霊衣（B面アンダーレイ）**: 「裏面で置ける」の**裏面＝B面 ≠ 裏向き(faceDown)**（[04 裏向き≠裏面](04_state-based-rules.md)）。host スピリット下の専用スロットへ **B面を表向き公開**で置く → **B面のフル素性**＋「【星霊衣】でスピリットの下にあるこのカード」印字効果が host に働く。**B面を持たない（転醒でない）カードは置けない**。挿入も入れ替えも**フラッシュタイミング**（マジック同様メインも可）。離脱時は host の行き先がトラッシュ以外でも下の星霊衣カードを**破棄**（[[project_face_down_zone_movement]] 既定を明示上書き）。**入れ替えで表に出たカードは正規の合体ブレイヴ（全素性・合体効果あり）**。スロット数は host テキストが規定。

**アンダーカード一般則（裁定 2026-06-11）**: カードの下にカードがある状態は公式でも頻出（毒刃・装弾・煌臨元など）で、特別な状態ではない。役割は **「煌臨元」か「それ以外（カードテキストで役割定義）」の 2 分類**。星霊衣/アルドノアドライブ等は機構別の専用サブシステムではなく、**汎用アンダーカード基盤＋役割タグ**に載せ、挙動（host が得る効果・入替タイミング・離脱時処遇）はカードテキスト＝DSL で定義する。**例外はクォーツのみ**（[07 §4](07_custom-orica-mechanics.md): 魂状態 host へ左右3枚+中央1枚をセットし、セット中のカードも魂状態として扱う＝「下」ではない独立セット状態。専用モデル維持）。

**鍵/星霊デッキオープン置換（裁定 2026-06-11、Q16858）**: BSFT01 C/TR 共通の『系統：「鍵」／「星霊」を持つ効果でデッキからオープンされたか、トラッシュに置かれたこのカードは、手札（1枚）と入れ替えられる』は、**実装済み BSTH01-R12 と同型**の `card_event(revealed/moved_to_trash)` + optional パターンで扱う。`trigger_from_zone:deck` は効果イベントの**論理起点**（deck reveal 効果由来か）を表す。Q16858 の「デッキからオープンされた後に破棄された場合、このスピリットの効果では召喚できません」を受ける自己配置／自己召喚型は、追加で `trigger_physical_from_zone:deck` を指定し、オープン後に `revealed` からトラッシュへ移動したカードを `moved_to_trash` の候補にしない。差分は原因条件が色→系統になる点と、手札 1 枚との入れ替えになる点のみ。FT 以外でも今後頻出する一般形。
原因系統は `trigger_tribes` 条件（`trigger_colors` の系統版・`TriggerContext.sourceTribes` 必須＝自カード系統へフォールバックしない）で表現する。**手札に加える add 型（C02/C04＋BSDB01-C10 地球人）は実装済（2026-06-14）。**

**swap 型（C01/C03『手札 1 枚と入れ替えられる』）の裁定（2026-06-14）**: (1) **任意／強制は語尾で決まる**＝`入れ替えられる`(可能形)=任意・`入れ替える`(終止形)=強制。これは汎用「可能形＝任意」一般則（[03c](03c_effect-text-interpretation.md) line 12 に `入れ替えられる` 明記）の個別事例で、**カード固有裁定は不要**。(2) **入れ替えで手札から出る 1 枚は「このカード（＝オープン／トラッシュに置かれたこのカード）」と同一物として扱い、同じ行き先へ送る**。その行き先は効果テキストが規定する（オープン札なら open 効果の処理先、トラッシュ自己回収ならトラッシュ）ため、**ルールで「デッキ」等に決め打ちしない**（「オープン由来→デッキ」は不正確）。(3) 実装は**出る札を「このカード」の行き先決定経路に相乗りさせる**だけでよく、由来別の専用分岐は不要。

**入れ替えカードの不活性則（裁定 2026-06-11 追補）**: 効果は 2 層 — ①本体効果（オープンし系統指定で「手札に加える/入れ替える」）②オープンカード側効果（「手札に加える/入れ替える」）。**入れ替えで手札から出たカードは、同効果の解決が終わるまで不活性**: (a) 同効果内で再選択できない (b) ①で入れ替えたカードが「オープンされたとき」持ちでも発火しない (c) ②で入れ替えたカードが①の条件対象（系統一致）でも対象に選べない。実装は「同一効果解決中に swap-in した instance の除外セット」を保持し、トリガー収集と対象列挙の両方から除く。

**アルドノアドライブ**: 【アルドノアドライブ：N】host 下の専用スロットへ **表向き**配置。本体は **【合体条件：合体不可】**＝合体ではなく、**シンボル/BP 統合は無い** enabler（存在で host が Lv 段効果を得る）。自軍【アルドノアドライブ】持ちを召喚/配置/転醒したとき手札/場から配置可→1ドロー＋ボイドからコア1個。**host 離脱時は下のカードも host と同じ場所へ追従**（トラッシュ固定ではない）。

**転召（裁定 2026-06-14）**: 【転召：N／〔系統＆コスト条件〕／ボイド】（例 サリエル BSTH001-X01「召喚コスト支払い後、対象の自分のスピリット1体の上のコアすべて（最低1個）をボイドに置かなければならない」）は **召喚時効果ではなく、召喚手順内のステップ**。

- 順序＝**コスト支払い → スタックタイミング → 転召 → 維持コア配置**（転召はスタック窓クローズ後・場入り前に挿入。[02:188](02_turn-flow-and-timing.md) コスト支払い完了後にスタック窓）。**この転召ステップ専用のスタック窓は開かない**。
- **対象（〔系統＆コスト条件〕＋最低N個コアを満たす自分のスピリット）が居なければ召喚宣言自体ができない**（no-op で召喚成立ではなく、召喚条件型の事前適法性ゲート）。
- 実装: `CardDefinition.tenshoSummon`（専用フィールド）＋ `canSummonCardTensho` 適法性ゲート（legalActions 列挙時）＋ `pendingTenshoSummon`（場入り前の強制コア消費）。旧 `card_event:summon` 強制誘発実装は廃止済み（ENGINE-tensho-summon-gate 解消）。

**タイプ：作戦**: `type:マジック` に付くキーワード。場の作戦マジックを「効果を**使用**できる」場合も、手札/手元同様に解決後はまずトラッシュへ移る。本文の「フラッシュ/スタック効果使用後以外でトラッシュに置かれたこのカードはフィールドに置く」は到着後の自己配置であり、除外されない使用なら field へ戻る。**「発揮する」だけの直接効果は使用ではない**ため発動元マジックを移動しない。また、「〜の間、フィールドに置き」のトークンマジック等の継続残置も優先する（ユーザー裁定 2026-09-01）。
場のマジックは**非アクティブ instance**で原則使用/発揮不可 — **ゾーン非依存効果**と**「フィールドに置かれている間」効果**のみ発揮。■「お互いのアタックステップ中フラッシュ効果を使用できる」は**元々マジックを使える窓だけ合法化**（flash 効果→フラッシュ窓、stack 効果→スタック窓。手札/手元使用の窓拡張）。被対象は**マジック対象 or カード対象効果のみ**（場にあってもあくまでマジックカード。スピリット/ネクサス対象は受けない）。

「使用できる」は**指定タイミングでの合法手を拡張する常時効果**。この許可自体を起動・誘発効果として宣言しない。許可されたマジックを使う際は通常どおりコストを支払い、その後で相手へのスタック窓を開く。許可文にスタックラベルが無くても、指定先のスタック効果を通常使用できる（ユーザー確認 2026-09-26）。

### 5. 分身（公式・確定 / 信頼度 A）

ソース: 公式 FAQ「汎用 -【分身】編」Q782 ほか87件（`external-qa-official/_freeword-分身.md`）。

- **定義(Q782)**: デッキのカードを裏向きでフィールドに置き、リザーブから**コア1個以上**でスピリット化＝「分身スピリット」。**召喚ではない**（召喚時系は乗らない）。**【分身：N】**=出せる上限枚数。
- 緑シンボル1つ（アタック可）／スピリット対象効果を受ける／**ブレイヴ合体不可**／**効果記述なしのバニラ**扱い。
- **破壊・手札/デッキ/手元に戻る効果ともに表向きでトラッシュ**（戻らない。待機で発揮する効果は解決後、戻る段でトラッシュ）。入れ替えも破棄されるため不可。
- 自分の裏の内容は確認可（相手に非公開）。複数の裏向きは**内容非統一**（置いた効果ごとに別管理）。

## マジック兼用ブレイヴ（二面性）（裁定 2026-06-14）

鍵ブレイヴ等の「このカードは、マジックカードとしても扱う」型。

- **「このカード」＝カード状態指定**。手札/トラッシュ等の**カード形態でのみマジック兼用**。フィールドでスピリット（合体ブレイヴ含む）として存在中は**マジックカードではない**。
- マジックとして**使用/参照される全箇所**でマジックとしても振る舞う（手札からのマジック使用、「マジックカード」を数える/参照する効果の対象など）。
- **合体可能数に数えない**。**魂状態を継承**（host が魂状態ならこのブレイヴも魂状態扱い）。
- 鍵ブレイヴが合体したまま魂状態になった場合、その魂状態の1枚の合体スピリットカードは通常召喚時のカード状態としてブレイヴ側のカード情報を引き継ぐ。例外的に軽減シンボルも引き継ぐため、BSFT01-CX01 + BSFT01-TR01(A) は通常召喚時 7コスト導4軽減、「本来の」コスト支払い時は CX01 単体の 2コスト導1軽減（`external-qa/qaData.js` qa-015）。
- スピリット状態ブレイヴの**アタック/ブロック不可・疲労しない**は、ユーザー確認裁定 2026-08-15 により**ルール強度**。マジック兼用ブレイヴ/アルドノア系/神機ブレイヴ/異魔神/導界者を含め、`prevent_battle` と `effect_resistance(exhaust)` は `ruleStrength:true` として扱う。
  - **BSGE01 神機ブレイヴB面の先頭ヘッダー**（「疲労せず、アタック/ブロックできず、ただちに裏返す」）の `ただちに裏返す` は mandatory SBA（`revertToFrontOnSeparation`）。
  - 実装上、成立済みアタック/ブロックは通常の prevent_battle CE では取り消さない。スピリット状態ブレイヴのルール攻防不可だけ `metadata.ruleStrength:true` として battle entity cleanup の対象にする。

## トークンカード（公式ギミック）（BS71/BS73 Q）

- **トークンカードはデッキ外に用意**し、**デッキに入れられない**（カード種類「トークンスピリット」等）。
- **デッキ外のトークンはコストを払っても召喚/配置できない**。**「トークンを出す」効果でのみ**フィールドに出る。
- フィールドを離れたら**トークンプール（デッキ外）へ戻る**（裁定 2026-06-14、トラッシュには行かない）。
- コアは**基本スピリット同様の維持コア配置**で、それを各カードの効果で拡張/制限する。
- 実装モデル: デッキ外の**トークンプール**ゾーンを保持し、`summon` の実在ゾーン前提と別経路（token-summon）で出す。出典: `external-qa-official/BS71.md`。

## 効果借用（別カードの効果を発揮）（裁定 2026-06-14）

- トラッシュ等の指定カードの**効果1つ**を、**借用先の記述どおり**（対象・コストも借用先準拠）に発揮する。
- ⚠ **2 分類**: (a) 真の借用（借用するカードが発揮元）と、(b) **借用に見えて借用先自身に発揮させる**型がある。テキストの主語/発揮元で判別する。
- タイミング/スタックは**基本的に借用を行うカードのタイミング**（フラッシュ/スタック窓）に従う。借用後の後段（「その後フィールドに置く」等）は**効果記述準拠**。

## BSGE01【リンクエイド】機構（裁定 2026-06-17）

BSGE01-CX01..CX04/R01..R05 (計10枚) のフラッシュ『お互いのアタックステップ』効果:

> 魂状態のこのカードは、系統:「GE」を持つ自分のスピリットから1コスト支払うことで、(リザーブ|フィールド/リザーブ)のコアを好きなだけ置いてスピリット状態にする。

ユーザー裁定（2026-06-17）:

1. **コスト源**: 系統「GE」を持つ自分のスピリット上の**コア1個**を支払い（**固定1コア**、軽減後コスト1や軽減シンボル参照ではない、疲労ではない）。
2. **配置先スコープ**: CX01 文末『リザーブのコア』 vs 他『フィールド/リザーブのコア』の差分は**意図的**（CX01 は reserve-only、他カードは field+reserve のコア source から好きなだけ置ける）。
3. **「スピリット状態にする」**: **召喚扱いではない state-change**。`executeSoulStateSummon` 経路を通さず、**召喚時効果は誘発しない**（魂状態 → スピリット状態への直接遷移）。
4. **「1コスト」の意味**: **固定 1**。他カードの『nコスト支払って』参照と同パターン（数値の文字どおりの数）。
5. **制限**: テキストに明示のないターン1回・同名制限は**なし**。

BSGE01-C03 [4,5] の書き換え効果「【リンクエイド】を『フィールド/リザーブから1コスト支払って、フィールド/リザーブのコアを好きなだけ置いてスピリット状態にする』に変更する」は、**コスト源を field+reserve に拡張**する書き換え（GE スピリット上のコアに限定しない）。

実装含意: 新規プリミティブ `link_aid_revive`（cost_source: `GE_spirit_cores`、place_scope: `reserve` | `field+reserve`、no_summon_event）を起こすか、**既存「コスト支払い + 非召喚 state-change」プリミティブの組み合わせ**で表現する。`BSSL01-C05` の `executeSoulStateSummon` 先例とは経路が異なる（あちらは召喚扱い）。

## BSTH09-C04/C05 「手札/手元と入れ替えられる」（裁定 2026-06-17）

BSTH09-C04/C05（妖戒系）の deck_reveal 後 swap:

> その中の[桂斧]1枚までと[少名 針妙丸]1枚までと[系統:妖戒のカード]1枚までを**手札/手元と入れ替えられる**。オープンしたカードはデッキの下に戻す。

ユーザー裁定（2026-06-17）= 上記**BSFT01 C01/C03 swap 型先例（2026-06-14）の destination 2 ゾーン拡張版**:

1. **入れ替えの実体**: **1対1 物理交換**（先例どおり）。picked カードを**手札 or 手元**へ入れ、その swap 先ゾーンから1枚を**「このカード（=picked）」と同じ行き先**（このテキスト本文では「デッキの下」）へ送る。
2. **任意/強制**: 汎用『可能形=任意』([03c L12](03c_effect-text-interpretation.md)) 適用で『入れ替えられる』= **任意**。
3. **pick 単位の独立選択**: 桂斧/針妙丸/妖戒の**各 pick について独立に**「入れ替えるか／どちら（手札 or 手元）と入れ替えるか」を選ぶ（先例の per-card 任意性を 2 destination に自然拡張）。
4. **片側ゾーンが空の場合**: **β-1 諦める** — 手元が空なら手元側 swap 不可、手札が空なら手札側 swap 不可、両方空なら pick 諦め（**単純 add フォールバックは行わない**）。

実装含意: BSFT01 先例の「出る札を『このカード』の行き先決定経路に相乗りさせる」モデルを **2 destination 化**するだけで足りる。両ゾーン残量チェック + per-pick destination 選択 UI の追加が必要。

`BSTH01-M03`/`BSTH02-C03` 二択 deck_reveal のコスト支払いタイミング裁定は、サイズ上限のため
[07c_card-observed-mechanics-extra.md](07c_card-observed-mechanics-extra.md) に分割した。
