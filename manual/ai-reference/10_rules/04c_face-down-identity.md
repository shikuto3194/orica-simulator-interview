# 裏向きカードの素性 (P3-69)

親文書: [04_state-based-rules.md](04_state-based-rules.md)。サイズ上限超過に伴い分離（2026-06-12）。裏向きカードの identity モデルと「裏向き ≠ 裏面」の混同回避を集約。

裏向き（非公開）カードは、**素性を一切持たない**のが既定。名前・色・コスト・シンボル・系統・Lv・BP・能力のいずれも無い「裏向きのカード」として扱う。

- **例外（その非公開状態で発揮すると明記された能力のみ）**: 「手札にあるこのカードは」/ 「セットされているこのカードは」(バースト) /「手元にあるこのカードは」のように、テキストがその非公開ゾーン/状態を scope する能力だけが働く。これらは別経路で gate される（バースト=`setBurstStates`、手元=`set_aside` ゾーン、手札 play=`applicability.zone`）ので、通常のフィールド効果登録には乗らない。
- **付与は additive**: 「〜として扱う」効果（`act_as_spirit` 等）が、素性ゼロの裏向きカードに名前・シンボル・系統・Lv・BP・限定能力を*載せる*。既定が null なので「印字を override で打ち消す」のではなく「無に付与する」。付与が外れれば再び素性なしに戻る。
- コントローラーが詳細表示で表面を覗けるのは presentation の話で、ルール上の素性とは別軸。

## 分身状態と効果の消失（2026-09-25ユーザー確認、信頼度C）

カード状態は表向き・裏向きを問わずアタック/ブロックできない。印字のカード種類と、現在フィールドの実体として扱われているかは別軸。疲労ブロック許可だけでは実体を得ない。`isCardTextCardState` をカード状態/実体の共通判定とし、戦闘資格と表示から参照する。「スピリット/アルティメットとして扱わない」という種類参照の否定は実体の喪失と区別する。
効果源を参照する「スピリットの効果」はスピリットカードの効果も含む（[公式Q3641と耐性判定](04b2_effect-prevention-priority.md#効果源の種類はカード状態も含む2026-09-25確認信頼度a)）。カード状態だからという理由で効果源の種類を消してはならない。純化による裏向き化の素性喪失は別に適用する。

分身自身の効果が消えても、分身としての状態まで失うわけではない。分身が持つ効果と、裏向きカードをスピリットとして扱う状態を区別する。
BSTH01-X04【フォーオブアカインド】は本体の現在値を参照する。本体が相手の離脱効果の対象になり、対象変更せず実際に離脱した場合、参照元がなくなり、残されたカードは分身状態を持たない裏向きカードになる。元の印字種類へ戻さず、フィールドの共通カード状態表示へ送る。
実装では `act_as_spirit` の状態付与を判定し、分身の効果記述の有無で配置を決めない。X04本体離脱時の付与終了は既存の `recomputeContinuousEffects` に従う。

## カード状態への移行時の初期化（2026-09-26ユーザー確認、信頼度C）

カード状態になったカードは、以前の実体が持っていた状態を一度リセットする。疲労・重疲労、「防げない疲労」の由来、次のリフレッシュで回復しない一時フラグを持ち越さない。手札へ戻った純狐（BSTH10-X02）も、次の通常召喚では回復状態で場に出る。

戦闘状態の初期化は `card/card-state-reset.ts` を正源とし、ゾーン移動・離脱確定・魂状態化・状態ベース処理から共有する。フィールド内の純化や分身状態の終了にも `isCardTextCardState` の共通判定を使う。離脱待機中はまだ初期化せず、状態付与中の分身や「疲労状態で召喚」した実体の疲労は維持する。初期化は回復効果ではなく、コア移動・合体解除・継続効果の寿命・効果使用回数は各既存ライフサイクルで処理する。

回帰: `card-state-reset.test.ts`、`?scenario=kanjuden&mode=junko-resummon`（`owner=bob` でREST側）、`scenario-card-state-reset.spec.ts`。通常再召喚と純化についてAlice GUI / Bob RESTで状態一致を確認する。

## 裏向き ≠ 裏面（混同の罠）

- フィールドに置かれていても、魂状態やカード状態のカードは手動「コア移動」の配置先にできない（2026-09-26ユーザー報告に基づく修正、信頼度C。魂状態のコア配置禁止は [契約](08a2_contract.md#魂状態)）。GUI候補・preview・RESTの拒否は `getManualCoreMoveCardBlockReason` で共有する。スピリットとして扱う状態付与が有効な分身への配置は可能。

- **裏向き** (`faceDown:true`): BS ロゴ背面・非公開 → **素性なし**。
- **裏面=B面** (転醒): `divineTransformState` セット・`definitionId`=B面で**表向き公開** → **B面のフル素性**。null 禁止。
- null-identity ゲートは `faceDown` のみにかける。「資源として置く」≠「裏向き」（表向きのまま資源化される手元札等は素性を持ち、寄与のみ別ルールで抑止される）。

実装メモ (P3-69 Phase 1):

- `getEffectiveSymbols` / `getEffectiveSymbolBundles`（battle-shared）、`getEffectiveTribe` / `getEffectiveCategory`（act-as-spirit）が `faceDown` を見て、付与があればその値、無ければ素性なしを返す。
- `continuous-effect-rebuild` はフィールド裏向きカードの印字継続効果を登録しない/失効させる。
- 中央 `resolveEffectiveIdentity`（battle-shared）が統一 entry + memo として表向き=印字+CE / 裏向き=null+grant を解決。ただし全 consumer の単一 resolver 化は循環 import で不可と判明し、`getEffective*` は各 dimension の正準 primitive として下位 module に残す（face-up の `def.*` 直読みは正当な仕様）。詳細は [issues/archive/P3-69](../../../issues/archive/P3-69/index.md)。
