# 情報の可視性（公開情報 / 非公開情報）

親文書: [01_glossary-and-card-types.md](01_glossary-and-card-types.md)。ゾーンの定義は親の「重要な場所とリソース」節を参照。

「誰がどの情報を見られるか」の正源。**裏向きカードの素性**（名前・色・BP を持つか）は別軸なので [04c_face-down-identity.md](04c_face-down-identity.md) を参照。本章は「見えるか」、04c は「見えたとして何であるか」を扱う。

## 原則（裁定 2026-05-29）

**表向きのカードはすべて相手も閲覧できる。** 非公開になるのは次の 2 種類だけ。

1. **ゾーンが非公開** — 手札・デッキ。表裏に関係なく中身を相手に見せない。
2. **カードが裏向き** — 未公開バースト（裏向きセット）、フィールドの裏向き配置。

## ゾーン別の可視性

| ゾーン | 所有者 | 相手 | 備考 |
|---|---|---|---|
| 手札 | ○ | × | 例外は下記「開示イベント」 |
| デッキ | × | × | 所有者も中身は見られない（順序も非公開） |
| フィールド（表向き） | ○ | ○ | |
| フィールド（裏向き） | ○ | × | 分身トークン等。素性は 04c |
| バースト（セット中） | ○ | × | 公開済み（発動宣言後）は両者可視 |
| ミラージュ | ○ | ○ | 「表向きでセット」のため相手可視（08c） |
| トラッシュ / 除外 / 手元 / カウントエリア | ○ | ○ | |
| ボイド | ○ | ○ | コアのみ。カード実体を置く領域ではない（[06 コア](06_core-system.md)） |
| ライフ | — | — | コアのみでカード実体を持たない |
| revealed（公開中） | ○ | 条件付き | 下記 |

`revealed` ゾーンは公開範囲を 3 値で持つ。既定（未設定）は `both`。

- `both` — 両者に見せる（「相手に見せて」型）
- `self` — 公開した本人だけ（「見て」「確認して」型）
- `opponent` — 相手だけ

## 開示イベント

ゾーンの規定に関わらず、特定の手順が情報を公開する。

- **契約カードの提示**（ゲーム開始時）: 提示すると、その契約カードの種別が相手に公開される。手札に加えた後もこの情報は残る（相手は「何と契約しているか」を知り続ける）。提示は任意 → [08a2_contract.md](08a2_contract.md)
- **バースト発動宣言**: 宣言によって裏向きセットが公開済みになる
- **効果によるオープン**: 「オープンする」「見せる」と明記された効果。範囲は上記 `revealed` の 3 値に従う

## 耐性の証明（2026-09-27）

- 非公開カード自身の「このカードは効果を受けない」や、系統など非公開の属性に依存する耐性で処理を防ぐ場合は、その成立を証明するカードを両者へ公開する。バーストも手札保護も同じ。
- 公開済みの別カードが無条件で与えている耐性だけで防げる場合は、非公開カードの内容を示す必要はない。複数の耐性があっても、不要な追加公開はしない。
- 証明は効果による「見る」「オープン」の成功ではない。バーストはセットされたまま、手札は手札のまま。公開内容は履歴へ残し、liveの識別子を恒久的に公開しない。
- 手札破棄で他の処理可能なカードだけで必要枚数を満たせる場合、残す耐性カードの公開は不要。全て耐性などで破棄を満たせない場合には証明する。
- 根拠 A: 公式エターナル [BS43 Q7064/Q7050](https://www.battlespirits.com/faq/list.php?format=eternal&prodname=BS43)、[CB29 Q16303](https://www.battlespirits.com/faq/list.php?format=eternal&prodname=CB29)、[CB10 Q&A](https://www.battlespirits.com/faq/list.php?format=eternal&prodname=CB10)。条件付き/無条件付与の一般化は同日ユーザー確認 C として適用。

## 開示履歴と追跡（裁定 2026-08-07）

- 公開カードが手札・デッキなどの非公開ゾーンへ移ったとき、**何のカードがそのゾーンへ移ったかという公開済みの事実は履歴に残る**。
- 公開履歴ログでは、非公開ゾーンへ入った時点で live card instance との対応は切る。後に同名カードが公開されても、非公開化前の instance と同一だったことを履歴から再結合しない。
- 実装は公開時点の immutable な `definitionIdSnapshot` を履歴表示へ使い、現在状態の `instanceId` / `definitionId` とは分離する。

### デッキ内既知スロット（裁定 2026-08-11）

デッキ自体は所有者にも非公開だが、公開済みカードを「デッキの上/下へ戻す」「見たカードを上/下へ置く」など、戻し位置が明示された場合は、そのプレイヤー視点に限り既知位置を表示してよい。

- 内部状態はカード実体の `deckKnowledge` に公開範囲だけを保存する。順序・カード名を別管理しない。
- `knownDeckCards` はサニタイズ時に実デッキから導出する配送用データ。`indexFromBottom`（0 = デッキ下）と `definitionIdSnapshot` を渡し、live `instanceId` や `deckKnowledge` は viewer へ渡さない。
- `revealedTo=self` / `peek_deck(revealTo=self)` 由来の既知位置は本人だけに見える。`both` 由来は両者に見える。
- 公開デッキのカードでも私的な閲覧を経た選択・戻し順は本人だけに見える。過去の公開履歴を、新しい手札・デッキ位置の公開権限に使わない（[神域との組合せ](07e_kanjuden-mechanics.md)、2026-10-02）。
- 本人が知る手札・未公開バースト・裏向き配置からデッキ上/下へ戻した位置も本人だけに残す。「内容を見せずに」は相手への非公開を保つ指定で、本人の既知位置を失わせない（2026-09-22 ユーザー確認）。
- 当該プレイヤーのデッキがシャッフルされたら、そのデッキの既知位置はすべてリセットする。
- 未知区間はカード裏面として扱い、UI では 3 枚以上の連続非公開区間を「裏 ... 裏」のように省略表示してよい。

## 実装 SSOT

`packages/rules-core/src/state-sanitize.ts` の `sanitizeStateForViewer()` が唯一の実装。PvP ルームの per-viewer 送信と、クライアント単独経路（シナリオ / スナップショット）の表示用サニタイズを兼ねる。

- カードの秘匿は `cardInstances` の `definitionId` / `originalDefinitionId` を `_hidden_card_` に置換して行う（インスタンスの存在自体は隠さない = 枚数は公開情報）
- デッキ内既知スロットは 実デッキと `deckKnowledge` から `knownDeckCards` を生成し、`sanitizeStateForViewer()` で audience ごとにフィルタする。`cardInstances` のデッキ内容は所有者にも伏せたまま。
- `PlayerState` はサニタイズ対象外。ここに置いたフィールドは**全て相手に見える**（`contractCardNo` が該当）
- `maskPendingPromptsForViewer()` は別レイヤ。「相手の選択中に自分の UI が反応する」のを防ぐ**表示専用**マスクであり、秘匿とは目的が異なる
- 閲覧後のゾーン選択は、その発揮中に選択者へ開示済みの候補だけを `PendingZoneSelection.revealedCardDefinitionIds` へ渡す。画像・詳細はこのsnapshotを使い、live手札の秘匿は維持する。過去の効果の履歴や閲覧後に移動した実体からは復元しない。選択が終わると対応も消える。
- オープン境界の継続効果内にある `resume_deck_reveal` も同じサニタイズを再帰適用する。ロールバック用の `priorStateSnapshot` は選択者本人にも配送しない。サーバーの継続処理・キャンセル用原本は変更しない。
- 手札カードの効果を借用するときは、借用元が確定した時点でその1枚だけを公開履歴へ記録する。入れ子効果の選択・配置待ち中も確認できるが、手札のlive識別子は公開しない。マジック使用扱いは既存の使用時公開を使い、二重公開しない。

新しく「相手に見せたくない情報」を `GameState` に足すときは、カード実体なら `shouldHideCard`、プレイヤー単位なら `sanitizeStateForViewer` 側に明示的な除去を書く。既定は「見える」なので、書き忘れは情報漏洩になる。
