# Multi-Attack, Designated Attack, Life Reduction Cap

`05_brave-and-attack-special-cases.md` から分割 (2026-07-08、サイズ上限対応)。

## 複数体同時アタック

- 効果（例: BSTH07.8-XX01【導域】「妖精スピリット5体まで同時にアタックできる」、BSTH02-R03「プリズムリバー3体まで」）がある場合のみ、複数体で同時にアタック宣言できる。
- 同時アタック group 全体で「アタックしたとき」は 1 回として数える（公式 Q26342 / Q27706）。
- ブロック数の既定は **group 全体で 1 体まで**（公式 Q26724「2体で同時にアタックした時点で、そのバトルでは1体しかブロックできない」）。
- 効果がブロック数を変更できる:
  - BSTH07.8-XX01: 同時にアタックしているスピリットの数までブロック可。相手は「どのブロッカーでどのアタッカーをブロックするか」をペアごとに選ぶ。アタック中の 1 体に対するブロッカーは 1 体まで（独自裁定 qa-022, 2026-01-17）。
  - BSTH02-R03: 3体同時アタックに対し 2 体までブロック可。
- フラッシュ窓は単体アタックと同じく前半/後半の各 1 回。全ブロック宣言が完了（またはブロック放棄）した後に後半フラッシュが 1 回開く（独自領域・2026-06-12 ユーザー確認）。
- バトル解決は group 単位: ブロックされたペアの BP 比較と、ブロックされなかった参加体のライフ減少を同じ `⑤バトル解決` でまとめて処理し、`⑥破壊` は group 解決終了時点の BP で判定する（公式 Q26333 / Q26337）。

### 召喚後の即時アタック参加（BSTH07.8-XX01）

- 2026-10-16ユーザー確認（信頼度C、実装採用）: 「召喚した…スピリットは、相手のブロック宣言前なら、ただちにアタックできる」は、召喚成立 → 神託・召喚時効果と派生処理の完了 → 「アタックする／しない」の順で選ぶ。
- この選択は能動フラッシュ使用ではなく、相手のフラッシュ優先権やパスを待たず、優先権・連続パス数を消費しない。辞退した参加機会を後のフラッシュへ持ち越さない。
- 参加する場合は通常どおりアタック宣言のスタック窓を開き、その応答後に参加・疲労・アタック時効果を処理する。ブロック宣言後は参加できない。
- 「ただちに」誘発を同時誘発群の先頭で処理する一般則とは区別する。本件の召喚時効果・神託との順序は上記のカード固有裁定による。

## 複数体ブロック強制（1 アタッカー vs 複数ブロッカー）と多重同時バトルの BP 比較方式（裁定 2026-07-12, 信頼度 B・類推適用）

BSFT01-TR06(B)〜TR13(B) 系「系統：「星霊」/「星霊魔導士」を持つ自分のスピリット/アルティメットが
アタックしたとき、相手はブロックするとき、スピリット2体でないとブロックできず。ブロックされたとき、
それらと同時にバトルする。」型（1 アタッカーに対し複数ブロッカーを強制し同時バトルさせる効果）の
BP 比較解決方式。

- **個別比較（アタッカー1体 vs 各ブロッカーそれぞれと独立に1vs1のBP比較。合算比較ではない）を採用。**
  ただし下記の通り直接該当する先例ではなく類推適用のため信頼度は B（要再検証の可能性あり）。
- 公式キーワード【連刃】（例: BS31-X01 戦国龍ソウルドラゴン, BS73-TX01〈【連刃・烈火】〉）は、
  「同時にバトルする」複数ブロッカー状態が成立した後の BP 比較を問う Q&A を持つ。
  **ただし【連刃】自体はブロッカー選択の構造が BSFT01-TR06(B) と異なる**（公式FAQミラー
  `external-qa-official/BS31.md:24` Q5259「相手がブロックを宣言するときです。通常、相手が選ぶ
  ブロックするスピリット/アルティメットを、【真・激突】なら1体、【連刃】なら可能な限り2体、
  自分が指定できます。」= アタッカー側がブロッカーを指定する要素を含む。【連刃・烈火】
  (`external-qa-official/BS73.md:1215` Q30117) はさらに強く「相手のスピリット/アルティメットを
  好きなだけ指定して同時にアタックできる」＝指定アタック型で、疲労状態でも強制ブロック化する。
  対して BSFT01-TR06(B) の原文「相手はブロックするとき、スピリット2体でないとブロックできず」には
  攻撃側指定を示す語が無く、あくまで防御側が自由選択で2体を用意する制約のみ。両者はブロッカー
  選択の主体・強制性が異なり、「同一の構造」とまでは言えない。
- それでも、引用する Q5331/Q30118 の質問・回答自体は「2体ブロックが**既に成立した後**の同時バトル
  BP 比較」だけを問うており、その部分の答え（各ブロッカーと個別に1vs1で比較する）は選択メカニズムに
  依存しない解決ステップの記述と読める。そのため「2体ブロック成立後の BP 比較方式」という限定された
  論点についてのみ、この Q&A を類推適用する。逐語引用（公式FAQミラー `external-qa-official/BS31.md:396-397`）:
  `Q5331 (2024.10.31) 対象: BS31-X01 戦国龍ソウルドラゴン — Q: Lv2で合体しているこのスピリットが
  【連刃】で相手のスピリット2体にブロックされた後、フラッシュタイミングで破壊されブレイヴをスピリット
  状態で残した場合、どうなるの？ A: 相手のスピリット2体でのブロックはすでに成立しているので、【連刃】
  の効果はなくなっても、スピリット状態の自分のブレイヴ1体と相手のスピリット2体でそれぞれBPを比べます。`
  同型の裁定が `external-qa-official/BS73.md:1220-1221`（Q30118、【連刃・烈火】）にも重複して存在し、
  一貫して「それぞれBPを比べます」（各ブロッカーと個別に1vs1比較）と明言している。
  補強: `external-qa-official/BSC45.md:918-920`（Q30240）は「【連刃】などの効果で、BPを比べ相手の
  スピリット2体だけを同時に破壊した場合」を前提に、破壊された2体を「コストを合計」せず個別に扱う
  裁定を出しており、【連刃】系が2体を一体化した単一バトルではなく個別の破壊イベント2件として扱われる
  ことを裏付ける。
- ソース: WebSearch 経由で「連刃」キーワードを特定した後、`external-qa-official/` を `連刃` で grep
  し BS31/BS33/BS34/BS73/BSC45/SD49 の 6 ファイルを確認。BSFT01-TR06(B) 系自体は独自カードのため
  独自Q&Aミラー `external-qa/{qaData.js,errataData.js}` を `TR06`〜`TR13`／`同時にバトル`／
  `星霊魔導士` で grep したが該当 Q&A・エラッタは 0 件（カード本文のみ `external-qa/cardData.js:10968`
  に存在）。BSFT01-TR06(B) 系そのものを直接裁定する一次資料は無いため類推適用・信頼度 B。
- 実装メモ: `blockedByEntityId: string|null` → `blockedByEntityIds: string[]` 拡張時、BP 比較は
  `blockedByEntityIds` の各エントリに対して独立した 1vs1 比較ループで実装する（合算 BP を作らない）。
  破壊判定・ライフコア処理（Q5330/Q5723「両者破壊時、相手ライフのコア1個をリザーブに置ける」）も
  ブロッカーごとに独立して発生しうる。P2-05 Phase 5 の設計前提として採用するが、実装着手時に
  違和感があれば再度ユーザー確認を挟む（信頼度 B のため）。

## ライフ減少の上限キャップ（裁定 2026-06-15, 信頼度 C / ユーザー確認）

「このターン（の間）、自分のライフは N しか減らない」(N>0) 型（BSTH08-C01[3,4] N=1 / BSFT01-TR09(B)[7,8] N=2）の確定裁定。

- **= ターン累積上限**。そのターンに自分のライフが減る量の**合計**を最大 N に頭打ちする。アタッカー単位・バトル単位ではなく、**全原因（バトル／効果／その他）合算**で N まで。3 体が無防備アタックしても N=1 なら合計 1 しか減らない。
- カウンタは**自分のターン開始（自分のスタートステップ）でリセット**。「このターン」= 発揮側コントローラの現ターンに限定。
- 文面で挙動が変わる派生（このカード群は該当しないが、他カードで頻出しうる）:
  - **「アタックごとに N しか減らない」** = アタックイベント単位リセット（per-attack-event。同時アタックは 1 イベント）。累積ではない。
  - **「次の自分のスタートステップまで」** = 持続が相手の追加ターンをも網羅（「このターン」より長い duration）。
- 実装（2026-06-15）: `life_damage_interception mode:"turn_cap" cap:N`。全原因合算でそのターンの減少合計を最大 N に頭打ちし、累積カウンタ `lifeReductionCappedThisTurn` を自ターン開始でリセット。BSTH08-C01[2] N=1 / BSFT01-TR09(B) backFace[7,8] N=2 着地。`mode:"replace" cap:N` は per-participant クランプ（各アタッカーを ≤N の「相手のアタックでは N しか減らない」型）で別軸。
  - **攻撃者 BP 閾値付きの累積キャップ**（BSTH08.5-C21「BP6000 以下のアタックでは自分のライフは 1 ターンに 2 以上減らない」, 裁定 2026-06-16 / 信頼度 C / ユーザー確認）:
    - ⚠ **「2 以上減らない」= 減少は最大 1（cap は N=1。"2" は cap 値ではない）。**
    - **BP≤6000 アタッカー由来のバトルライフ減少のみ**を別カウンタで最大 1 に頭打ち。他原因や高 BP（>6000）由来は枠外で無制限（基底 turn_cap と独立トラック）。
    - 高低 BP 混在の同時アタック／同一バトルは group 合計でなく各参加体の BP で個別判定。BP 判定はアタック解決時の実効 BP。
    - 実装（2026-06-16）: `life_damage_interception mode:"replace" + attackerFilter:{ maxBp:N } + attackerBpTurnCap:M`。閾値一致アタッカー由来のバトルライフ減少のみを独立カウンタ `bpThresholdCappedLifeReductionThisTurn`（自ターン開始リセット）で最大 M に頭打ち（基底 `turn_cap` とは独立トラック）。BSTH08.5-C21（maxBp:6000 + cap:1）着地。test/bp-threshold-life-cap.test.ts。

## 指定アタック

### 基本

- 相手ライフではなく、指定した相手スピリット/アルティメットへアタックする。
- 指定された相手は、疲労状態でも強制的にブロック宣言したことになる。
- 指定アタックによるバトルは通常のバトル手順で解決する。

### 通常アタックとの差

- 相手ライフは減らせない。
- 相手の `ブロック時` 効果は発揮しうる。
- `アタック宣言 -> ブロック宣言` 間の通常フラッシュは、アタック宣言で発動したバーストと、その解決で待機した誘発を片付けたあと、まだ指定アタックが成立している場合に限り飛ぶ。
- このため、持続しない `アタック時` 効果を先に処理し、その後 still-valid なら強制ブロック宣言を起こして `ブロック時` 効果を積む扱いになる。

### 重要制約

- `ブロックできない` スピリットには指定アタックできない。
- 装甲/超重装甲などの「相手の[色]の効果を受けない」対象には指定できない（確定、信頼度A）。
  - デフォルトでは指定アタックの対象選択も「(発生源カードの色の)効果」として扱われ、該当色の装甲で
    防がれる。専用の無効化文言（「この『指定アタック』効果は〜効果では防げません」等）を持つ
    カードに限り、装甲対象にも指定できる例外となる。
  - 根拠: 公式FAQミラー `external-qa-official/` 複数件が一貫してこのデフォルト/例外パターンを示す
    (BS39, BS52 Q20739, BS62, BS63 Q10163, BS64 Q10516, BS73, BSC50, CB18, CB19, CB22, CB29,
    CB30, CB32, PC04, SD69)。`needs-ruling.jsonl` 26番は本裁定で解消済み。
  - 実装: 本エンジンの指定アタックはカード固有能力ではなく Ver.17 base rule のため、発生源カードの
    色は「その攻撃を宣言したスピリット自身」の実効カラーとして扱う (`isDesignatedAttackTargetLegal`
    の `attackerCard` 引数、`getDesignatedAttackAttackerCard` で ActiveAttack から解決)。
    `ENGINE-designated-attack-armor-guard` 解消 (2026-07-11, engine-claude)。
- どの相手を指定するかは、アタック宣言後に他のアタック時効果と同時に処理する。
- `相手のスピリットのアタック後` など、アタック宣言で発動したバーストを先に解決し、その解決で待機した誘発も含めて片付けてから指定アタック成立を再判定する。
- 2024-03-30 改定以降、そのバースト解決前にアタックしたスピリットがフィールドを離れていたら、そのバースト自体が発動できない。
- 指定対象が、アタック宣言で発動したバーストや他のアタック時処理の解決中を含め、ブロック成立前に消えたら、指定アタックは無効になり、通常のブロック前フラッシュへ戻る。
- 指定アタック成立後の強制ブロック宣言で、`ブロック時` や `バトルしたとき` など block-side の即時効果をどの順で積むかは、個別Q&Aを見ながら詰める。

### 実装メモ

- `AttackAction`
  - `mode=normal | designated`
- `designatedTargetId`
  は宣言時ではなく、アタック時効果解決の中で確定してもよい。
