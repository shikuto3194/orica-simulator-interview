- ユーザー指定（逐語）: 「いや、常時効果なんだから契約合体系と一緒にするべき」「同類の常時型「置いたもの」全面監査も実施」。**信頼度C（ユーザー指定に基づく実装判断）、実装へ適用済み**。
- カード本文の正源: `packages/card-data/src/cards/{BSDB01,BSGE01,BSRK01,BSSG01,BSSL01}.ts` の各 `textLines`。登録済み全カードの「置いたもの」を走査し、常時型10枚・誘発型1枚を確認した。
- BSDB01-CX01 `textLines[1]`: 「また、〔ターンに1回:同名〕自分は、《ソウルコア》をトラッシュに置いたものとして【契約煌臨】できる」。常時の許可を使うため、契約合体の許可元と同様、同名制限は許可元の「孫悟空＆ベジータ」で共有すると解釈する。過去のP3-117実装履歴にある occupant 側での記録は構造裁定の逐語引用には含まれず、今回訂正した。
- BSSG01-M01/M02 の通常Lv効果が煌臨元化後に失効する点は、`needs-ruling.jsonl` の同カード行（2026-07-25）のユーザー回答「乗ればその効果は消える」による。CX01だけは本文が魂状態/煌臨元も明示する。
- 非消費そのものの公式根拠（A）は [Q17101の記録](08a4_advent-core-payment.md)。スタック手順は [02_turn-flow-and-timing.md](02_turn-flow-and-timing.md)、回数制限は [03e](03e_effect-duration-and-repeat-scope.md)。

## 宣言と処理

1. 常時の許可元を発揮宣言しない。煌臨する手札カードの `declare_advent`、合体する手札ブレイヴの `contract_combine` を1件だけ提示する。
2. 宣言でスタック窓を開く。発揮元・発揮ゾーンは手札カード。常時許可元は独立したキュー項目やスタックを作らず、許可元の色・系統を発揮元として扱わない。
3. 窓後、通常の支払いと、有効な許可元による擬制支払いを共通の `pendingAsIfSoulCoreChoice` で選ぶ。成立する経路が1つなら自動選択する。
4. その経路で対象を再列挙する。許可元の消失・使用済み・本人の宣言条件・タイミング制限を確認する。常時許可が煌臨カード自身の「アタックステップ」指定をメインへ拡張することはない。
5. 擬制ならソウルコアを移動せず、対象の最後のソウルコアも維持・継承する。成立後に該当する許可の同名制限を記録する。不発時には記録しない。

【真バディ】の分岐・魂状態/煌臨元へのコア配置は既存の共通処理を利用する。旧 `declare_host_dual_advent` は新規に列挙せず、保存済みスタックの解決用互換処理だけを残す。
