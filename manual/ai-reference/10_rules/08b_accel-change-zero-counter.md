## 4. アクセル（Accel）

スピリット/アルティメット/ブレイヴが持つキーワード。手札からマジックのようにコストを支払って効果を使用し、**使用後はオープンして手元に置く**。

### 基本ルール

- タイミング: 「フラッシュ【アクセル】」or「メイン【アクセル】」
- コスト: 召喚コストとは**別に設定**（通常はアクセルコストの方が高い）
- 効果の所属: カード種別（スピリット等）の効果（マジック効果ではない）
- フィールドで効果発揮されるが、そのカードのシンボルは反映されない
- 手元に置くタイミング: **派生効果（破壊時効果、召喚時効果等）を全て処理し、破壊/消滅状態のスピリットをトラッシュに置いた後**
- 条件不成立時（「〜のとき」「〜することで」の条件を満たさない場合）: 効果未発揮扱い → 手元ではなく**トラッシュへ**。対象不在時の扱いは未確認

### BSTH08.5-R12の継続無料化（2026-10-29 ユーザー確認、信頼度 C）

「このカードが手元に置かれたターンの間」はそのターン中の継続条件であり、面霊【アクセル】を何枚でも0コストで使用できる。
「ゲーム中に1回しか使えない」は同名共有の無料化開始1回だけを消費し、開始済みの同じ継続付与は再消費しない。
通常支払いだけを選んだ場合は「できる」に従って未使用のまま。終了後の再入場・同名別個体による再開始はできない。
根拠: BSTH08.5-R12本文、[03e](03e_effect-duration-and-repeat-scope.md) の常時/継続判定（11行）と同名ゲーム制限（74〜76行）、ユーザー確認 2026-10-29。裁定記録は `needs-ruling.jsonl`。

### 手元のカード

手元はオープンゾーン。手札と違い公開され、手札操作効果（手札を捨てる/見る等）の対象外。
手元のカードは以下のように扱う:

- アクセル再使用: **不可**（手札からのみ）
- 通常召喚（スピリット / アルティメット / ブレイヴ単独）: **可**
- ネクサス配置: **可**
- マジック通常使用: **可**
- バーストセット / ミラージュセット: 未確認（現状は手札からのみ）

実装側の対応箇所:

- `getAvailableHandCardLegalActions` — 召喚 / ネクサス配置で `hand + set_aside` を統合列挙
- `getAvailableMagicLegalActions` — マジック使用で `hand + set_aside` を統合列挙
- `getAvailableAccelLegalActions` — アクセルは `hand` のみ（再使用禁止が意図通り）

### 主要裁定

- アクセルのコスト/軽減シンボルは手札操作効果を受けない
- マジック使用制限と同列に扱われる

### 実装状況

実装済み（`accel-change-system.ts` / `model.ts`）:

```typescript
interface AccelData {
  timing: "flash" | "main";
  cost: number;
  reduction: SymbolColor[];
  effects?: Effect[];
}
```

- CardZone `"set_aside"` で手元ゾーンを表現。
- `useAccelCardAsAction()` / `useAccelCardInFlashContextAsAction()` / `resolveDeferredAccelStack()` で宣言〜効果解決〜後始末を実行。
- 効果成功 → `moveCardToSetAside`（手元）。全アクセル効果の condition が不成立 → `moveCardToTrash`（トラッシュ）。
- アクセル使用時に `checkAndQueueOracleChoices()` で `use_accel` 神託トリガーを発火。
- 手元からの召喚は legal-actions に追加済み。

## 5. チェンジ（Change）

フラッシュタイミングで手札からコストを支払い効果を使用し、**フィールドのスピリットと入れ替え**可能。

### 基本ルール

- 効果発揮後の選択: **破棄**（トラッシュ）or **入れ替え**（条件を満たすスピリットを手札に戻し、自身を回復状態でフィールドへ）
- 入れ替えは**召喚ではない** → 召喚時効果不発
- コスト差の追加支払い不要
- 回復状態は「回復させる」に該当しない。重疲労状態でも回復状態にできる
- 入れ替え対象に置かれていたコアは、そのまま入れ替え後のチェンジカードに置く（BS35 Q5847）
- 合体中のスピリットと入れ替える場合、ブレイヴは合体したまま。合体条件を満たさなくなったブレイヴのみ分離する（BS35 Q5849）
- バトル中の入れ替え → バトル続行（Ver.11.0以降テキスト省略、裁定変更なし）
- 手札増加扱いではない（Ver.11.0以降） → 「手札が増えたとき」効果や手札増加バースト不発動
- 分身スピリット、スピリットとして扱っているブレイヴ/ネクサスとは入れ替え不可（専用効果がない限り）

### 実装状況

実装済み（`accel-change-system.ts` / `model.ts`）:

```typescript
interface ChangeData {
  cost: number;
  reduction: SymbolColor[];
  effects?: Effect[];
  swapCondition: ChangeSwapCondition; // { tribes?: string[]; maxCost?: number; colors?: CardColor[] }
}
```

- `getChangeSwapCandidates()` で入れ替え対象スピリットを列挙（ブレイヴ単体・合体中ブレイヴ・魂状態を除外）。
- `useChangeCardAsAction()` / `useChangeCardInFlashContextAsAction()` / `resolveDeferredChangeStack()` でスタック窓対応済み。
- 入れ替え時: チェンジカードをフィールドへ（召喚イベント不発火）→ 対象スピリットのコアをチェンジカードへ引き継ぐ → 対象スピリット→手札（handCount 自動増加、`handIncreasedBy` には加算しない）→ 合体条件を満たすブレイヴは新 host に合体継続、満たさないブレイヴのみ分離。
- バトル中の入れ替え: `BattleEntity.memberInstanceIds` を差し替え、BP/シンボルを再計算。

## 6. ゼロカウンター（Zero Counter）

相手の「コスト踏み倒し召喚」に対し、手札からコスト0で割り込み使用するマジック専用キーワード。

### 発動条件

- 相手が**バースト効果以外**でコスト0召喚したとき
- コスト軽減で結果0になった場合は**対象外**（「0コストを支払った」扱い）
- 効果解決中の踏み倒し召喚には割り込め**ない**

### タイミング

**召喚時効果の前**に割り込む独自タイミング。ゼロカウンターで破壊されたスピリットの召喚時効果は不発。召喚されたカードが「効果を受けない」「使用できない」を持つ場合はそちらが優先。

### 効果パターン

| 色 | 効果 | 手札復帰コスト |
|----|------|--------------|
| 赤/紫/青 | 1体破壊 | 1 |
| 緑/白/黄 | ステップ終了 | 2 |
| 零ノ障壁(6色) | 1体破壊(Ult含) | 1 |

### 主要裁定

- 1トリガーに対し1枚のみ（複数枚同時使用不可。1枚目処理後に条件を満たさなくなる）
- ステップ終了効果で終了した場合、召喚時効果や待機中の効果は解決されない
- 別途フラッシュ効果も持ち通常使用も可能

### 実装状況

**未実装。** `model.ts` に `ZeroCounterData` 型・`zeroCounterData` フィールドいずれも存在しない（2026-04-15 時点）。
実装時に必要な設計案:

```typescript
interface ZeroCounterData {
  effects: Effect[];
  returnCost: number;
  includesUltimate?: boolean;
}
```

- EffectTiming に `"zero_counter"` 追加
- 踏み倒し召喚検出 → 召喚時効果前に割り込みウィンドウ → 効果処理 → 復帰コスト選択
