# Brave And Attack Special Cases

## ブレイヴ

主なソース: [公式ルールマニュアル エターナル版 ブレイヴ](https://www.battlespirits.com/rule/official-rule-manual-eternal/page09.html)

### 召喚

- ブレイヴは手札から召喚できる。
- 召喚時にすぐにスピリットへ合体させることもできるし（直接合体）、スピリット状態としてフィールドに置くこともできる。
- 直接合体の場合、コアを置くこともできる（個数不問、置かなくてもよい）。スピリット召喚としては扱わない。
- 創界神系への合体は[独立コア管理](08d_grandwalker-nexus.md)を適用（ユーザー確認/C）。
- スピリット状態のブレイヴは、自身の Lv1 BP を持ち、独立したスピリットのように扱われる。
- スピリット状態のブレイヴがシンボルを持つかどうかはカード定義による（シンボルを持つブレイヴも存在する）。
- ブレイヴ自身の「召喚時」効果は、通常召喚時・直接合体時の両方で発動する。合体先に関わらずブレイヴのカードに帰属する。

### 合体

- メインステップでフィールド上のブレイヴ（スピリット状態）を合体条件に合うスピリットへ合体できる。
- **合体と召喚の区別**: 「合体する」だけでは召喚にならない。[629905088の原文・Q21599・再現根拠](05a_brave-semantic-events.md#合体と召喚の区別2026-10-13)を参照。
- 「スピリット状態/魂状態のこのブレイヴは、召喚された/スピリット状態になった/召喚・煌臨した
  自分のスピリットに合体できる」型は、通常のメインステップ合体を消す制限ではなく、そのイベント時にも
  合体できる追加タイミング許可として扱う（通常合体はフィールド上のスピリット状態ブレイヴのみ）。
  （BSGE01-C05〜C08 / TR01(A) / TX01〜TX04(A) / BSAZ01-CX01、裁定 2026-08-15、信頼度 C / ユーザー確認）。
- 合体にコストはかからない。
- 合体した結果は 1 体の `合体スピリット` として扱う。
- 合体中のブレイヴ自身は Lv を持たない。実装上もブレイヴ側の `getEffectiveLevel()` は 0 とし、合体スピリットの Lv はホスト側で算出する。
- 合体スピリットには以下が合算される:
  - コスト（ブレイヴのコスト + スピリットのコスト）
  - BP（本体・全ブレイヴの「BP＋」・修正値を合算後に0を下限とする。途中で負値を0にしない。[03c Q164/Q165](03c_effect-text-interpretation.md)）
  - シンボル（ブレイヴ分を合体先へ追加し、本体の色追加も適用。アルティメット・ネクサスも同様。異魔神は左右へ加算、子の重複なし。公式 page09/Q3263、2026-09-27確認/A）
  - 効果（ブレイヴの【合体中】効果がスピリットに追加）
  - 属性（色が追加）
- 合算しない要素: 名前、系統、Lv ごとのコア数、軽減シンボル。
  - 例外: 鍵ブレイヴが合体したまま魂状態になった「1枚の合体スピリットカード」は、召喚時のカード状態としてブレイヴ側の軽減シンボルも引き継ぐ（`external-qa/qaData.js` qa-015）。
- ブレイヴ上のコアは合体先に移動する。
- 合体前のいずれか、または両方が疲労状態なら、合体スピリットは疲労状態。
- 合体中のスピリットが合体条件を満たさなくなった場合（例: 系統変更効果）、ただちに分離する。
- 合体スピリットへさらにブレイヴを合体することはできない（1体1ブレイヴ制限、`maxCombinedBraves` 付きホストは例外。P3-16）。

- **複数合体の枠・失効**: 持ち主が合法な残留対象を選ぶ。指定外の通常1枠、追加枠、Lv/抑止/条件変化、待機、分離コアを区別する。[裁定・反証盤面](../00_meta/source-findings-brave-capacity-2026-10-20.md)（公式A・適用推論C）。

- **合体中ブレイヴの転醒時効果（2026-09-04、信頼度 C / ユーザー確認）**: BSGE01-TR01(B) の正しい見出しは「このスピリット/ブレイヴの転醒/アタック時」で、「このブレイヴの転醒時」と「このスピリットのアタック時」を指す。【合体中】の効果発揮元はホストだが、転醒イベントの主語はブレイヴ自身。ホストの転醒には反応しない。両タイミングの「ターンに1回」は共有する。実装は `Timing.effectSourceEvents:["rebirth"]`（裁定記録: `needs-ruling.jsonl` の BSGE01-TR01(B)）。

- スタック応答後に合体先が離脱した場合は、[04d の合体中効果の解決](04d_leave-choice-timing.md#スタック応答後の合体中効果2026-09-13信頼度-c--ユーザー確認)を参照。

### BSTH03-M05の読み替え（2026-10-19、信頼度 C / ユーザー本文訂正）

- Lv3〜Lv5本文の末尾は「変更する」。前半の「合体でき」は維持し、合体は任意、読み替えは必須の継続適用とする。
- Lv不足・該当効果の抑止・分離時は適用せず、再有効時は選択なしで適用する。合体条件失効時の分離は既存規則に従う。
- ブレイヴ本来の任意性は維持し、【スピリット合体中】の見出しは変更しない。
- [本文訂正と旧照会の履歴](../00_meta/source-findings-bsth03-m05-continuous-rewrite-2026-10-16.md)。任意選択時点・保持期間の旧裁定待ちは解消。

### 状態化に反応する合体（2026-09-08 実装再監査）

- BSGE01-TR01(A) 本文の「召喚された/スピリット状態になった自分のスピリットに合体できる」は、リンクエイドの非召喚の復帰も対象。信頼度 B（external-qa/cardData.js:8464、05_brave-and-attack-special-cases.md の追加合体タイミング裁定）。
- コア配置前の状態変化は共通の差分検出で保持し、配置完了後の誘発群へ合流させる。召喚イベントや契約合体の原因は付けない。
- 同じ本文行に未合体時と合体中の別効果が併記されても、DSL の applicability.combined:false を本文からの合体中条件推定で上書きしない。実操作の回帰は link-aid-spirit-state-combine.test.ts。
- 合体中かつ消滅待機中の BSGE01-C05 は、上記のスピリット状態で発揮する合体効果を誘発しない。待機後の新規発揮は待機・離脱関連のみ（[04 の破壊/消滅待機状態](04_state-based-rules.md)）。後で分離しても、過去の復帰イベントへ遡って参加しない（2026-09-08 ユーザー再確認）。

### 合体条件

- 合体条件はカテゴリ/色/系統/コスト/カード名で指定される（複数指定は AND）。
- カード名指定は `「X」`=部分一致、`カード名：「X」`=完全一致。[全効果共通のカード名参照規約](01_glossary-and-card-types.md)（裁定 2026-06-05）。
- 実装: `BraveCondition.cardNameContains`（部分一致）/ `cardNames`（完全一致）。判定は `legal-actions-availability.ts` の `matchesBraveCondition()`。

### 交換

- 交換は
  - 合体スピリットからブレイヴを外して別のスピリットへ合体し直す
  - 2 体の合体スピリットのブレイヴを入れ替える
  行為。
- 交換後の合体先すべてが合体条件を満たしていないと行えない。
- 交換中、ブレイヴは一度スピリット状態にならない。
- 交換ではコア移動は発生しない。
- 「合体ブレイヴできない」効果を持つスピリットへは交換不可。

### 分離

- 分離は、合体スピリットをスピリットとブレイヴに分け、それぞれを別のスピリット状態として扱う。
- 分離にコストはかからない。
- 通常の分離では、ブレイヴがLv1以上になるようコアを置く。合体条件喪失による強制分離では置かず破棄することもできる（Q382）。
- コアはリザーブまたはフィールドのカード上から移動させる。
- 分離後のブレイヴは分離時点のホストと同じ疲労状態を引き継ぐ。ただし、スピリット状態で「疲労せず」を持つブレイヴは分離後ただちに回復状態になる（下記 §分離時の疲労状態）。

### 合体/交換/分離とスタック窓（裁定 2026-07-08, 信頼度 B）

合体・交換・分離は 02:190 の4カテゴリに該当せず 02:209「基本ステップ処理」に整合。
`brave_combine`/`brave_swap`/`brave_separate` は `not_a_declaration` が正しい。
根拠: 本章の「コスト不要」記述（全ブレイヴ共通の基本ルール操作）＋独自Q&Aミラー qa-005
（スタック非発生例「メインステップの効果ではないコアの移動」と構造的に同型）＋実装
（`legal-actions-apply.ts` 各 executor が窓オープンを呼ばず atomic 実行）。信頼度 B（直接明示裁定
なし、構造的類推）。`swap_bullet_edit`（BSGE01-CX01 のフラッシュタイミング入替）は対象外・前例が無く
一次資料が閉じないため `needs-ruling.jsonl` (`ENGINE-bullet-edit-family-window-classification`) で
ユーザー確認待ち。

実装メモ:

- 分離時、ブレイヴが Lv1 以上になる条件を満たせば、任意の数のコアをリザーブまたはフィールドのカード上から置ける。
- Lv1 コストが 0 のブレイヴはコア補填なしで分離可能。

### 合体スピリット破壊時のブレイヴ

合体スピリットがフィールドを離れるとき、ブレイヴの扱いは2択:

1. **フィールドに残す場合**: ブレイヴが Lv1 以上になるよう任意の数のコアを移動する（Lv1 必要コアが 0 のカードならコア不要で残存可能）。
2. **フィールドに残さない場合**: ブレイヴは合体先と同時に同じ場所（トラッシュ等）へ移動する。

- 「破壊されたとき」効果はスピリット側に帰属し、ブレイヴの「破壊されたとき」ではない。
- ただし合体スピリット自体を対象とした「フィールドを離れたとき」はブレイヴ側にも波及しうる場合がある（個別Q&A参照）。

実装メモ:

- 実装済み (P2-09)。ホスト離場時に `pendingBraveLeaveChoice` を立て、`resolve_brave_leave_choice` で
  `keep`（フィールドに残す・コア補填は separation UI 流用）/ `send_with_host`（一緒に移動）を選択する。
  正源は `state-based-actions.ts` の `checkBraveLeaveChoice` / `resolveBraveLeaveChoice`。
  GUI モーダルは `effect-choice-overlay` を流用、シナリオ `?scenario=brave-leave-choice`。

## 通常アタック

- アタックは 1 体ずつ順に解決する。
- アタック/ブロック宣言の後に疲労する。
- アタック時効果は、アタック宣言で疲労した後に発揮する。
- 通常アタックでは持続しない `アタック時` 効果を解決してからブロック宣言へ進む。
- バトルはアタック宣言後に始まり、バトル解決後に終わる。
- `バトル終了時` はバトル1件ごとの終了、`アタック終了時` はアタックステップ全体の終了を指し、区別する。

## `『アタック時』` の2類型と上位フィルター

`『アタック時』` には**宣言時一点型**と**アタック中スコープ型**があり、混同しない。どちらも発火する効果自体は単発（即時）で、常時効果（BP 修正等の継続修飾）ではない。差は「いつ発火できるか」。

- **宣言時一点型**: アタック宣言で一点だけ発揮する。例「アタック時、〜を1個ボイドに置く」。宣言→疲労後にその場で解決して終わる。
- **アタック中スコープ型**: `『アタック時』` が**発揮枠（＝効果が有効なスコープ）を表す上位フィルター**で、その枠内で内包する `〜したとき` がイベントを観測して発火する。発火点が宣言時ではなく「アタック中に観測したその時」になる。

### 上位フィルターと effectCondition を同層で扱わない

- `『アタック時』`（発揮枠）は「このスピリットが今アタック中か」という**スコープ＝上位レイヤー**。内包する `〜したとき` 誘発や `ConditionClause`（effectCondition）評価より**上**に位置する。
- アタック中スコープ型を「アタック宣言時に1回 ConditionClause を点検する即時効果」として実装すると、発火点が宣言時にズレ、枠内で後から起きるイベント（破壊）を観測できない。窓ゲートと内包トリガーを取り違えないこと。
- 正しい分解＝**内包トリガー（枠内で観測するイベント）＋ 窓ゲート（このスピリットがアタック中）＋ usageLimit**。

### 「破壊したとき」を宣言時一点にできない理由（と実装）

- 宣言時一点の即時は発揮の瞬間に条件を点検する。だがアタック宣言時点ではまだバトル解決前で**何も破壊されていない**ため、`相手のスピリット/アルティメットを破壊したとき` を観測する対象が存在しない。
- 破壊は**アタック中に実際に起きたその時**に観測される。バトルでの討ち取りに限らず、発揮枠が開いている間なら自分の破壊効果起因の破壊も観測対象になり得る（帰属は自分起因のみ＝`battle` / `self_effect`。相手による自壊 `opponent_effect` は除外）。
- 実装例: `BSTH01-X08`（実装済み）。`game_event:destroy`（`triggerFilter`＝スピリット/アルティメット、`cause:["battle","self_effect"]`）で観測し `condition:[in_battle:attacking]` で『アタック時』スコープにゲート。誘発収集はバトル reset 前（in_battle=true）に走るため解決が reset 後でも gate 成立。`cause` は配列で複数の自分起因をまとめて受ける。
- `event:"attack"` ラベル（retrigger 参照用）は timing 種別とは別概念で原文検出で後付け。X08 参照カードが無いため発火正しさ優先で `game_event` にしている。

## 合体先離脱後のアタック/ブロック継続

- アタック/ブロック中の合体スピリット/合体アルティメットが離脱し、ブレイヴをフィールドに残した場合、スピリット状態で当該アタック/ブロックが可能なブレイヴは**強制継続**する。続けるかの選択は行わない。
- スピリット状態のアタック/ブロック不可に該当するブレイヴは、そのバトル参加を継続できない。参加者のいない空バトルは保持し、[バトルの存続と終了](02c_battle-lifetime-and-resolution.md) に従って処理する。ブロック成立済みならブロッカー不在でもライフダメージは発生しない。
- ブレイヴを「残す/同行させる」選択と、残すためのコア配置は従来どおり行う。
- 根拠: ユーザー指定裁定（2026-09-12、信頼度 C / 実装採用）。継続強制は [既存公式本文調査](../00_meta/source-findings-official-battle-brave-burst.md#4b-ブレイヴの追加裏取り) とも整合。旧 P2-10 の任意継続記述を訂正する。
- 実装: removeBattleEntityMembersAndRecompute が攻撃側/防御側共通で残留ブレイヴの参加可否、BP/シンボル、空バトル保持を確定。flushPendingLeaves / 魂状態置換から継続選択を生成しない。シナリオは ?scenario=brave-attack-continuation（role=block / restricted=1 / owner=bob）。

## ブレイヴ分離時の疲労状態（裁定 2026-08-15）

- **「疲労せず」が無いブレイヴ**は、分離後も分離時点のホストだった合体スピリットと同じ疲労状態で残る。ホストが離脱後に魂状態になる/場からいなくなること自体は回復条件ではない。
- **スピリット状態で「疲労せず」を持つブレイヴ**は、分離によりスピリット状態単独になった時点で回復状態になる。
- 既存の個別事例: チェンジの入れ替え（[08b](08b_accel-change-zero-counter.md)）で、合体条件を満たさなくなり分離したブレイヴにも同じ疲労状態決定を適用する。
- 他のブレイヴ分離経路（マジック兼用ブレイヴ含む、[07b](07b_card-observed-mechanics.md)）にも波及する。
