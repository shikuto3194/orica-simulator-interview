# 煌臨・顕現・契約合体・現界のタイミングと条件

親索引: [特殊ギミック](08_advanced-mechanics.md)。2026-11-15のルール・実装監査。
ルール確認後の「すべて修正して公開まで」に基づき、条件の欠落を共通判定で修正する。検証範囲は末尾に記録する。

## 根拠と採用範囲

- **A・一般則に採用**: [公式エターナルBS40 Q6414/Q6415](https://www.battlespirits.com/faq/list.php?format=eternal&prodname=BS40)。BS40-052は相手メインで効果によりアタックステップ指定の煌臨が可能（Q6414）。その効果で煌臨条件を無視できるかには「いいえ、できません。」（Q6415）。タイミングと条件は別に判定する。
- **A・支払いに採用**: [公式エターナルBS41 Q6566](https://www.battlespirits.com/faq/list.php?format=eternal&prodname=BS41)。BS41-045のバーストによる煌臨も、煌臨条件とソウルコア支払いを要求する。効果内であること自体は支払い免除ではない。
- **A・常時許可との区別に採用**: [公式エターナルCB33 Q28621/Q28625/Q28627](https://www.battlespirits.com/faq/list.php?format=eternal&prodname=CB33)。条件無視の常時効果や支払い置換は、煌臨・顕現の指定タイミングを拡張しない。R01のような即時効果内の実行と混同しない。
- **A・顕現に採用**: [公式エターナルBS71 Q28184](https://www.battlespirits.com/faq/list.php?format=eternal&prodname=BS71)は「自分のカウントが条件で指定されたカウント以上のとき」と定める。[公式マニュアル](https://www.battlespirits.com/rule/official-rule-manual-eternal/page12.html)の顕現は、指定タイミング・ソウルコア移動・指定ネクサスの1コスト支払いによる召喚である。
- **A・独自一般則に採用**: 配布元[qaData.js](https://github.com/shikuto3194/orika-react/blob/main/src/qaData.js)をGitHub連携で再取得（blob `a921bfb6baca40d0eb076b0c3d87202129822c02`）。qa-013（139–145行）は「【契約合体】で指定された条件を満たした対象であっても、合体条件を満たしていない場合は【契約合体】できません。」。qa-014は煌臨扱いを否定。qa-046（459–464行）は現界の条件対象の存在を要求し、召喚/煌臨ではないと定める。
- **C・R01への適用に採用**: 今回のユーザー指定「この効果は、煌臨タイミングを無視するが、煌臨条件を無視するものではない。具体的には、『カウントN以上』を無視しない」。公式一般則とも整合する。R02等への条件保持は一般則からの適用であり、R02固有の新しいユーザー回答とは扱わない。

ローカルの独自Q&Aミラーは欠落していた。公式ミラー再取得も接続エラーだったため、公式Webと配布元GitHubの本文を用いた。「Q&Aなし」とは判断していない。スタンダード版は参照していない。

## 判定原則

1. 実行機会（通常宣言か、他効果の解決中か）、タイミング、条件、支払い、置く位置、結果の種類を分ける。
2. 「効果で実行」「置いたものとして」「コストを支払わずに」から、印字条件の無視を推定しない。本文で変更された項目だけを変更する。
3. R01は、手札の「ベジータ」1枚・共有煌臨元の隣・同名ターン1回を守り、タイミング外の契約煌臨とソウルコア支払い置換を行う。煌臨カードのカウント・対象条件は残す。成立した場合だけ2ドローを選べる。
4. R02はトラッシュからの煌臨というゾーン変更を維持する。本文に支払い免除はないが、有効なCX01の常時許可は選択できる（[既存裁定](08a5_as-if-soul-core-permissions.md)）。実支払いの経路ではソウルコアを移す。煌臨不成立でも先行したドロー・破棄を巻き戻さない。
5. 煌臨禁止、合体禁止、顕現の召喚禁止等も、本文による例外がなければ適用する。宣言時の合法性だけで解決時の成立を保証しない。

| ギミック | 通常のタイミング | 維持する条件・支払い | 結果 |
| --- | --- | --- | --- |
| 煌臨・契約煌臨等 | 各カードの指定とフラッシュ等の機会 | カウント、名前・色・系統・コスト等の対象条件、指定ゾーン、ソウルコア。明示された変更だけを適用 | 重ねる。召喚ではない |
| 顕現 | 各カードの指定。収録X03は自分メイン | カウント、指定ネクサス、ソウルコアとそのネクサスの1コスト、維持コア | 召喚 |
| 契約合体 | 各カードの指定 | 契約合体条件と通常の合体条件の両方、手札、ソウルコア。常時許可は支払いだけを置換 | 召喚を経ず合体。煌臨ではない |
| 現界 | 収録2枚はお互いのアタックステップのフラッシュ | 指定創界神の存在、個別の現界条件、手札扱い、ソウルコア、維持コア | 出す（put）。召喚・煌臨ではない |

## 現行実装の確認

`ALL_CARDS`を現在のソースから列挙した。通常/契約/F契約の`adventData`34枚、多重煌臨1枚、常時煌臨許可3枚、効果内煌臨2枚（R01/R02）、顕現1枚、契約合体9枚と常時許可5枚、現界2枚を対象にした。過去の「36枚」を現行件数として流用しない。

| 経路 | 確認結果・修正箇所 |
| --- | --- |
| 通常・擬制支払いの煌臨 | `legal-actions-availability.ts`で通常/代替とも`declareCondition`とタイミングを評価。`advent-system.ts`の`checkAdventConditions()`で解決時もカウント等を再評価し、同じ関数の対象条件判定へ進む。`host-dual-advent.ts`も条件を保持する |
| 効果内煌臨 | 旧実装は`declareCondition`を落とし、`adventCondition`をカテゴリだけに縮めていた。`effect-advent.ts`で印字条件を保持し、`checkAdventConditions()`を通常登録・効果途中の選択候補・支払い選択・実行直前で共有する。タイミングだけを迂回し、R01の明示免除とR02の常時許可選択を維持する |
| 顕現 | BSTH02.7-X03のC2を`ManifestData.condition`に保持。宣言は`legal-actions-availability.ts`、実行は`manifest-system.ts`の`evaluateCondition()`と対象判定を通る。通常タイミング外で顕現させる別効果の収録はない。今回の条件削除型の不具合は確認しなかった |
| 契約合体 | 旧実装は`contractCombineData.braveCondition`だけを見ていた。`getContractCombineCandidateTargets()`で通常の`braveCondition`も共通の実効値判定へ渡す。TX01(A)～TX04(A)の名前だけ一致する不適格対象を除外し、deferred解決も同じ関数で再確認する。常時許可は支払いだけを置換する |
| 現界 | BSTH10-X05とBSTH11-X02は`Effect.condition`に創界神の条件、X05は未契約条件も保持。`legal-actions-availability.ts`で宣言前、`effect-interpreter.ts`で解決開始時に共通評価。`core_move`→`conditional_cost`→`put`で支払いと場入りを接続。今回の条件削除型の不具合は確認しなかった |

契約合体の再現は実カード定義を基礎に、対象の名前を維持して系統を`GE・1G`または`神喰`へ変えた合成負例。修正前は4枚すべてで通常合体条件はfalseなのに候補へ出た。無変更の印字対象ではtrue/候補あり。修正回帰では条件を満たす場合の最終合体、失う場合の支払い・旧ブレイヴ破棄・使用記録の非実行まで確認する。実戦でその系統変更を作るカードの組み合わせを再現したとは扱わない。
