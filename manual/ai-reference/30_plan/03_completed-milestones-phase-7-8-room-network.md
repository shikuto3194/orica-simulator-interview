# Phase 7–8 完了履歴: ルーム通信の確定と復旧（2026-10-27）

親: [完了履歴索引](03_completed-milestones.md)

- stateとreplayを同じDBトランザクションで確定し、ID・actor・入力の照合で再送を一回の操作へまとめる。結果不明の要求は永続履歴の照合または未適用IDの取消を確定してから入力を再開する。
- client/DBの期限、認証更新と取得の重複抑制、待機時間を守る再送、SSE・前景復帰での再同期、proxy配下のユーザー別制限を追加した。観戦通信はログイン中も匿名とする。
- APIはDB準備確認後に配備し、切替時はSSE再接続を通知して処理中要求を待つ。移行は旧APIのRPC不存在cacheも考慮する。
- 原子的保存のPostgres回帰、応答喪失・認証停止・再読込の回帰、実JWTのGUI/REST往復、API再起動後の一回適用、10room/20userの再接続を検証対象とした。
- 調査、仕様、実測の範囲と証跡入口は[通信調査](../20_design/18_room-network.md)と[復旧契約](../20_design/19_room-network-protocol.md)。段階4のWebSocket/メモリownerは、永続DB以外が支配的になる測定条件を満たすまで採用しない。

- main統合査読で、未確定の本人通知が既読番号を進め、拒否後に同番号の正常通知を消す反例を採用。ルーム通知はviewer別にsanitizeした権威状態だけを表示し、3.5秒の遅延拒否後に正常操作を通知するGUI回帰を追加。
