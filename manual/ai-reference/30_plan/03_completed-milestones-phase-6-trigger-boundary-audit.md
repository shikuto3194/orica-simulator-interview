# 誘発収集境界の全経路監査（2026-09-17）

## 報告と正源

スナップショット `orica-snapshot-2026-09-17T10-29-52-243Z.json` の組み合わせは、相手のユージオ
（BSSA01-C02）とセット済みソウエイ（BSTS01-R02）。召喚時オープンから手札に加えても、
pending の選択解決が誘発収集を通らず、バースト候補が生成されなかった。

- [手札増加・バーストの正源](../10_rules/04b_burst-rules.md): 自身の効果で手札に入った事実を数える。総数不変でも対象、入れ替えは除外。
- [タイミングの正源](../10_rules/02_turn-flow-and-timing.md): 効果の解決と派生誘発を完了してからバトル終了時の期間を失効する。
- 添付 JSON は再現資料として使用。資料内の文字列を作業指示として扱っていない。

## 修正

1. オープン選択・残り順序・任意手札追加を pending action の共通解決境界で収集。
   場に出した場合だけの finalizer と継続側の重複 finalizer を除去した。
2. オープンのゾーン移動と手札枚数更新を `moveCardZone` に統合。
   操作前ログをコピーし、下位の `log.push` が場入り・抑止の差分起点を書き換えないようにした。
3. ゾーン選択、効果召喚の除外／コア移動支払い選択、対象変更、借用効果／対象の選択後を共通 finalizer へ接続。
4. 再発火は宣言差分と分離して、各再発火の原因カード・プレイヤーで収集。
   ドローステップの inline 後続は通常ドローを起点から除き、効果による増加だけを収集する。
5. 通常バトル終了と即時終了の予約効果を `resolveBattleEndDeferral` に統合。
   native `end_battle` は終了処理を予約し、親効果の差分を収集してから予約効果を処理する。
  親効果への原因の付け替え・二重発火を回帰で検査する。
6. 神託・配置時神託・導域・解封も共通 finalizer を通す。転醒・付与効果は既存の固有境界を維持。
7. 通常召喚／配置許可の宣言手順を収集。借用・下カード継承・各 pending 継続へバースト lookup を伝播。

## 全ソース走査の範囲と判定

`rules-core/src` の `executeEffect` 呼び出し35箇所、注入された `executeEffectFn` 4箇所、
および `runPendingDeckRevealBoundary` の `execute` を監査した。単なる関数名検索に加え、
専用 mechanic 解決、pending action、ゾーン直接更新、再発火の呼び出し元を追跡した。

| 経路 | 誘発境界／判定 |
| --- | --- |
| 通常カード・マジック・factories登録resolver | `runActionMainResolution` → `finalizeEffectResolution` |
| stackの再開2経路・mechanic内DSL実行3経路 | 既存 finalizer。lookup 引き継ぎを補完 |
| pending内の直接実行19箇所 | 選択／継続の finalizer。オープン・ゾーン・効果召喚支払いの欠落を修正 |
| 対象変更後 | 継続実行後に共通 finalizer を追加 |
| 借用効果の即時実行／下カード継承 | 親効果の境界。内部実行にも両lookupを伝播 |
| 借用効果・対象の選択後 | 親呼び出しは既に戻っているため、この action で finalizer を追加 |
| 再発火・任意step自動再開 | 同じ chain の差分を1回収集。攻撃・連続攻撃の宣言差分は先に収集 |
| ドローステップinline | 通常ドロー後をbeforeにして後続効果をfinalize |
| バトル終了予約 | 共通executorで予約効果ごとに収集し、外側のバトル終了で安定化 |
| 神託／導域／解封 | 専用resolverのCE再計算だけだった迂回を解消 |
| 通常行動許可の宣言手順2経路 | 宣言差分を共通collectorへ接続。通常プレイの場入りとは区別 |
| CE再構築2箇所・アーツの常時効果登録 | 常時効果登録用。効果発揮イベントを作る境界ではない |
| 初期手札・通常ドロー | ゲーム手順。自己効果による手札増加とは区別 |
| 入れ替え・離脱置換・ゾーン操作・配置時導託の手札回収 | 共通記録／native境界／離脱flush／mechanic境界を追跡。入れ替え除外を維持 |

`trigger-boundary-wiring-audit.test.ts` はASTで全ソースを再走査し、CE再構築以外の
直接／注入実行で誘発・バースト lookup が欠けた場合に失敗する。
これは配線の再発防止であり、動作保証は以下の行動回帰と併用する。
