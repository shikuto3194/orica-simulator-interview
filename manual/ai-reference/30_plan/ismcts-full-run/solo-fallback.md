# 一人バトルのAIフォールバック

2026-10-06本人指示（信頼度A）。現行モデルが失敗し旧モデルも使えない場合は、
学習checkpointに依存しない簡易AIで継続する。I4/I5/I6c/I7の共通受入仕様。

## 復帰順と独立性

`現行champion → 互換性確認済みの旧正常モデル → 観測限定の簡易AI` の順に選ぶ。
旧モデルがない・破損・版不一致ならその段階を飛ばす。簡易AIは最初の配備から必須とする。
簡易AIは既存heuristicとPlayerDecision共通adapterを再利用し、NN・checkpoint・GPU・
重い探索serviceへの接続を必要としないCPU経路にする。同じ故障serviceへ再送するだけでは成立しない。
一人バトルのゲームを保持する側に配置し、探索service全停止でも実行できるようにする。

障害対象はmodel load/非有限出力/timeout/crash/service切断/不正応答/版不整合。
queue混雑・予算不足も簡易AIへ退避可能にし、原因を区別して記録する。
認証拒否を別経路で迂回しない。stale応答は棄却し、最新の認証済みactor/revisionから再要求する。
共通engine・状態・合法入力contractが壊れている場合は復帰不能として保存・再試行可能に表示し、
勝手なpass・支払い省略・候補削除で対戦を進めない。

## 1手の適用と利用者表示

- 確定済みstateを戻さず、未適用のdecision境界で切替える。支払い/対象/配分等の全入力を扱う。
- 全段階で観測境界・合法性・actor/revision/hash・requestIdの二重適用防止を共用する。
  旧応答の遅着を破棄し、fallback側と両方適用しない。
- 再試行回数と全段階合計deadlineをrequest予算内に制限する。残時間がない場合は
  安全な未適用状態で新要求へ進み、段階ごとに時間枠をリセットして永久待機しない。
- 同一障害で現行/旧版を無限に往復せず、故障版を隔離してその対戦は簡易AIに固定する。
  復旧probe成功後の新規対戦でのみ上位経路へ戻す。
- GUIは「簡易AIで対戦を続けています」と表示する。内部hash・token・実装詳細を表示しない。
- 使用経路・理由・遷移時刻・各版・入力/応答hashを記録し、簡易AIの勝敗をchampionの
  強さ評価へ混ぜない。fallback自体の成功とモデル正常性を別々に集計する。

## 必須反証 S2

GUI+RESTで次を確認し、実ゲームの最終盤面・自然終局とfallback traceを保存する。

1. 現行だけ失敗し旧正常モデルへ復帰。
2. 現行・旧版の両方が破損/timeout/非互換となり、簡易AIへ到達。
3. 探索service全停止・checkpoint全欠落・GPU不使用でも簡易AIでpreGameから終局。
4. 支払い・対象・配分の途中、遅着応答・二重送信・切断再接続で二重適用0。
5. 簡易AIでも秘密情報を参照せず、全PlayerDecisionを合法な完全payloadへ変換。
6. 合法入力contract自体の破損は適用せず停止理由を保持。偽の正常終局にしない。

通常のrelease評価ではfallback率5%以下など[evidence](evidence.md)の基準を維持する。
故障注入試験を通常性能評価と混ぜず、両者を別receiptに結合する。
