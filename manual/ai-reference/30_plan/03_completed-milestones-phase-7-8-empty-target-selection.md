# 対象不在の選択待ちと同類監査（2026-09-27）

## 再現と修正

- ユーザー提供 `orica-snapshot-2026-09-27T07-30-08-667Z.json`。BSLH01-X08のアタック時効果で、対象グループ2つとも候補・必要数・上限が0。共通HUDが可変選択時だけ確定ボタンを出すため、固定0件はカードのタップも確定もできなかった。
- `BattleScreen` の共通対象選択で、固定0件にも「対象を取らずに確定」を表示する。必要数・上限・グループ充足検査は維持する。新規ゲームだけでなく保存済みの選択待ちも操作できる。
- 同類監査で、battle-immediateの候補が選択待ち中に離脱すると、全体の必要数だけが緩和され、グループ内の必要数が残る不整合も再現した。`revalidatePendingEffectTargets` に生存候補・必要数・上限の再計算を集約し、legal action列挙と確定処理で共有する。離脱候補を再送する操作も拒否する。
- ルール解釈は変更しない。[空撃ちの既存仕様](../10_rules/03b_resolution-and-interrupts.md#空撃ち)と、既存のbattle-immediate候補再検証に合わせた入出力整合の修正。

## 同類監査の範囲

| 経路 | 確認内容 |
| --- | --- |
| 共通対象HUD | `pendingEffectTargetSelection`、任意ステップ、借用効果、宣言時対象選択が使う共通の確定条件を修正。単一・グループ・0〜N体・固定0件を確認 |
| エンジンの選択待ち | 候補0件、候補全離脱、グループの一部だけ離脱、同一候補の複数回選択、フィールド外候補の既存回帰を確認 |
| 強制・任意の境界 | 候補がある固定数選択を0件にできないこと、空グループと生存グループが混在しても生存側の必要数を守ることを確認。ことで構文・任意ステップ・反復選択の既存回帰も実行 |
| `usePendingCardSelection` | 最小・最大の両端を含む判定で固定0件も確定できる。順序つき支払いは解決可能なactionを要求 |
| `DeckRevealModal` | 必須数は候補数で制限され、0件確定またはスキップがある |
| `ZoneSelectionModal` / インライン手札選択 | 任意選択は別のスキップ操作を持ち、強制選択は実効必要数で判定 |
| 個数選択HUD / モーダル | 最小・最大でクランプし、0〜0でも確定操作が残る。対象リダイレクト・合体選択は専用の解決actionを使う |

候補の再検証は既存仕様どおりbattle-immediateに限定する。他の効果種別にフィールド限定の候補判定を流用しない。カードごとの特例やカード本文・DSLの変更はない。
