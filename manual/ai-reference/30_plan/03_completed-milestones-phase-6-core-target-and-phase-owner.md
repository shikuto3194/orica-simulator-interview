# フィールドのコア選択・開始時効果のプレイヤー判定（2026-09-26）

## 報告と原因

- BSTH01-C22「土符『レイジィトリリトン』」の相手フィールドから2コアを除去する選択で、創界神系ネクサスも黄色枠になった。
  添付スナップショット `orica-snapshot-2026-09-26T13-12-44-404Z.json` を確認した。
  BattleScreenの支払い後の先行選択は、定義lookupなしで候補を組み立て、エンジン側の特殊ネクサス・耐性判定と分岐していた。
- BSTH01-M01「パチュリー・ノーレッジ」の自分アタックステップ開始時効果が、相手の開始時に発揮した。
  添付スナップショット `orica-snapshot-2026-09-26T13-28-10-796Z.json` では、同じ側のBSTH03-R01「鈴仙・優曇華院・イナバ」の相手開始時効果と混在していた。
  鈴仙側へ分けた誘発キューの再走査時、`whose`省略が効果コントローラをイベント主体として扱うため、パチュリーも候補になった。

## 修正と同類監査

- GUIの先行コア選択を削除。支払い・スタック応答後、エンジンが生成するpending候補を共通HUDで選ぶ。
  コア配分を直接指定する経路も、通常コア・ソウルコアともに `getFieldCoreSourceTakeableCount` へ接続した。
  選択で中断したマジックが解決後に使用中へ残る経路も、既存のマジック解決後処理へ接続した。
  残りスタックはコア選択の完了まで退避し、完了したマジックの後処理を妨げずに再開する。
- phase効果登録時に省略された `whose` を `self` として明示する。キューのコントローラが変わっても、元イベントの `relatedPlayerId` で自分／相手を比較する。
  明示された `opponent` / `either` は維持し、個別カードの書き換えは行わない。
- 全594カード定義と裏面・入れ子を走査し、`core_move` の `from:field` 38箇所、`from:field_card` 24箇所（計62箇所）を監査。
  GUIの旧分岐に該当するマジックはBSTH01-C22、BSTH04-C12、BSAZ02-M04の3枚。
  相手スピリット／アルティメット限定・最低コア数・先行ステップ成立後の任意ライフ回復を、個別GUI推測でなく既存DSL実行へ委ねる。
  特殊ネクサスの明示指定、フィールドとリザーブの横断、自己カードへの集積、ソウルコア除外の経路も共通判定への到達を確認。
- phase効果55箇所を監査し、`whose`省略はBSTH01-M01のみ。全カード・裏面の登録結果を回帰テストで検査する。
