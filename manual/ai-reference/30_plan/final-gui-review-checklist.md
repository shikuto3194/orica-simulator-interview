# 完了後 GUI レビューチェックリスト（人間用）

機械検証・公開後に行う、人間によるGUI受入の手引き。実施前は「機械検証済み・GUI受入待ち」と区別する。
機械ゲート（型 / 全テスト / 忠実度 / fuzz / e2e）は通過済みの前提で、
**機械が判定できない「遊んで気持ちよいか・表示が正しいか」**に集中する。

## 準備

1. dev サーバー起動: `npx vite --config apps/playground-web/vite.config.ts --port 4173`
2. 残量ゼロの確認（任意）: `pnpm cards:coverage` / `pnpm cards:fidelity`

## レビュー観点（1 セッション 30 分目安）

### A. 通しプレイ（最重要）

- 通常対戦を 1〜2 局通しでプレイ（alice GUI / bob は REST か 2 画面）
- 観点: 操作に詰まる場面がないか / pending・スタック窓の出方が自然か /
  ログと盤面の食い違いがないか

### B. 新規実装ギミックの見た目

フルラン中に基盤実装されたギミックを 1 つずつ確認
（完了通知に当該ランで実装されたギミック一覧が載る）:

- `?scenario=` でシチュエーション起動（一覧: `25_gui/10_scenario-test-reference.md`）
- 例: 星霊衣の下カード表示 / クォーツのセット位置 / 煌臨元スタック / 転醒 B 面 等
- 観点: カードの重なり・バッジ・コア表示が崩れないか（横画面はネクサス両プレイヤー
  配置の 2 行/プレイヤー想定）

### C. 気になった弾のサンプリング

- デッキ構築画面で弾フィルタ → 気になるカードでデッキを組み実戦投入
- 効果テキストと実挙動の食い違いを感じたら、その場で記録（下記）

## 問題を見つけたら

- 1 件 = 1 行で記録して対話セッションに渡す（再現手順 / 期待 / 実際）。
  修正は通常タスクとして回す（フルラン再起動は不要。修正→緑→GUI 再確認）。
- ルール解釈の食い違いは裁定として `10_rules/` に反映させる（裁定が正、実装が従）。
