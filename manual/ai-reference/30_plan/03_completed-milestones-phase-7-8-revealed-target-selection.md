# オープン対象・解決前公開表示の全カード監査（2026-10-03）

対象: キーア BSLH01-X01【導技:2】の「ゾーン候補」表示、および解決するまで公開内容・選択元を確認できない観測。同類を共通効果処理・GUI・viewer配送から監査した。

## 原文と因果の実証

`packages/card-data/raw/cardData.js` と `raw/by-pack/BSLH01.js` の原文は一致する。

> 【導技:2】Lv1-Lv2 フラッシュ〔ターンに1回、このネクサスのコア-2する〕自分のデッキを上から2枚オープンし、その中のクォーツ効果を持つカード1枚をコストを支払わずに魂状態の対象にセットする。残ったカードはデッキの下に戻す。

対応は `BSLH01.ts` の `grandwalkerData.divineSkills[0].effects[0]`、`textRef: [6, 7]`。`deck_reveal(2)` の `beforePickSteps` で `on_step` の `quartz_set` が自分の `revealed` / `hasQuartzData` を1枚選び、魂状態にセットする。残札は `bottom`。

基準HEAD `8243f362e` の実カードシナリオとGUIで次を分離して再現した。

1. `deck-reveal-boundary` が対象待ちへ入る間は `pendingDeckReveal` がなく、`resume_deck_reveal` に継続を持つ。このため既存モーダルではなく汎用 `ZoneBrowseModal` に流れ、候補外のオープンカードが表示されない。
2. 固定枚数の対象はタップで即送信され、確定前の選択確認ができない。候補1枚の場合はengineでも入力待ちを省略する。
3. クォーツ配置待ちは専用HUDを早期returnし、公開カード部品を描画しない。選択元も見えなくなる。
4. 別問題として、継続override内の `resume_deck_reveal.pending.priorStateSnapshot` が配送stateへ残る。liveの手札を伏せても内部スナップショットから手札・デッキを取得できることを再現した。
5. 原文逆引きで BSRK01-M01 の手札借用を追加検出。選んだ借用元が手札に残る配置待ち中、公開履歴がまだなく相手が内容を確認できなかった。
6. 相手に配送される配置pendingは秘匿されるため、本人のdraftから確定済み対象を表示できない。さらに公開記録の発揮元が通常効果indexだけを持ち、導技を同indexの常時効果と誤認してログを抑止していた。実GUI/RESTで宣言後・配置前の相手表示を確認した。
7. 全件回帰で、対象候補が指定枚数より少ない場合にpendingは候補数へ丸める一方、注入検証は原指定枚数を要求していた。橙の候補1枚とAI配置回帰で再現し、共通枚数判定へ統一した。

## 共通修正

- 公開ゾーンだけの候補は既存DeckReveal表示を再利用。候補外を含む公開内容、選択中、確定ボタンを表示する。候補1枚でも公開中の対象は入力待ちを保ち、候補0枚は従来の不発・残札処理に進む。
- 混在ゾーンは汎用候補を保ち、公開閲覧を併用。公開候補が含まれる場合は固定枚数でも明示確定する。配置HUD・choice・相手待機でも公開内容を確認できる。
- 同じpendingの盤面確認ではdraftを保持し、キャンセル・次のpendingで解除。別ゾーンへ移ったカードを履歴から現在の公開カードとして復元しない。
- viewer用継続overrideを再帰サニタイズし、内部ロールバックstateを除去。元stateの継続・キャンセル原本は変更しない。
- 非マジック使用扱いの手札借用は、抑止判定・借用元確定後に選択元だけ公開履歴へ追加する。
- 公開効果記録に既存の定義pathを伝え、効果本文・常時効果判定・pending照合を既存の共通参照関数で行う。indexを持つ公開記録の生成元2箇所を監査した。path省略は従来の通常効果、nullは定義外効果として扱う。
- 相手の確定印は、現に公開中のカードについて最新オープン後の公開対象宣言だけから得る。カード内容はviewer用live状態を参照し、古い履歴・非公開化後・epoch欠落から復元しない。
- 明示対象入力と注入検証で同じ枚数上限・下限を使い、候補不足でも実際に選べる枚数を受理する。重複・候補外・合計条件の検証は維持する。
