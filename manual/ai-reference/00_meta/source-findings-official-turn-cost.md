## 今回追加で補えた内容

### 1. ターン進行の最低限仕様

- `ルールQ&A` の検索スニペットから以下を補強した。
  - スタートステップでデッキ 0 枚なら敗北
  - コアステップでボイドからコア 1 個をリザーブへ
  - ドローステップに手札上限なし
  - ドロー失敗では即敗北せず、次の自分のスタートステップで敗北判定
  - リフレッシュステップで疲労回復 + トラッシュのコア全回収
  - エンドステップで終了時効果を先に解決し、その後に一時効果が失効
- `公式ルールマニュアル page06` の検索スニペットからも以下を補強した。
  - メインステップに `flash` タイミングの効果/使用が存在する
  - それは「ターンプレイヤーがメインステップに行えること」として整理されており、通常は相手に共有された `flash` 窓ではない
- これは元レポートで「未指定」だった部分のうち、かなり重要な穴埋めになった。

### 2. 軽減とコスト支払い

- `ルールQ&A` の検索スニペットから以下を補強した。
  - 軽減はフィールド上の同色シンボル数で決まる
  - ダブルシンボルは 2 軽減
  - 多色として扱うシンボル 1 個は同時に複数色へは使えない
  - 軽減できる場合は必ず軽減する
  - 支払いの結果シンボル元が消えても、コスト確定後なので軽減計算は有効
  - 絶対に支払えないと判明した場合はカードを戻して状態巻き戻し
- `まずはこれだけ覚えよう` の本文から以下を補強した。
  - スピリット召喚では、コスト支払い自体はトラッシュ移動として処理する
  - その後で、召喚したスピリットには別途 `Lv1以上になるよう` リザーブやフィールド上からコアを置く
  - したがって、`召喚コストの支払い` と `召喚後の初期コア配置` は別処理として設計すべき
- `コストとコア` の本文から以下も補強した。
  - コスト支払いに使えるのは `リザーブ` と `フィールドのカード上` のコアだけ
  - スピリット/アルティメットは、支払い後に最低Lvを満たすよう別途コアを置かなければならない
  - ネクサス配置時も同様にコアを置けるが、置かない場合でも Lv1 として扱う
  - 創界神グランウォーカー/創界石グランストーンネクサスには、配置時にコアを置けない
  - したがって、通常の `summon` と `place_nexus` では `直後コア配置入力` を持ち、特殊ネクサスだけ別例外で扱う設計が自然
- `創界神` / `創界石` の公式デッキ掲載からも以下を補強した。
  - `BS58-X09` / `BS59-X09` / `BS61-X09` は、実在する創界神グランウォーカーネクサスの cardNo 例として扱える
  - `BS58-071(A)` / `BS59-071(A)` は、実在する創界石グランストーンネクサスの cardNo 例として扱える
  - したがって、少なくともこれらの実在 cardNo は shared enter-field placement registry で `forbidden` 扱いにしてよい

### 2b. 2026-03-23 再調査での追加補強

- `カードのコスト及びその支払いについて` の本文 (信頼度 A に昇格) から以下を新規確認した。
  - **余分コストの巻き戻しルール**: 余分コスト (転召など) 適用後に最低Lvコアが置けず召喚不可になった場合、メインステップや神速ならば宣言前に戻す。
  - **マジックのバースト発動手順**: 発動宣言 → 対象選択 → 効果発揮＆コスト支払い → メイン/フラッシュ効果 → トラッシュへ。通常使用とはコスト支払いの位置が異なる。
  - **コスト変更効果の複数競合**: ターンプレイヤーが解決順序を指定する。複数の固定値効果がある場合、最後に発揮した効果が有効になる。
  - **マジック効果が無効化された場合**: 「マジックを使用した」条件は満たすが、「効果発揮後」条件は満たさない。
- `公式ルールマニュアル エターナル版 page05/page06` の本文から以下を新規確認した。
  - **1ターン目の扱い**: コアステップとアタックステップは「存在しない」（スキップではなく存在しない、という表現）。
  - **メインステップの行動**: 8種 (召喚 / 合体・分離・交換 / 配置 / マジック使用 / メイン効果使用 / コア移動 / バーストセット / ミラージュセット) が公式に列挙されている。
  - **バーストセット**: ターンに1回のみ。ミラージュセットも同様にターンに1回のみ。
- `ルールQ&A` の本文 (信頼度 A に昇格) から以下を新規確認した。
  - **Q90**: 「コアの支払いは、コストの確定と同時なので軽減シンボルとして数えます。その後、コストが確定された後に、コアが0になったスピリットは破壊されます」。ここで「破壊」の語が使われているが、消滅との用語使い分けについては open-questions 参照。
  - **Q91**: 軽減せずにコストを支払うことはできない（軽減は強制）。
  - **Q93**: シンボル1つで2色の軽減は同時に行えない。

### 2c. 2026-09-22 余分コストの計算と支払い操作を区別

- 公式エターナル [BS02 Q1783 / Q1813](https://www.battlespirits.com/faq/list.php?prodname=BS02&format=eternal) を再確認（信頼度 A、計算に使用）。ミラーは `external-qa-official/BS02.md:358-361,509-512`。`harvest-official-faq.mjs --freeword 余分` でも110件取得した。
- Q1783: 「まず軽減シンボルによるコスト軽減を計算してコスト0になり、その後1コスト余分に支払うことになるので、1コスト支払うことになります。」軽減計算後に余分コストが必要となる例を示す。Q1813: 無償使用のミカファールと螺旋の塔の組合せでも「はい、1コスト支払わなければいけません。」
- 旧 `03a` の「提示 → 軽減 → 余分コスト → 支払い」という4段階は、[Wikiの解説](https://www.batspi.com/index.php?カードのコスト及びその支払いについて=) を整理したもの。公式Q&Aの逐語規定として引用しない。今回の公式本文だけで「通常コストの実コア移動 → 余分コストの実コア移動」という二段階の先後までは確定できない。
- 実装照合: `core/cost-system.ts` の `calculateReduction()` は `reducedCost + additionalCost` を `finalCost` にし、`mechanics/magic-system.ts` の `applyMagicPayments()` は共通 `applyCardCostPayments()` で支払う（いずれも `packages/rules-core/src/` 配下）。`cost-override-magic.test.ts` に無償使用時も正の余分コストを払う既存回帰がある。
- ユーザーの「既に合算ならそれでいい」により、合算した表示・支払い操作を維持する（信頼度 C、2026-09-22、本プロジェクトの操作方針として使用）。支払いを二段階にする変更は行わない。公式での実移動順の新しい確定裁定としては扱わない。
