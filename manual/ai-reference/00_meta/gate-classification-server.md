# server 15モジュールの絞り込み実測（P2-16）

`apps/playground-web/server/` の公開ゲート絞り込みの根拠。分類の仕組みと他群は [gate-classification-queue.md](./gate-classification-queue.md)、残作業は [P2-16](../../../issues/P2-16_gate-classification-narrowing.md)。

- `apps/playground-web/server/` の15モジュール（確度B、2026-11-02）: 内容破壊と削除の2条件で、全件28ゲートから format / lint / types / docs / vitest / secrets の6本を除いた22本と `card-tests` の計23本を、基準と比べた（基準は全て成功）。除いた6本のうち types / vitest / secrets は残し、format / lint は変更ファイルへの `changed-style` に置き換わる（旧全件の repo 全体の prettier・eslint は、server 変更では走らなくなる）。`docs` だけは下記のとおり別に測った。
  - 結果: 変わったのは `ssot` だけ（`game-api.ts` の `passthroughKeys` を `check-ssot.mjs` が読むため。破壊は exit=1、削除は ENOENT 由来の exit=1）。handoff / ismcts-program / ismcts-runtime / harness / fidelity / auto-merge-integration など残り22本は終了コードも出力末尾も同じ（`auto-merge-integration` ほかの差は実行ごとの乱数 ID のみ）。`ssot` は6本目の検査で落ちるので後続の検査は走っていないが、後続も server は読まない（`check-ssot.mjs` の `gameApiRel` が唯一）。
  - `docs`（別測定）: 破壊は exit=0、削除は exit=1（active な設計文書が `game-api.ts` と `api-limits.ts` へリンクしており、`broken link` で落ちる）。そのため全15本に `docs` を残した。
  - merge fuzz: 15ファイルを壊しても削除しても `selfplay-fuzz.test.ts` の要約は基準と同一（`games=100 ... stuck=0 error=0`、直接100局、本番の `pnpm fuzz` とは別）。fuzz の入口（`selfplay-fuzz.test.ts`、`fuzz-runner.mjs`、`run-fuzz.mjs`）の静的 import 閉包にも server は無い。
  - GUI 側: `vite.config.ts` が `image-assets` / `public-build` / `release-version` を静的に、`game-api` / `local-game-api`（と import 先）を dev サーバー起動時に動的に読む（静的 build / preview では読まない）。この12モジュールは CI の full 側と同じ `scenario` / `local-game-ui` / `build` / `public-build` を残した。これらは import の静的読解による選択で、変異実験はしていない（確度B）。
    旧全件の merge には無く、merge では新たに走る（追加コストは `scenario` / `build` / `public-build` の履歴中央値が無く未計測。`local-game-ui` は約21秒）。GUI 4ゲートは CI でも残し、他の22本は実測で idle（確度B）。`http-runtime` / `http-server` / `main` は vite・e2e に届かないので `types` / `vitest` / `secrets` / `docs` のみ。
  - 規則: `semantic-scope.mjs` の `pathOverride`、パスの一覧は `static-inputs.mjs`（完全一致。`server/` に後から足したファイルは `fullScopes` の `playground-server` に残り全件）。`ssot` は `game-api.ts` にだけ足す。`requiresMergeFuzz` もこの15本を除外する。
  - 反証テスト: `test-path-classification.mjs`（群別厳密一致、近傍・新規ファイルは全件、`selectGates` の merge / finish / push / ci が 8 ゲート＋`changed-style`）。読み手のガードは2つ。(1) `scripts/` と `deploy/` で `playground-web/server` を名指しするファイル（ハーネス自身の6本を除く4本）の固定。(2) `vite.config.ts`、`load-server-env.ts`、`src/`、`shared/`、`e2e/`、Playwright 設定を起点とする相対 import の閉包（型 import も含み過大側）が standalone の3本（`http-runtime` / `http-server` / `main`）に届かないこと（閉包が vite 系12本には届くことも検査して、走査自体の健全性を担保）。`.github/` は名指し検索。名指し検索なので、パスを別の場所で組み立てる読み手は検出できない（確度B）。
    規則とガードを壊す複数の変異（件数は参考で、スクリプトは保持していない。`ssot` / `public-build` / `vitest` / `docs` の欠落、fuzz 除外の削除、一覧への追加と欠落、standalone への過剰ゲート、ディレクトリ全体の規則、game-api・room-list・RoomLobby・e2e・vite.config からの standalone への import、workflow・新規スクリプトからの名指し）をすべて検出した。変異スクリプトはスクラッチ（リポジトリ外）。
  - 履歴中央値（`logs/harness/timing`、確度B）で merge から外れる: handoff 約745 / ismcts-program 約294 / ismcts-runtime 約250 / harness 約234 / fidelity 約136 / auto-merge-integration 約71 秒ほか。`test-harness.mjs` の全件アサートは `selectGates` を override なしで呼ぶので変わらない（本番の経路は `test-path-classification.mjs` が固定）。
  - 狭めなかった範囲: `vitest` 全件の群別絞り込み（`focused-vitest` への置換）は未実施。server を直接 import するテストは約26〜32本（数え方で幅があり、推移的な到達は別）。それだけに絞れるかは別の実験が要る。
