### 2026-09-13: 宣言時効果の解決中のOC/Lv条件達成

公式エターナル版を再確認。Q5537（[BS33](https://www.battlespirits.com/faq/list.php?format=eternal&prodname=BS33)）は、コア増加から新たに有効になるLv2アタック時効果とビランバの反応を同時発揮とする。Q9681（[BS60](https://www.battlespirits.com/faq/list.php?format=eternal&prodname=BS60)）は、煌臨時効果によるカウント増加後にOC効果を発揮できるとする（いずれもA、実装根拠として使用）。

ユーザーは「アタック時解決の時間軸と同じ時間位置」であるため、カウント/Lv条件を満たす原因効果からの派生誘発となり、ブロック時も同様と確認（C）。正源と引用位置は [02c](../10_rules/02c_battle-lifetime-and-resolution.md#宣言時効果の解決中に満たした条件2026-09-13)。

### 3. アタック窓の細部

- `ルールQ&A` の検索スニペットから以下を補強した。
  - アタックは 1 体ずつ順番に解決
  - アタック/ブロック宣言後に疲労
  - アタック時効果は疲労後に発揮
  - 通常アタックでは `アタック時` を解決してからブロック宣言へ進む
  - 通常アタックではフラッシュタイミングが 2 回ある
  - ブロック宣言がない場合、後半のフラッシュはなく直ちにバトル解決
- `公式Q&A` と `カードページ` から以下も補強した。
  - `PC12-005` の Q26713 では、指定アタックが絡む同時アタックでも、**アタック宣言で発動したバーストをすべて解決した時点で** まだ指定アタックが成立していれば、通常のブロック前フラッシュを飛ばすとされている。
  - したがって、指定アタックは「アタック宣言直後に即確定」ではなく、アタック宣言起因のバースト解決後に成立を再確認する前提で扱う必要がある。
  - `BS01-X01 龍皇ジークフリード` の Q24507 では、指定対象をアタック時効果で先に破壊した場合、指定アタックは成立せず通常のブロックへ戻る。したがって、指定アタックの block-side は `アタック時` と同時に積むより、成立再判定後の強制ブロック宣言時に積む読みが自然。
  - `SD69-003 巨神要塞トール・キャッスル` の更新Q&Aでは、指定された側は「強制的にブロック宣言したことになり、バトルを行う」と整理されている。したがって `ブロック時` 効果を積む起点は、この強制ブロック宣言の成立時点と読むのが自然。
  - `GX16-01 バーニングスピリッツ` のように、「アタックしている自分のスピリット1体と、他の自分のスピリット1体で、相手のスピリット1体を指定してアタックする」効果が存在する。
  - `CB14-060 ありがと⇄大丈夫` の Q26329 では、2体同時アタック時に両方が `アタック時` 効果を持っているなら、その解決順はターンプレイヤーが選ぶとされている。
  - `CB14-060 ありがと⇄大丈夫` の Q26331-Q26337 では、2体同時アタック時に「1体だけがブロックされた場合」「両方ブロックされなかった場合」「ライフ減少後バーストの解決順」まで個別に裁定されている。
  - 同Q26333 では、1体がブロックされもう1体がブロックされなかった場合でも、`⑤バトル解決` の中で「ブロックされた側のBP比較」と「ブロックされなかった側のライフ減少」をまとめて処理し、その後 `⑥破壊` に進むと読める。
  - 同Q26336 では、1体目のシンボルでライフを減らした結果発動した `ライフ減少後` バーストは、2体目のライフ減少を終える前には解決しない。
  - 同Q26337 では、ライフ減少で派生した効果によるBP変動も含め、`⑤バトル解決` が終わった時点のBPで `⑥破壊` を判定する。
  - 同Q26342 では、2体同時アタック時の `アタックしたとき` は2回ではなく1回として数える裁定がある。
  - 公式ルールマニュアル `page12` の `バーストおよびバースト効果の説明` では、バースト条件を満たした時点でほかの効果が発揮中なら、それらをすべて解決したあとにバースト効果を発揮すると整理されている。
  - `ルール改定に関して` の「アタックでライフを減らしたときに発揮する効果について」では、アタックによるライフ減少と、その派生効果による追加ライフ減少は、`ライフが減らされたとき` を 2 回発揮させるように変更された。
  - 同じ 2024-03-30 改定で、`相手のスピリットのアタック後` バーストは、バースト解決前にそのアタックしたスピリットがフィールドを離れていた場合は発動できないと整理された。
  - したがって、実装では「同時アタック = 単なる連続 attack 2 回」では足りず、`activeAttack` のような battle group 内で複数 participant を保持しつつ、ブロック有無とライフ減少順をまとめて解決できるモデルが必要。
  - 同時に、`アタック時` 効果そのものは participant ごとの逐次解決であり、そこで起きたライフ減少や派生効果は、その都度トリガー判定される層として `battle_resolution` とは分ける必要がある。

### 4. ブレイヴ実装に必要な細則

- `ルールQ&A` の検索スニペットから以下を補強した。
  - 合体スピリットは 1 体として扱う
  - 交換は合体条件を無視できない
  - 交換ではブレイヴを一度スピリット状態にしない
  - 交換ではコア移動なし
  - 分離時はスピリット/ブレイヴの両方に Lv1 以上のコアが必要
  - 分離時のコアはフィールド/リザーブから自由に補える
  - 分離後も疲労状態は引き継ぐ（※2026-08-15 ユーザー確認: 「疲労せず」が無いブレイヴは分離時点のホストだった合体スピリットと同じ疲労状態で残り、ホストが魂状態になる/場からいなくなること自体では回復しない。スピリット状態で「疲労せず」を持つブレイヴだけ分離後ただちに回復する。正源は [`10_rules/05`](../10_rules/05_brave-and-attack-special-cases.md) §「ブレイヴ分離時の疲労状態」）。
- `公式ルールマニュアル` の本文から以下も補強した。
  - ブレイヴをスピリット状態で召喚するときも、最低でも Lv1 になるようカード上にコアを置く
  - 分離時にブレイヴへ置くコアは、`召喚時などと同様に` リザーブやフィールドのカード上から移動させる
  - したがって、ブレイヴ分離時のコア補填ルールは、通常の召喚後コア配置モデルと揃えて扱うのが自然

### 7. バーストの set / reveal / post-resolution

- `特殊な効果` と `バースト解説` から以下を補強した。
  - 自分のメインステップには、手札のバースト効果を持つカードを 1 ターンに 1 回だけセットできる
  - バーストエリアには 1 枚しかセットできず、すでに set されている場合は、そのバーストを破棄してから別の burst を置く置き換え手順が必要
  - `バースト発動` を宣言した時点では、カードはまだ `セットされているバースト` の状態
  - 実際にバースト効果を解決するときは `バースト状態` として burst area で解決する
  - ほかの効果が解決中なら、それらをすべて解決したあとに burst 効果を解決する
  - バースト効果発揮後、通常は burst card はトラッシュへ置かれる
- `カード効果：ネクサスカードをコストを支払わずに配置する` の実カード例から以下も補強した。
  - `この効果発揮後、このカードをコストを支払わずに召喚する。` のように、burst card 自身が解決中に別 zone へ移る例がある
  - `この効果発揮後、このカードをコストを支払わずに配置する。` 例も確認できる
  - `ルール改定に関して` でも、バーストでの `召喚` は `コストを支払わずに召喚する` として扱う整理が案内されている
  - したがって、実カードでまず多い例外は `stay_in_burst` よりも、source card 自身が `召喚/配置` によって burst area から field へ移る型と見るのが自然
  - したがって engine 実装では、post-resolution 移動は「解決後も burst zone に残っているなら trash、解決中に別 zone へ移っていればその移動を優先」と扱うのが自然
  - また、実装の次段は `stay_in_burst` の個別例外を増やすことより、burst area にある source card 自身を `コストを支払わずに召喚/配置する` shared helper を作ることの方が優先度が高い
  - ✅ 実装済み (2026-05-30 確認): 上記 helper は完成。`playBurstSourceCardWithoutPayingCost` (burst-system.ts) + DSL `summon/place { target: self, costModifier: "free" }`、post-resolution は `sourceCard.zone !== "burst"` で早期 return (kept)。実カード BSTH01-X07「宵闇を司る妖怪 EXルーミア」のバーストが本経路を使用。`stay_in_burst` は依然 demo (`DEMO-BURST-STAY-001`) のみで実需なし

### 8. バースト発動条件の多様性

- `バースト解説`、`ルール改定に関して`、個別 Q&A / デッキ解説から、バースト発動条件は少なくとも次の family に分かれることを補強した。
  - `ライフ減少後` のような、出来事そのものの発生を見る型
  - `相手のスピリットのアタック後` のような、行為完了後を見る型
  - `相手の効果によるスピリット/ブレイヴの召喚後` のような、効果起因の行為完了を見る型
  - `相手の効果によって相手の手札が増えた後` のような、枚数変化を見る型
  - `相手の『このスピリット/ブレイヴの召喚時』発揮後` のような、特定 timing の効果発揮を見たあとで待つ型
  - `相手によって自分のスピリットがフィールドを離れた後`、`相手による自分のスピリット消滅/破壊後` のような、ゾーン移動や leave cause を見る型
  - `自分か相手の《封印》後`、`相手の〖神技〗発揮後` のような、後年 keyword / mechanic の発動後を見る型
- つまり、バースト条件の多様性は「文言違いが多い」だけではなく、
  - 行為そのものを見るのか
  - 効果発揮を見るのか
  - 結果のゾーン移動を見るのか
  - さらに actor / controller / cause / keyword を絞るのか
  という形で event family 自体がかなり広い。
- このため、engine 設計では `BurstEventKind` を文言ごとに増やし続けるよりも、
  - `event family`
  - `action / effect / leave / keyword` の別
  - actor / target / related player
  - cause / validation mode
  - count / cost などの追加 predicate
  を持つ structured trigger model へ寄せた方が中長期には安全そうである。
- 現段階では `life_reduced` と `attack_after` 程度なら flat enum でも回るが、次に 2〜3 family 増やす前には切り替え判断を入れるべき、という設計含意が得られた。

### 2026-03-23 再調査での追加補強

#### 3b. アタック窓の追加裏取り

- `PC12-005` の Q26718 から以下を新規確認した。
  - **バトル解決中のバースト解決タイミング**: 2体同時アタックで、1体目のシンボルでライフを減らしたときに `ライフ減少後` バーストの条件を満たしても、2体目のシンボル分のライフも減らした後、(5)バトル解決が終わるときにバーストを解決する。
- `PC12-005` の Q26724 から以下を新規確認した。
  - **2体同時アタック時のブロック上限**: 「2体で同時にアタックした時点で、そのバトルでは1体しかブロックできないというルールに変更されています」。
- `PC12-005` の Q27706 から以下を新規確認した。
  - **同時アタック時のアタック時効果**: 「同時にアタックしているので、（○○のスピリットがアタックしたとき）1回しか発揮しません」。

#### 4b. ブレイヴの追加裏取り

- `公式ルールマニュアル エターナル版 page09` の本文から以下を新規確認した。
  - **Lv1コスト0のブレイヴ**: 「Lv1コストが0ならコアを移動しなくても残せます」。合体先が離脱してブレイヴがフィールドに残る判定で重要。
  - **ブレイヴ召喚はスピリット召喚ではない**: 「ブレイヴカードをスピリット状態で召喚しても、スピリットの召喚とは扱われません」。
  - **分離でLv1保てない場合**: トラッシュに置かれるが、「このとき、破壊時や消滅時に発生する効果は発生しません」。
  - **交換の中間状態なし**: 「交換を行った場合、分離と合体ブレイヴが同時に行われ、その間にブレイヴがスピリット状態になることはありません」。
  - **合体先離脱時のバトル継続**: 「合体ブレイヴスピリットがアタック／ブロック中にフィールドを離れ、ブレイヴがスピリット状態でフィールドに残ったときは、代わりにブレイヴがアタック／ブロックを継続します」。
  - **破壊の待機状態での合体解除**: Q77「破壊の待機状態になった時点で、合体しているスピリットなどに対して、シンボルや色、コスト、BP+、【合体中】効果などは与えなくなります」。
  - **異魔神ブレイヴ・神話サーガブレイヴの正式ルール**: エターナル版 page09 から詳細取得。open-questions P2 の言及を補完。

#### 7b. バーストの追加裏取り

- `公式ルールマニュアル エターナル版 page12` の本文から以下を新規確認した。
  - **手札/トラッシュからのバースト発動もバーストエリア扱い**: 「手札やトラッシュから効果で発動したバーストも、バーストエリアでバースト効果を発揮している扱いになります」。open-questions のバースト発動スタック窓議論に影響。
  - **バースト入れ替え時の破棄のみ不可**: 「すでにセットしてあったバーストを手札に戻したり、代わりのバーストをセットせずに破棄することはできません」。
  - **バーストエリア離脱/ゲーム終了時の公開義務**: 「セットしたカードがバーストエリア外に移動したときや、ゲームが終了したときは、必ずカードの内容を公開して、バースト効果を持つことを確認してください」。
  - **バーストセット時コア不可**: 「バーストをセットするとき、カードの上にコアを置くことはできません」。
  - **バースト状態は対象制限あり**: 「バースト状態のカードは、バーストを対象とした効果以外を受けません」。ただし「対応する【超装甲】や【重装甲】の効果があれば、バースト状態のカードの効果も防げます」。
  - **burst.html との表現矛盾**: burst.html は「フィールドに伏せる」と記載するが、page12 は「バーストエリアはフィールドには含まれません」と明記。page12 が正。
- `ルール改定に関して` の本文から以下を新規確認した。
  - **ブロックアイコン《2》以降の例外**: 「"召喚する"とだけ書かれた効果でもコストを支払って召喚/配置する」。バースト召喚でもコスト支払いが必要になる場合がある。
  - **Ver.15.0 の即発動制限**: 「ただちにバーストを発動できる」効果で複数条件がある場合、「派生する効果の解決に入る前に発動を宣言しなければ、ただちに発動できない」。
  - **Ver.6.0**: バースト効果とメイン/フラッシュ効果は「ひとつの効果」として扱う。

### 2026-09-16: 裏返ったB面と宣言時効果の再評価

- BSGE01-TR01(B)への適用はユーザー承認済み（B）。[02c](../10_rules/02c_battle-lifetime-and-resolution.md)へ反映し、宣言時の提供元の面・個体を照合する。
