# 対象選択・発揮後の辞退監査（2026-10-02）

## 根拠と適用

- **A（独自カード原文）**: `external-qa/cardData.js` の BSAZ02-C16「我は地球人というだけで憎いがな」。原文は「トラッシュにあるこのカードは、自分のエンドステップに、手札の系統：「火星」を持つカードと入れ替えられる」。手元を含まず、「このカード」は発揮元個体である。同名の別個体を選ぶ効果ではない。元サイト: <https://dancing-pixie-db5cc3.netlify.app/>。カード固有の追加Q&A・訂正はミラーに見つからない。
- **A（公式）**: [エターナルマニュアル FAQ](https://www.battlespirits.com/rule/official-rule-manual-eternal/page14.html) の「する／できる」。可能形は発揮するかを選ぶ。2026-10-02に本文確認。
- **C（既存ユーザー裁定の適用）**: [03cの任意性](../10_rules/03c_effect-text-interpretation.md) の2026-08-09裁定と今回の確認。発揮することを選んだ固定枚数処理は、対象選択で再度辞退できない。「まで」、0を含む枚数指定、独立した任意の後続手順は維持する。対象が存在しない不発と、候補があるのに選ばないことは別。
- GUI正源: [共通選択UI](../25_gui/08b_gui-interaction-reference.md)。カードを対象にする選択は、手札・盤面のタップと画像付きゾーン候補を使う。

## 監査範囲

全登録カードのeffect/steps/choice内を走査し、`queue_hand_trash_swap` 3、`queue_field_hand_swap` 5、`search_zone` 27、`discard` 88、`deck_reveal` 96アクションの枚数・任意性と該当原文を照合した。対象カードの効果以外も含むカード全体の完全実装を主張する記録ではない。

| 経路 | 結果 |
| --- | --- |
| 手札/手元⇔トラッシュ交換 | C16のみ手札限定・発揮元個体限定を修正。3アクションすべて発揮後の交換辞退を除去 |
| フィールド⇔手札交換 | BSSG01-C01/C02、BSSG02-C01の5アクション。発揮後の辞退を除去 |
| 検索・回収 | 固定1枚なのにmandatory未指定の7箇所を修正。複数ゾーン経路にもmandatoryを伝播 |
| 破棄 | optional stepの実行確定後に固定枚数を再辞退できる共通経路を修正 |
| オープン | 「まで」や公開後の独立任意手順を維持。今回の修正対象なし |
| GUI | 交換2種・転召・煌臨元追加先に残っていた文字列候補を共通カード選択へ統合 |
| GUIのその他の選択 | 任意step、効果内分岐、魂状態/除外置換、連続バトル、オープン枚数追加、借用する効果、コスト前使用は処理そのものの選択。文字ボタンを維持 |

固定検索7箇所: BSDB01-C06、BSKB01-R01、BSSL01-R03、BSTH003-R01/R02、BSTH06-C04、BSTS01-C01。いずれも効果・分岐の発揮を選択した後の1枚処理であり、0枚選択の根拠がない。

オープンの任意指定はBSAZ01-CX01、BSES01-C02、BSKB01-C02/M01、BSLH01-C14/X07、BSRK01-C01/C02/R03、BSSA01-R01、BSSG01-C08、BSTH02.7-C03、BSTH09-C01〜C05、BSTH10-R02、BSTH11-X02の該当手順を確認。「まで」と公開後に独立して行う任意処理を、発揮前の任意性と混同しない。BSKB01-C03の手札/トラッシュからの配置も独立任意手順として0枚を維持する。

## 再発防止

- C16は`incomingFrom: source_card`と`outgoingZones: [hand]`で指定し、候補生成・実行・発揮前可否の3経路が同じ候補関数を使う。
- 旧交換辞退のaction型は既存保存形式との互換のため残すが、合法手に出さず、直接送信も拒否する。
- 共通カード選択はlegal actionの実際の候補ペアを保持して順に選び、選んだペアのactionを送る。別個体・不正な組合せへ置き換えない。
- `swap-choice-contract`、`declared-selection-count`、`selection-option-contract`で候補範囲・発揮後の固定枚数・0枚指定の例外を保護。既存の効果継続組合せテストと、交換/転召/煌臨元のGUI・RESTシナリオで解決後の盤面まで確認する。
