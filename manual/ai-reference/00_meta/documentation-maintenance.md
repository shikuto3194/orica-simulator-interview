# 文書の正源と保守

運用規則は [CLAUDE.md](../../../CLAUDE.md)。説明の重複を減らし、通常の変更・検査だけで参照を保つ。

## 判断する対象を分ける

| 判断 | 参照先 | その参照だけでは証明しないこと |
|---|---|---|
| ゲーム上の意味 | [出典索引](source-map.md) → 該当するルール章・原文 | 現在のコードがその通り動くこと |
| 使用できるDSLの形 | [dsl-types.ts](../../../packages/rules-core/src/dsl-types.ts) | 印刷本文の意味・実配線・受入 |
| 現在の実装 | 該当ソースと回帰テスト | 未実行テストの成功・本番動作 |
| 次の仕事 | [現役タスク](../30_plan/02_detailed-todo.md) → 該当issue | 過去Snapshotの現在性 |
| 検証・公開 | [検査契約](harness-validation.md)と対象treeに結び付く実行結果 | 部分検証からの全体合格 |

型と説明が違えば型の現状を確認する。ルールとコードが違えば、コードを裁定の根拠にせず原文・適用版へ戻る。

## 書く量を増やさず更新する

- 変動する型一覧・件数・実装済み表・実行手順を複製しない。正源ファイル、既存の集計コマンド、実行テストへのMarkdownリンクを置く。
- 実行用の例は既存のテスト・実例へリンクする。未検証の案にはその旨と必要な確認を書く。過去の測定値には日付・対象・条件を残し、現在値に見せない。
- 仕様・ファイルを変更したら、旧パス・旧用語を `rg` で検索し、現役の説明と導線を同じ変更で直す。全履歴の意味を書き換える必要はない。
- 解決済みの経緯は既存の履歴・裁定章へ置く。現役タスクには未完了範囲と次の行動・待機の発火条件だけを残す。全件に新しい台帳や必須メタデータを課さない。
- 取得方法のA/B/Cと、公式/独自/ユーザーという出典主体、確定/暫定/未確認、実装採用を混同しない。必要な区別は裁定の本文に短く記録する。

## 検査範囲

`pnpm docs:lint` はlockfileに従うdevDependenciesのinstallが前提（既存Prettierを利用）。依存不足は検査失敗であり、preflightの読取診断とは分ける。
既存のサイズ・形状検査に加え、現役文書のMarkdownリンク先がrepo内に存在するかを検査する。
相対・repo root相対 `/...`、コードファイル、ディレクトリ、URLエンコード、リンクタイトル、参照形式を扱う。
既に導入済みのPrettierのMarkdown parserを使い、コード例（フェンス・インデント・inline code）・HTMLコメント・画像・未使用参照定義はリンク検査から除く。構文解析器を自作せず、新しい依存は追加しない。
`archive/`・`_legacy/`・日付別history・phase別milestoneのリンクは凍結記録として対象外（従来のサイズ検査は維持）。
ignore除外はartifacts/logs等の既知の生成物保存先だけ。HEAD/indexで追跡するファイルと、packages/apps/scripts/manual等のソース参照欠落はignoreで免除しない。Git・ファイルの読取失敗は検査失敗。

**見出しfragment、外部URLの到達性、ルールの意味、コードの実行結果は検査しない。**
アンカー変更時は参照元を検索して確認する。複雑なslug生成器・自然言語禁止regex・定期AI監査は追加しない。
検査範囲と除外先は `artifacts/docs-lint.json` の `linkCoverage` に出る。合格を文書内容全体の正しさに読み替えない。
回帰は [test-doc-links.mjs](../../../scripts/test-doc-links.mjs) から既存harnessへ接続し、finish/push/merge/CIの経路で確認する。

## 作業開始と終了

- `pnpm codex:preflight` は実checkoutのbranch・SHAとローカルupstreamとの差を表示する。fetchを行わないためremote最新の証明ではない。差分・読取不能はpartialとして表示し、自動同期や他作業の停止は行わない。
- コピーするコマンドは対象repo/worktreeのrootで実行する。PowerShellの環境変数は `$env:NAME = 'value'`。別treeへ強制移動する例や別serverの無条件再利用を避ける。
- 調査のみなら、調査範囲・参照SHA・変更なし・実施した検査・未確認を報告する。既存の他作業の差分や検査結果を自分の成果に含めない。
- `PROTECTED_WRITE` はKnowledgeDBの保護状態。読取検索のno_matchや履歴監査partialと分ける。提供元のENTRYに従って読取経路を使い、別rootへの迂回や開始/完了証跡の作成をしない。
- ゲート起動前の依存取得/DNS失敗、検証lease待ち、テスト失敗を区別する。代替コマンドが通っても元ゲート通過と報告しない。
