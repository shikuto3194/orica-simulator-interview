# 効果召喚のコア・コストSSOT監査（2026-09-13）

親: [Source Map](source-map.md)

## 発端と裁定

BSDB01-C06 カメハウスの配置時効果で、手札にBSDB01-CX01 孫悟空＆ベジータがあっても「発揮しない」しか出ないスナップショットを調査した。

- 実データ: Bobのカメハウスは `card-44`、手札のCX01は `card-65`。リザーブ通常0 / ソウル1、トラッシュ通常3、手札4、デッキ35、カウント0。
- **信頼度A（公式エターナル）**: [コストとコア page07](https://www.battlespirits.com/rule/official-rule-manual-eternal/page07.html) の「ソウルコアも通常のコアと同様、召喚･配置したカードの上に置くことができます｡」を確認。配置元はリザーブまたは自分のフィールド上。トラッシュは効果による許可が必要。
- **信頼度A（カード本文）**: [独自カード一次ソース](https://dancing-pixie-db5cc3.netlify.app/) のローカルミラー `external-qa/cardData.js` とBSDB01.tsを照合。CX01は契約スピリット、コスト3、軽減は赤2/青2。C06の全軽減充足では支払い0、Lv1維持コアは1。
- **信頼度C（既存のプロジェクト確定規約）**: [08a2:10](../10_rules/08a2_name-reference-scope.md) の「名前一致は card_name_reference 規約（「X」=部分一致／カード名：「X」=完全一致）に従う。」を適用。「孫悟空」は「孫悟空＆ベジータ」に一致する。
- **信頼度A（公式エターナル＋既存ルール章）**: [公式FAQ page14](https://www.battlespirits.com/rule/official-rule-manual-eternal/page14.html) と [03c:72](../10_rules/03c_effect-text-interpretation.md) の「前述を解決してから」を適用。召喚後の条件を召喚前の発揮条件にしない。

以上を実装判断に使用。カード本文・名前一致規則・独自の新裁定は変更していない。

## 原因

1. 後続のドロー／回収ステップの `field_has` 条件を、registrationの択一候補から効果全体の発揮条件へ持ち上げていた。召喚前には「孫悟空」がいないため全候補が消え、これが「発揮しない」だけになる直接原因。
2. 別の不具合として、from_zone/selfの召喚可否シミュレーションと自動配置が通常コアだけを数えていた。条件を直すだけでは、唯一のソウルコアを維持コアに使う召喚を拒否する。
3. 監査で、候補側の印刷コスト計算と実行側の軽減計算、固定支払いとコスト下限の扱いにも重複を検出。複数の無料召喚に必須追加コストが掛かると、実行側が支払元を空と決め打ちして拒否する経路も共通支払元選択へ統合。
4. 複数召喚で、先に召喚したカードの維持コアを次の召喚へ使い回せた。トラッシュ上限も候補ごとに再使用していた。
5. トークン・分割召喚の一部支払いがリザーブ通常コアだけを使い、魂状態・持ち越しコアの集計にもソウルコアの欠落があった。

## 監査範囲と共通化

カード別パッチではなく、合法手→任意ステップ可否→対象選択→支払い→フィールド進入→後続再開を追跡した。カードファイル内に直接記述されたsummon 150箇所（self 101 / from_zone 48 / ref 1）に加え、put・トークン・魂状態などの共通生成／変換先を監査した。

| 経路 | 結果 |
| --- | --- |
| self（手札・トラッシュ・一時領域・バースト等） | 予測と自動配置を共通化。持ち越すソウルコアも維持数へ算入 |
| from_zone（手札・トラッシュ・一時領域・煌臨元） | コスト・支払元選択・維持コア配置の重複を削除。複数対象の維持コアを相互使用しない |
| 魂状態・マジック互換合体ブレイヴ | 全ソウルコアを共通配置元列挙から集計。コスト計算も共通化 |
| ref（持ち主フィールドへの再召喚） | 所有者ごとに共通配置処理を使用。同時対象間の維持コアの使い回しを禁止 |
| トークン・関連トークン全種・強制合体先生成 | 支払いを共通化。配置元は共通列挙／既存のmulti-placement実行器を使用 |
| トークンとゾーン札の分割召喚 | 固定支払いも共通支払元を利用。配置下限判定を共通列挙へ統合 |
| デッキ公開後のフィールド進入 | リザーブ通常のみの補填を撤去し、共通配置実行を使用。同時選択された札からは補填しない |
| 手札プレイ・天翔の配置可否 | 効果召喚と同じ配置元列挙へ合流し、比較元の判定も一元化 |
| 後続の条件付き択一 | 後続stepのconditionを宣言条件へ昇格させず、既存の条件評価器でそのstep到達時に評価・提示 |

SSOTは次の3層。ゾーン／コア移動の制限を呼び出し元で再実装しない。

- `zone/enter-field-core-sources.ts`: 既存 `canProvideEnterFieldCorePlacementSource` を使った配置元列挙・数え上げ・自動配置。実移動は `applyEnterFieldCorePlacements` に委譲し、移動できた個数のみを充当。
- `core/auto-card-cost-payment.ts`: 既存 `getAvailableCardCostPaymentSources` を使う自動支払元選択。実支払いは `applyCardCostPayments` に委譲。
- `effect/summon-cost.ts`: costModifier変換と召喚コスト計算。予測・self/from_zone・魂状態・トークン／分割の各入口が使用。

任意追加コアの選択や「トラッシュ＋ボイド同時指定」の既存DSL対応範囲は、この監査で拡張していない。無条件の択一や必須「ことで」の対象・コスト選択契約を維持し、後続step自身に掛かるconditionの早期判定を修正した。

## 再現・検証

- 添付JSONをローカルAPIへ読み込み、C06発揮→スタック終了→CX01召喚→リザーブソウル配置→カウント+1→ドローを実行。CX01はfield/通常0/ソウル1、Bobはカウント1/デッキ34/手札4を確認。元の対戦ルームへは送信していない。
- `e2e/scenario-c06-soul-core.spec.ts`: Alice GUI操作／Bob REST操作それぞれで、ドローと「かめはめ波」回収の4ケース。Aliceは発揮、ソウルコア選択確認、配置完了、択一をGUIで操作し、REST状態と画面を照合。
- `effect-summon-core-sources.test.ts`: 手札/トラッシュ/一時領域×リザーブ/フィールドのソウル、配置元制限、待機中の移動元、複数ソウル、魂状態、トークン支払い、軽減、同時召喚の共有予算、持ち越しを回帰検証。
- `effect-interpreter.test.ts`: 集合として実行不能な対象選択を拒否する既存テストの資源設定を修正。2枚を合法に維持するための別々のコアを用意する。
