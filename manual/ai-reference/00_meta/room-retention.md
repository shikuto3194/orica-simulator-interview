# ルームの保持期間と清掃

正源は `apps/playground-web/server/room-retention.ts`。対戦・待機ルーム共通。

| 状態 | 削除可能になる時刻 |
| --- | --- |
| 全員が退出通知を送信 | 最後の退出から10分 |
| 通信断・ブラウザ終了などで退出通知が未達 | 最終接続確認から45秒（切断猶予）+10分 |
| 接続確認の記録がない旧ルーム | 作成から45秒+10分 |

作成・参加・再参加時に接続確認時刻を初期化する。対戦画面は heartbeat を送信し、
ロビーは既存の3秒ポーリングから、接続中の本人に限り10秒以上空いた時刻を更新する。
観戦者・部外者・退出済み参加者による読み取りは保持期間を延長しない。
`GET /api/room` の参加済み未決着ルーム一覧も読み取り専用で、接続状態・接続確認時刻・
全員退出時刻を変更しない。一覧に表示されたことを参加と扱わず、「戻る」で選択した
ルームへの `POST /join` だけが再接続する。閲覧中も従来どおり期限切れルームを清掃する。
ロビーの「ホームに戻る」とページ終了は JWT 付き退出通知を送る。
対戦画面への遷移を退出として扱わない。繰り返し退出しても全員退出時刻を延長しない。

APIサーバーと開発サーバーは起動後1分から、1分間隔で清掃する。
最初の1分は旧ロビーの接続確認を受け付ける猶予。APIアクセスがなくても実行するが、
サーバー停止・PCスリープ中は動かず、再開後の清掃で回収する。
実際の削除には最大約1分の清掃待ちとDB処理時間が加わる。

清掃は盤面本体を取得せず100件ずつID順に読む。削除は取得時点の作成日時・盤面版・
接続状態・接続確認時刻・全員退出時刻がすべて一致する行に限定し、
清掃中に再接続・操作されたルームを削除しない。不正な日時は削除対象にしない。
DBエラーはサーバーログの `[room-cleanup]` に記録し、次回に再試行する。
ルーム削除で `replay_events` は外部キーのCASCADEに従い削除される。
ユーザー保存済み `snapshots` は残り、`room_id` がNULLになる。

## 調査と検証

2026-09-20、実DBで134件の残存、127件が作成から1日超、最古は3月27日、
全件 `all_disconnected_at` 未設定を確認。旧実装はこの列が設定されたルームだけを
APIアクセス時に削除し、ロビー退出通知と通信断からの期限切れ判定が欠けていた。

同日23:09 JST、修正した清掃処理を実DBへ実行。137件のうち期限切れ134件を削除し、
直前の検証で作成した保持期間内の3件を維持した。削除時は取得した接続情報との一致を
DB側でも確認し、期限切れ候補の残存は0件、保存済みスナップショット数は実行前後とも0件。

- `room-retention.test.ts`: 期限境界、旧データ、片方接続中、再接続との競合、ページング、定期実行・失敗再試行。
- `room-leave-auth.test.ts`: JWTと所属、退出の冪等性、ロビーの本人だけの接続確認更新。
- `room-list.test.ts`: ページング、盤面・デッキ情報の非公開、繰り返し一覧取得後も期限どおり清掃。
- `e2e/room-sse-opponent-sync.spec.ts`: AliceロビーGUI/Bob REST、退出・ページ終了・再参加、対戦SSE同期。
